## 0. 一页速览

1. 战斗脚本放 `script/battle/mod/*.lua`，普通战役战斗也会自动加载，**不需要任务战 setup**。
2. 管理器是 `bm`（不是 `cm`）；**战斗时间单位是毫秒**。
3. 单位**不能**自己下命令：查询走 `battle_unit`，下命令走 `battle_unitcontroller`（UC）；`script_unit` 把两者打包。
4. 高频目标捕获用引擎原生 `register_repeating_timer`，不要只靠 `bm:callback`。
5. `Special Ability` 指令事件**只用来开捕获窗口**，目标必须另找（phase / 原版 attribute / CCO）。
6. `Complete` 阶段必须清理 timer / process，否则泄漏到下一场。
7. 所有引擎调用包 `pcall`，日志带统一前缀。

## 1. 加载机制与入口

```
战斗 setup（部队/地形/胜负条件）
   │
   ├─ 指定脚本路径：cm:add_custom_battlefield(...) / battle_set_pieces.battle_script / XML <battle_script>
   └─ 未指定 → 默认 script/battle/default_battle/battle_start.lua（内部 load_script_libraries()）
   │
   ▼
load_script_libraries() → 创建全局 bm
   │
   ▼
lib_mod_loader.lua：core:is_battle() 时
   core:load_mods("/script/_lib/mod/", "/script/battle/mod/")
```

| 项 | 事实 |
|---|---|
| MOD 战斗脚本目录 | `mod/<你的MOD>/script/battle/mod/<name>.lua` |
| 加载顺序 | **按文件名排序**；库工具用 `!!`、`!`、`z_` 等前缀控制先后 |
| 库工具约定 | 工具层文件最先加载（如 `!!rlh_battle_utils_arthas.lua`） |
| 与战役差异 | 战斗**顶层**即可用 `bm:*`；也可 `bm:register_*` |

- **怎么做**：库/工具函数放 `!!` 前缀文件，业务脚本放普通名；不要依赖未声明的加载顺序。
- **验收**：日志里工具文件的初始化输出出现在业务脚本输出之前；`bm` 在业务脚本顶层非 `nil`。

> ⚠️ 坑：用战役思维在战斗里写 `core:add_listener` 并等 `cm:add_first_tick_callback` → 战斗环境没有 `cm`，监听不到。战斗优先 `bm:register_*`。

### 1.1 日志通道（调试必看，实测）

| 函数 | 写到哪 | 使用条件 |
|---|---|---|
| `ModLog(text)` | `<GAME>\lua_mod_log.txt` | ✅ **可靠**，不依赖任何开关 |
| `bm:out(text)` / `out(text)` | `script_log_<DDMMYY>_<HHMM>.txt`（游戏根目录） | 先确认当前环境启用了脚本日志，并实际探测输出文件 |

- **依据**：`ModLog` 定义于 `游戏原文件\script\_lib\lib_mod_loader.lua` L41；`script_log` 缺失见 `references/60-日志与崩溃排查.md` §1.1 实测记录。
- **怎么做**：战斗脚本统一写 `if ModLog ~= nil then ModLog("[前缀] " .. text) end;`——加 `nil` 判断是因为该函数由 mod loader 提供。
- **验收**：战斗后 `lua_mod_log.txt` 出现自己的前缀行；同时出现 `Mod [script\battle\mod\<名>.lua] loaded successfully` 即证明脚本已加载。

> ⚠️ 坑：脚本日志未启用时只用 `bm:out()`，会因缺失输出而误判脚本没执行。先确认日志开关与输出位置，再看 `lua_mod_log.txt` 的 mod 加载行和自己的 `ModLog` 输出。

## 2. 对象层级

```
bm / battle
 └── alliances (battle_alliances)          -- 恒为 2 个：1 = 进攻方，2 = 防守方
      └── alliance (battle_alliance)
           └── armies (battle_armies)
                └── army (battle_army)
                     └── units (battle_units)
                          └── unit (battle_unit)     -- 只读查询为主
                               + unitcontroller     -- 下命令、改状态
```

| 对象 | 职责 | 取用方式 |
|---|---|---|
| `bm`（`battle_manager`） | 全局管理器：层级访问、阶段、指令拦截、定时、消息、收尾 | 引擎自动创建，全局可用 |
| `battle_unit` | 单位**查询**与部分状态修改（≈110 函数） | `army:units():item(k)` |
| `battle_unitcontroller`（UC） | 下**命令**：施法、移动、瞬移、攻击、士气（≈77 函数） | `bm:get_scriptunit_for_unit(unit).uc`（首选）或 `script_unit:new(unit).uc` |
| `script_unit` | 查询 + 控制的**高层封装**（≈151 函数） | `script_unit:new(battle_unit, "tag")` |

**实践范式**（几乎总是这样用）：

```lua
local sunit = script_unit:new(unit, "my_tag")
-- sunit.unit → battle_unit
-- sunit.uc   → battle_unitcontroller
```

**全场遍历模板**（`battle_units` 索引 **1-based**）：

```lua
local alliances = bm:alliances()
for i = 1, alliances:count() do
    local armies = alliances:item(i):armies()
    for j = 1, armies:count() do
        local units = armies:item(j):units()
        for k = 1, units:count() do
            local u = units:item(k)
            -- u:type() / u:unique_ui_id() / ...
        end
    end
end
```

- **怎么做**：找专属角色用 `u:type()` 比对 `land_units` / `main_units` 键；缓存用 `u:unique_ui_id()`。
- **验收**：日志打印出预期单位数量与 `type()` 命中记录。

**高频 `battle_unit` 分组**：

| 分组 | 关键函数 |
|---|---|
| 身份 | `type()` · `unique_ui_id()` · `name()` · `alliance_index()` · `army_index()` · `is_commanding_unit()` · `army()` |
| 位置 | `position()` · `bearing()` · `ordered_position()` · `position_of_officer()` · `can_reach_position(pos)` · `unit_distance(other)` · `unit_in_range(other)` |
| 生命人数 | `unary_hitpoints()` · `heal_hitpoints_unary(ratio, allow_rez?)` · `reduce_hitpoints_unary(delta, hide?)` · `number_of_men_alive()` · `initial_number_of_men()` · `kill_number_of_men(n, hide?)` |
| 士气/交战 | `is_wavering` · `is_routing` · `is_shattered` · `is_rampaging` · `is_in_melee` · `is_under_missile_attack` · `is_valid_target` · `is_deployed` |
| 能力 | `can_perform_special_ability(key)` · `disable_special_ability(key, disabled?)` · `owned_special_abilities()` · `can_use_magic()` |
| 属性 | `has_attribute(key)` · `set_stat_attribute(key, enable)` |

**高频 UC 函数**：

| 类别 | 函数 |
|---|---|
| 控制权 | `take_control` / `release_control` |
| 施法 | `perform_special_ability(key, target?)` / `perform_special_ability_q(...)` / `perform_special_ability_ground(key, pos, orient?, width?)` |
| 冷却/次数 | `reset_ability_cooldown(key)` / `reset_ability_number_of_uses(key)` |
| 瞬移 | `teleport_to_location(pos, facing_deg, width_m)` |
| 移动 | `goto_location` / `goto_location_angle_width`（及 `_q` 队列版） |
| 攻击 | `attack_unit` / `attack_location` / `attack_building` |
| 士气 | `morale_behavior_fearless` / `rout` / `default` |
| 显隐 | `set_invisible_to_all` / `change_enabled` / `set_invincible` |

**生命 API 语义（必须分清）**：

| 函数 | 语义 |
|---|---|
| `unary_hitpoints()` | **当前生命比例**（0~1，相对开战满血） |
| `heal_hitpoints_unary(ratio, allow_rez?)` | 治疗到指定比例（**目标绝对值**，不是增量） |
| `reduce_hitpoints_unary(delta, hide?)` | **扣除**指定比例（是减量） |

```lua
-- 换血正确写法：先缓存双方比例，再写回
local current = unit:unary_hitpoints()
if desired > current then
    unit:heal_hitpoints_unary(desired, false)          -- 传目标比例
elseif desired < current then
    unit:reduce_hitpoints_unary(current - desired)     -- 传差值
end
```

- **验收**：日志同时打印 `current` 与 `desired`，游戏内血量落在预期比例。

> ⚠️ 坑：把 `heal_hitpoints_unary` 当增量传 → 血量跳到错误比例（传的是目标比例）。

## 3. 战斗阶段与清理

| Phase | 时机 |
|---|---|
| `Deployment` | 部署开始（**即使跳过部署也会触发**） |
| `Deployed` | 进入交战 |
| `VictoryCountdown` | 胜负已定，倒计时 |
| `Complete` | 结束；**务必在此清理 timer / repeat_callback** |

```lua
bm:register_phase_change_callback("Complete", function()
    bm:unregister_timer("my_timer")
    bm:remove_process("my_watcher")
end)
```

- **怎么做**：每个 `register_repeating_timer` / `repeat_callback` / `watch` 都要有一个对应的清理动作，并在 `Complete` 统一执行。
- **验收**：连续打两场战斗，第二场不出现重复回调 / 报错；日志有清理记录。

> ⚠️ 坑：战斗结束不清理 → 下一场异常（timer 与 process 泄漏到下一场）。

## 4. 两套定时器

| API | 机制 | 适用 |
|---|---|---|
| `bm:callback` / `bm:repeat_callback` | bm 共享 process 队列 | 一般延迟、轮询 |
| `bm:register_repeating_timer(name, interval_ms)` + **同名全局函数** | 引擎原生 timer，**不走 bm 共享 callback 队列** | 高频目标捕获；避免被 UC 命令打断 Lua 调用链时丢回调 |

```lua
bm:register_repeating_timer("my_mod_target_capture_timer", 100)

function my_mod_target_capture_timer()   -- 全局函数名必须与 timer 名完全一致
    capture_target()
end
```

- **怎么做**：高频扫描（目标捕获、位置轮询）用原生 timer；一次性延迟用 `bm:callback`；暂停也要走的时间用 `real_callback` / `repeat_real_callback`。
- **验收**：日志显示捕获回调稳定触发（不因中途发出 UC 命令而丢帧）。

> ⚠️ 坑：全局回调函数名与 timer 名不一致 → timer 触发时找不到函数，静默无效。
> ⚠️ 坑：只靠 `bm:callback` 做高频捕获且紧跟 UC 命令 → 回调丢失。

### 4.1 轮询 + 去重：覆盖开局与中途援军（实测）

一次性扫描只覆盖战斗开局；**援军**在战斗中陆续入场，必须靠轮询补（完整实现见 `<WORKSPACE>\su_fymsm\script\battle\mod\su_fymsm.lua` 的 `su_fymsm_scan()`）。

```lua
local processed = {};                                   -- [unique_ui_id] = true

local function scan()
    local armies = bm:alliances():item(bm:get_player_alliance_num()):armies();
    for j = 1, armies:count() do
        local units = armies:item(j):units();
        for k = 1, units:count() do
            local unit = units:item(k);
            local id = nil; pcall(function() id = unit:unique_ui_id() end);
            if id ~= nil and processed[id] == nil then
                local deployed = false; pcall(function() deployed = unit:is_deployed() end);
                if deployed then
                    processed[id] = true;               -- 只处理一次
                    -- …对 unit 下命令（经 UC）…
                end;
            end;
        end;
    end;
end;

bm:register_phase_change_callback("Deployed", function()
    processed = {};                                     -- 新战斗先清空
    bm:repeat_callback(scan, 3000, "my_mod_scan");       -- 毫秒；第 3 参是清理用 process key
end);

bm:register_phase_change_callback("Complete", function()
    bm:remove_process("my_mod_scan");                    -- 不清理会泄漏到下一场
end);
```

- **依据**：`battle_manager:repeat_callback(callback, interval, name)` 与 `remove_process(key)` 见 `lib_battle_manager.lua`；`battle_unit:is_deployed()` 原版用法见 `_lib\lib_battle_misc.lua` L930。
- **去重是硬要求**：玩家会在战斗中手动改单位状态，无去重地重复下命令会**反复覆盖玩家操作**。
- **`is_deployed()` 过滤**：预备队与未入场援军也在 `units()` 列表里，未部署时下命令无意义。
- **验收**：开局出现一次批量处理日志；援军入场后 3 秒内再出现一次（数量 = 该波援军数）；手动改过的单位后续被跳过。

> ⚠️ 坑：无去重地重复下命令 → 玩家每次手动调整都被几秒后的扫描改回去。
> ⚠️ 坑：`Complete` 不 `remove_process` → 定时器与 `processed` 表泄漏到下一场，新战斗单位被误判"已处理"而全跳过。

## 5. 毫秒时间单位（易错点）

| 环境 | 单位 | 示例 |
|---|---|---|
| 战斗 `bm:callback(fn, interval)` | **毫秒** | `bm:callback(fn, 5000)` = 5 秒 |
| 战役 `cm:callback(fn, interval)` | **秒** | `cm:callback(fn, 5)` = 5 秒 |
| 战役 `cm:real_callback(fn, interval)` | **毫秒** | 见 `40-Lua战役脚本.md` §5.1 |

- **怎么做**：写战斗脚本时所有延时数值按毫秒算；从战役脚本复制代码时**必须重新换算**。
- **验收**：日志时间戳间隔与预期毫秒值一致。

> ⚠️ 坑：把战斗 `bm:callback(fn, 5)` 当 5 秒 → 实际 5 毫秒，逻辑几乎立即执行。

## 6. 指令拦截：只开捕获窗口

```lua
bm:register_command_handler_callback(
    "Special Ability",
    function(context)
        local ability_key = context:get_string1()
        -- 文档保证的字段主要是 ability key
        -- 不要假设 context 直接给出手动点选的目标单位
    end,
    "my_mod_cmd_handler"
)
```

**实践结论（RLH + 无双英灵录一致）**：

1. 用指令事件**只开捕获窗口**（知道"这个能力被按了"）。
2. **目标**靠 DB phase / 原版 attribute 标记 / CCO `ActiveEffectList` 扫描得出。
3. 标记可能在蓄力期间就出现又消失 → **提前缓存**目标，等自身 phase 激活再执行。

- **怎么做**：收到指令后记录时间与能力 key，启动捕获 timer，捕获成功后写一条"目标已捕获"日志，再执行效果。
- **验收**：日志边界齐全：`能力指令收到` → `手动目标捕获` → `瞬移/施法命令发出` → `命中或 HP 变化`。

> ⚠️ 坑：从 `Special Ability` context 猜目标单位 → 目标经常为 nil 或错单位。

## 7. CCO：读当前生效的 ability phase

原版 HTML 文档几乎不写 CCO，但实战必需（RLH 工具库与无双英灵录证明）：

```lua
common.get_context_value(
    "CcoBattleUnit",
    tostring(unit:unique_ui_id()),
    "ActiveEffectList.Size"
)
-- ActiveEffectList.At(i).PhaseRecordContext.Key
-- NumEntitiesInitial 等
```

- **怎么做**：读 phase 优先走 CCO；读不到时回退到同一 phase 施加的**两个原版 attribute**（如 `stalk` + `unspottable`，要求同时存在）。
- **验收**：日志打印 `ActiveEffectList.Size` 与每个 `.Key`；回退分支能独立命中同一目标。

> ⚠️ 坑：新建 `unit_attributes` 做脚本标记 → 可能无法启动。只用原版键，组合两个以上做标记。

## 8. 反模式表（照抄，踩坑价值最高）

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 把 `heal_hitpoints_unary` 当增量 | 血量跳到错误比例 | 传**目标比例**；减血用 `reduce` 传差值 |
| 从 `Special Ability` context 猜目标单位 | 目标经常为 nil/错 | phase / attribute / CCO 扫描 |
| 新建 `unit_attributes` | 可能无法启动 | 只用原版键，组合标记 |
| 隐藏技能不 disable | AI/误触乱放 | 默认 disable，窗口内短暂 enable |
| 只靠 `bm:callback` 做高频捕获且紧跟 UC 命令 | 回调丢失 | 原生 `register_repeating_timer` 或先入队再瞬移 |
| 战斗结束不清理 | 下一场异常 | `Complete` 阶段 `unregister_timer` / `remove_process` |
| 无 `pcall` 调引擎 API | 单次失败拖垮整脚本 | 工具函数统一 `safe_call` |
| 用战役思维写 `core:add_listener` 且忘了战斗环境 | 监听不到 | 战斗优先 `bm:register_*` |
| 写 `unit:unit_controller()` 取 UC | **该方法不存在**，脚本报错 | `bm:get_scriptunit_for_unit(unit).uc`；见 §2 |
| 用 `bm:out()` 当调试日志但不确认日志开关 | 未启用时缺失输出，误判"脚本没跑" | 核对开关或用 `ModLog()`；见 §1.1 |
| 轮询时无去重地重复下命令 | 玩家手动调整被几秒后改回去 | `unique_ui_id()` 去重；见 §4.1 |

## 9. 实践模式（脚本施法骨架）

```lua
bu:disable_special_ability(ability_key, false)   -- 窗口内短暂启用隐藏技能
bm:callback(function()
    if not bu:can_perform_special_ability(ability_key) then
        bu:disable_special_ability(ability_key, true)
        return
    end
    su.uc:perform_special_ability(ability_key, target_bu)
    -- 或 perform_special_ability_ground(ability_key, position)
    bm:callback(function()
        bu:disable_special_ability(ability_key, true)   -- 用完立刻收回
    end, reset_delay_ms)
end, cast_delay_ms)
```

**共用设计原则**：

1. **DB 能做的别用脚本**（伤害、半径、特保 phase、单次瞬移）。
2. **脚本只做编排**：找单位、读标记、延时、连发、换血、多段瞬移。
3. **目标捕获与效果执行分层**：没有"目标已捕获"日志前，不改伤害/生命 API。
4. **只用原版 attribute** 做脚本可读标记。
5. **所有引擎调用包 `pcall`**；日志统一前缀（`[wyccc_duya]` / `RLH_Log`）。
6. **战斗结束清理** timer / process。

**工作流**：

```
① DB：主能力（玩家可见）+ 可选隐藏执行能力 + phase（自身特保/目标标记）
      + special_ability_phase_attribute_effects（原版 attribute，positive）
② Lua：script/battle/mod/xxx_battle.lua
      - 按 unit:type() 找到角色
      - register_command_handler_callback("Special Ability", ...)
      - 定时扫描标记 / CCO phase
      - 执行 teleport / perform_special_ability / heal·reduce
③ 日志边界：能力指令收到 → 手动目标捕获 → 瞬移/施法命令发出 → 命中或 HP 变化
```

- **验收**：四个日志边界齐全；缺哪条只排查那一层，不要在目标未捕获时改伤害/vortex 数值。

## 10. API 数量附录（参考，不进正文结论）

数量来自原版 HTML `name="function:..."` 统计，**随版本漂移**；完整签名以 `源码/documentation/script/battle/*.html` 为准。

| 接口 | 约数 | 用途摘要 |
|---|---|---|
| `battle_manager` | 183 | 单位集合、阶段、事件、时间、消息 |
| `battle_unit` | 110 | 查询与部分状态修改 |
| `battle_unitcontroller` | 77 | 下命令 |
| `script_unit` | 151 | 查询+控制封装 |
| `battle` | 123 | 原生同盟/相机/音乐/timer/UI |
| `global` | 214 | `v()` 向量、距离工具、类型检查、音效 |
| `generated_battle` | 126 | 消息驱动的军队级剧本战 |
| `core` | 105 | 跨环境核心（事件、SVR、mod 加载） |
| `common` | 58 | UI/CCO 上下文（含 `get_context_value`） |

容器接口：`battle_alliances` / `alliance`（`count()` / `item(i)`、`alliance:armies()`）、`battle_armies` / `army`（`army:units()`）、`battle_units`（`count()` / `item(k)`，**1-based**）、`battle_vector`（`get_x/y/z`、`distance` / `distance_xz`）。

## 11. 验收清单

- [ ] 脚本位于 `script/battle/mod/`，库工具用 `!!` 前缀且先加载
- [ ] 全程用 `bm`，没有误用 `cm` 或 `cm:add_first_tick_callback`
- [ ] 所有延时按**毫秒**写；从战役脚本复制的代码已换算
- [ ] 下命令一律经 UC 或 `script_unit`，没有试图用 `battle_unit` 直接下命令
- [ ] 高频捕获用 `register_repeating_timer`，且全局函数名与 timer 名一致
- [ ] `Special Ability` 只用于开捕获窗口，目标来自 phase / attribute / CCO
- [ ] 隐藏能力默认 `disable`，窗口内短暂 `enable`，用完立即收回
- [ ] 每个 timer / process / repeat_callback 都在 `Complete` 阶段清理
- [ ] 引擎调用包 `pcall`，日志有统一前缀与四个边界输出
- [ ] 未新建 `unit_attributes`；标记只用原版键组合
- [ ] 调试日志用 `ModLog()`（不是 `bm:out()`），且 `lua_mod_log.txt` 能看到自己的前缀行
- [ ] UC 经 `bm:get_scriptunit_for_unit(unit).uc` 或 `script_unit:new(unit).uc` 取得，未写 `unit:unit_controller()`
- [ ] 需要覆盖援军的场景：轮询 + `unique_ui_id()` 去重 + `Complete` 清理三件套齐全
