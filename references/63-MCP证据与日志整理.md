# 63 · MCP 证据与日志整理

> 适用：已有游戏端查询、Lua/UI/CCO 状态与脚本日志的整理；普通 pack 问题先读 03/60。
> 整理：2026-10-27 ｜ 来源：scnjwyc `45a4c4b` 的 MCP 证据流程及其固定版本源码审查摘要。
> 边界：未安装或注册新服务、未运行游戏端命令；本册不附 MCP 服务或文件采集器。

## 1. 先确认工具与问题

游戏端 pack、外部 MCP 服务和当前聊天可调用工具是三件事。订阅 pack 不证明服务已经配置，工具名出现在文档也不证明会话可用。游戏启动、采集和操作依用户授权与项目规则分工，不能照搬上游项目的私人权限约定。

先写玩家实际触发步骤、目标对象和要比较的字段，注明前端/战役/战斗环境。查询得到成员非 nil 不证明它是可调用函数，更不证明参数正确。`eval`、任意 Lua 或 CCO 表达式可能写状态，须检查实际内容；直接授予奖励或技能可搭场景，却绕过玩家合法性与事件路径，不能当流程修复证据。

## 2. 保留请求与响应原件

为每次采集记录版本、pack 指纹、上下文、对象身份/CQI、时间和实际操作，分别保留请求、原始响应、相关日志。输出放独立研究目录，不删除或改写原结果。若协议没有请求编号，标签和相近时间不能单独证明响应归属；结合用户操作记录，无法闭合就写未知。

按顺序检查：文件是否存在 → 读取期间是否变化 → 编码 → JSON 完整性 → 响应内部 status → 必需字段 → 业务含义。JSON 不合法时保留原字节与错误；另存修复副本也不能冒充原响应。文件整理成功只证明整理完成。

## 3. 对照前后日志

用源路径、指纹、记录边界和实际新增内容对照，不能按文件名相同就当本次日志。重写、轮换或读取期间变化时重新建立基准；保留相关完整原文，展示时可以摘录。

上游对其固定版本工具报告了 JSON 转义不完整、错误匹配条数上限、offset 前推、额外日志未计入总标志和固定文件通信缺少关联等问题。这些是版本相关线索，本次没有对当前第三方服务重验。不要仅依赖 `has_new_errors=false`、`no_matches`、`pcall` 成功或成功退出码判断游戏通过。

缺日志、无有效响应、缺字段或响应身份不明都保留为缺口。多个客户端和重试须考虑旧响应、覆盖、取消与会话关联；不能靠固定延迟证明某响应属于本次请求。

## 4. 跨层补证与验收

- [ ] 请求来源、响应原件、上下文、对象身份和采集时间可核对；读取变化与解析错误未隐藏。
- [ ] 区分界面显示、操作调用、状态实际变化和游戏结果，未把测试捷径当玩家路径。
- [ ] 历史错误与新增错误分开；检索无命中不被写成没有错误。
- [ ] Lua 行为转 [45](45-Lua离线回归.md)，接口差异转 [46](46-CA字符串接口.md)，原生问题转 [62](62-运行时样本与内存研究.md)。userdata 的 tostring 不被当作已核验的原生对象指针。
