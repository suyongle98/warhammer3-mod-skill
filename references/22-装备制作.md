## 1. 装备体系总览

装备由 **`category`（占哪个槽）** + **`subcategory`（UI 分组）** 决定。

| `category` | 槽位 | 原版 `icon_name` | 说明 |
|---|---|---|---|
| `weapon` | 武器 | `equipment_items_weapon` | |
| `armour` | 护甲 | `equipment_items_armour` | |
| `talisman` | 护符 | `equipment_items_talisman` | |
| `enchanted_item` | 魔法物品 | `equipment_items_enchanted` | |
| `arcane_item` | 秘法物品 | `equipment_items_arcane` | |
| `mount` | 坐骑 | `equipment_items_mount` | 见 §7 |
| `general` | 一般装备（随从/方旗/符文/印记/礼物/毒药共用这一槽） | `equipment_items_mount` | 用 `subcategory` 分组 |
| `form` | 形态 | `placeholder` | `hidden=true`，非玩家槽位 |

依据：`游戏原文件\db\ancillaries_categories_tables\data__.tsv`（8 行，实测）。

**`subcategory` 原版全部合法值**（`ancillaries_subcategories_tables`，11 个）：
`armour_rune` / `banner` / `banner_rune` / `character_rune` / `engineering_rune` / `follower` / `gift` / `mark` / `poison` / `rune` / `spell_fragment`

> ⚠️ 坑：新增 `category` 或 `subcategory` → 引擎不识别，装备不出现在槽位/分组里（硬规则：只能用原版枚举）。

**验收**：`ancillaries_tables` 的 `category`/`subcategory` 值都出现在上面两张原版表里（`grep` 确认）。

## 2. 最小可用表集合

| 表 | 必填? | 作用 | 漏了的表现 |
|---|---|---|---|
| `ancillaries_tables` | **必填** | 装备本体（字段字典见 14） | 装备不存在 |
| `ancillary_info_tables` | **必填** | 注册装备 key（每件一行） | 装备不显示/不完整 |
| `ancillary_to_effects_tables` | 有数值效果时必填 | 装备 → 效果 | 装备无加成 |
| `ancillary_types_tables` | **general 类必填**；普通装备复用原版共享 type | `type` + `ui_icon` | general 类无图标 |
| `ancillary_to_included_agents_tables` | 需限领主/事务官时 | 限 `agent`（`general`/`champion`/…） | 战旗无法分配给部队 |
| `ancillaries_included_agent_subtypes_tables` | **坐骑必填**，其它按需 | 限 `agent_subtype` | 坐骑谁都能骑 |
| `ancillaries_required_skills_tables` | 需前置技能时 | 前置技能与等级 | 前置失效 |
| `text\db\*.loc.tsv` | **必填** | 名称与描述 | 显示键名原文 |
| 套装链 / 方旗链 / 技能链 | 按需 | 见 §4–§6 | — |

**普通装备的共享 type**（原版 `ancillary_types_tables` 实测存在）：
`wh_main_anc_weapon` / `wh_main_anc_armour` / `wh_main_anc_talisman` / `wh_main_anc_enchanted_item` / `wh_main_anc_arcane_item`

> ⚠️ 坑：以为坐骑也有共享 type `wh_main_anc_mount` → 原版不存在；坐骑是**每个坐骑一个 type**，图标在 `ui/campaign ui/mounts/`。

**general 类装备的 type 规则**：`type` = 装备自身 key，并在 `ancillary_types_tables` 加一行 `type` + `ui_icon=ui/campaign ui/ancillaries/{key}.png`。
**怎么做**：抄一个原版同类行（如 `wh2_dlc09_anc_tmb_herald`）做基准。
**验收**：装备栏里图标正常显示，且图标文件名 = 装备 key。

## 3. 主链：`ancillaries_tables` → `ancillary_to_effects_tables` → `effects_tables`

```tsv
# ① ancillaries_tables（29 列，列名见 14）
my_mod_anc_weapon_frost_blade	wh_main_anc_weapon	.	true	false	false	1	0	9999	false	false	false	weapon	16	30	30	50	true			80	0		true	true	true	all
# ② ancillary_to_effects_tables
my_mod_anc_weapon_frost_blade	wh_main_effect_character_stat_melee_attack	character_to_character_own	10.0000
# ③ 若用自定义 effect 才需要 effects_tables 一行
```

**怎么做**：
1. 效果键先查 `references\效果实现速查表.md` 与原版 `effects_tables`；**纯数值属性直接引原版键，不自定义**。
2. 只有"启用技能 / 激活攻击附魔 / 属性授予"这类必须挂 junction 的效果才自定义 effect 键。
3. 作用域选 `effect_scope`（常用值）：

| `effect_scope` | 生效目标 |
|---|---|
| `character_to_character_own` | 装备持有者本人 |
| `character_to_force_own` / `_alt_text` / `_unseen` | 持有者所在军队 |
| `character_to_faction_unseen` | 派系（科技点、外交…） |
| `character_to_province_any` / `character_to_region_own_factionwide` | 行省 / 区域 |
| `force_to_force_own` | 军队级技能启用 |
| `character_to_character_own_banner` | **方旗专属**（只给携带方旗的单位），见 §5 |

4. `value` 随效果键：属性型写修正值（`10.0000`=+10）、百分比型写百分数（`40.0000`=+40%）、启用型写 `1.0000`；负值是否有益由 `effects_tables.is_positive_value_good` 决定。

> ⚠️ 坑：把机械效果写进描述文本 → 效果栏重复/显示异常（描述只写背景，见 §9）。

**验收**：装备上身后效果栏出现该效果；`grep` 确认 effect 键存在于原版 `effects_tables` 或本 MOD 的 `effects_tables`。

## 4. 套装链（可选，2–4 件一套）

| 表 | 内容 |
|---|---|
| `ancillary_sets_tables` | `key` + `icon`（图标在 `ui/skins/default/`） |
| `ancillary_set_ancillary_junctions_tables` | `ancillary_key` + `set_key`：套装成员 |
| `ancillary_set_effect_junctions_tables` | `effect_key` + `set_key` + `effect_scope` + `value`：集齐后生效 |

**怎么做**：先建 `ancillary_sets_tables` 一行 → 每件成员装备一行 junction → 集齐效果一行（效果键同 §3 规则）。
**验收**：游戏内集齐后效果生效；成员装备的 tooltip 显示套装名（`ancillary_sets_name_{set}` 已本地化）。

## 5. 方旗链（可选；战旗必须走两条路径之一）

方旗（banner）的**效果不走 `ancillary_to_effects_tables`**，走 `effect_bundle`：

| 表 | 内容 |
|---|---|
| `banners_tables` | `banner` + `effect_bundle` |
| `effect_bundles_tables` | `key` + `bundle_target=character` |
| `effect_bundles_to_effects_junctions_tables` | `effect_bundle_key` + `effect_key` + `effect_scope=character_to_character_own_banner` + `value` + `advancement_stage` |
| `banners_permitted_unit_sets_tables` | `banner` + `unit_set`（**无论是否限制都必须填**，无限制填 `all_units`） |

**两条路径（都在 bundle 内，区别是效果键类型）**：

| 路径 | 效果键 | 适用 |
|---|---|---|
| A 纯数值 | 原版数值键，如 `wh_main_effect_character_stat_armour` | 只加属性 |
| B 带技能/自定义被动 | 启用型键：原版 `*_effect_ability_enable_*`，或自定义 effect + junction（`enable`/`active`） | 方旗带技能或攻击附魔 |

依据：原版 `banners_tables` 全部指向 `*_bundle_anc_*`；参考实现 `参考mod\Just More Items` 的 67 条方旗 bundle junction 中两类键都有（`wh_main_effect_character_stat_armour` 与 `wh2_dlc10_effect_ability_enable_ironwardens_shield`）。

**战旗三处同 key**：`ancillaries_tables.provided_banner`、`banners_tables.banner`、`banners_permitted_unit_sets_tables.banner`（都等于装备 key）。

**必做限制**：
- `ancillary_to_included_agents_tables` 加 `general`（只让领主持有）。
- `banners_permitted_unit_sets_tables.unit_set` 取 `unit_sets_tables` 里**存在**的键；原版实测有 `all_units` / `missile_units` / `all_land_artillery` / `characters` / `dwf_slayers` 等 45 种，按需 `grep` 确认。

> ⚠️ 坑：战旗不加 `general` 限制 → 事务官也能装备，但无法分配给部队，等于废装备。
> ⚠️ 坑：方旗不填 `banners_permitted_unit_sets_tables` → 战旗无法分配。

**验收**：装备方旗后，把战旗拖到某部队上能成功；效果数值出现在该部队面板。

## 6. 装备上的战斗技能（只讲挂接）

**怎么做**（技能本体在 21 造好后，选下面一条挂到装备上）：

| 形态 | 挂接方式 |
|---|---|
| 主动 / 被动 / 军队技能 | 自定义 effect + `effect_bonus_value_unit_ability_junctions_tables`（`enable`）或 `effect_bonus_value_military_force_ability_junctions_tables`（`enable`）；装备 → 该 effect 走 `ancillary_to_effects_tables` |
| 攻击附魔（武器附带毒/火/诅咒） | 自定义 effect + `effect_bonus_value_special_ability_phase_record_junctions_tables`（`active`）→ 直接激活 phase，**不需要 `unit_special_ability`** |
| 方旗带技能 | 把上面的启用型 effect 写进 §5 的 bundle |

**必查**：
- 技能要在 `unit_abilities_tables` 有行（`icon_name` = 技能 key，图标在 `ui/battle ui/ability_icons/{key}.png`），否则战役 UI 不显示。
- 军队技能另需 `army_special_abilities_tables` 一行。
- 技能形态、junction、硬规则 → **21 册**；逐列字段、攻击附魔、光环、投射物/涡流/炮击 → **26 册**。

> ⚠️ 坑：只在 `ancillary_to_effects_tables` 写一个 enable 效果、不建 junction 行 → 技能不出现（启用必须经 junction 表）。

**验收**：装备后技能出现在角色/部队技能栏并可释放；攻击附魔在命中敌人时目标身上出现 phase 提示。

## 7. 坐骑链（五步）

1. **造坐骑单位**：按 `23-兵种新增与修改.md` 造一个能在自定义战斗正常使用的单位；`main_units_tables.mount` → `campaign_mounts_tables.model`（大地图坐骑显示；留空则战斗中骑乘、大地图步行）。
2. **做成装备**：`category=mount`；`provided_bodyguard_unit` = 该坐骑的 `main_units_tables.unit`；`transferrable=false`、`randomly_dropped=false`；`turns_before_swap_allowed=1`。
3. **加限制**：`ancillaries_included_agent_subtypes_tables` **必填**（`agent_subtype` + 装备 key）。
4. **加获取途径**：角色技能（`character_skill_level_to_ancillaries_junctions_tables`，见 `13`）或 Lua 发放（§10）。
5. **补大地图动作**：`campaign_mount_animation_set_overrides_tables` **必填**：`character_animation_set`（步行动作）+ `mount_unit` + `rider_animation_set`（骑乘动作）+ `vfx_filter_override`（多数填 `0`）。

**查动作键的方法**：想参考哪个原版英雄，就查 `campaign_character_arts_tables` 的 `art_set_id` → `land_animation`；骑乘动作抄原版同坐骑单位那一行。

> ⚠️ 坑：不填 `campaign_mount_animation_set_overrides_tables` → 大地图上以**步行动作**骑坐骑。
> ⚠️ 坑：坐骑不填 `agent_subtype` 限制 → 同类型所有角色都能骑（如死爪被任意帝国事务官骑）。
> ⚠️ 坑：坐骑勾了 `transferrable`/`randomly_dropped` → 坐骑被夺取/随机掉落。
> ⚠️ 坑：骑乘后模型持握方式要变（如换武器）却没填 `campaign_character_uniform_ancillary_junctions_tables` → 战役中仍用步行模型。

**验收**：进战役 → 装上坐骑 → 大地图移动动作正常、战场模型与兵牌正常、换下坐骑后恢复步行。

## 8. 派系组与稀有度

### 8.1 种族限制用 `faction_set`

`ancillaries_tables.faction_set` → `faction_sets_tables.key`。

- **优先用原版内置键**：`all`、`anc_set_exclusive_dwarfs`、`anc_set_exclusive_tomb_kings`、`anc_set_exclusive_kislev`…（原版共 203 键，`grep` 确认存在再用）。
- 需要自定义组时：`faction_sets_tables` 加 `key`，`faction_set_items_tables` 每行 `id` + `culture`/`faction`/`subculture` **三选一** + `set` + `remove`。
- 实测原版 1107 行：`culture` 非空 272、`faction` 非空 747、`subculture` 非空 79，**无一行 culture 与 faction 同时非空**。

> ⚠️ 坑：把 faction key 填进 `culture` 列 → 该行不生效，装备派系限制错乱。
> ⚠️ 坑：`faction_set_items_tables.id` 超过 2,147,483,647 → 行不加载（原版实测取值范围 1,081,455–2,146,346,997）。
> ⚠️ 坑：参考实现 `参考mod\Just More Items` 用了 `id=2992992992`（超 I32 上限），**不得照抄**；该 MOD 的号段约定见其自身 README。【未验证：该值是否被引擎接受】

种族限制按本节的 faction set 链填写，核对当前原版同类装备。

**验收**：非该派系角色拿到该装备时无法装备/不出现。

### 8.2 稀有度用 `uniqueness_score`

WH3 的档位由 `ancillary_uniqueness_groupings_tables` 定义（**以这张表为准**）：

| `uniqueness_score` | 原版分组键 | `ui_state` | 颜色 |
|---|---|---|---|
| 35–50 | `wh_main_anc_group_common` | common | 灰 |
| 80–100 | `wh_main_anc_group_uncommon` | uncommon | 绿 |
| 130–150 | `wh_main_anc_group_rare` | rare | 蓝 |
| 151 | `wh2_dlc17_anc_group_rune` | crafted | 青 |
| 199 | `wh_main_anc_group_crafted` | crafted | 锻造色 |
| 200 | `wh_main_anc_group_unique` | legendary | 紫 |

**200 档 = 唯一/传奇**：`randomly_dropped=false`，只能由 Lua 条件发放（§10）。

> ⚠️ 坑：照抄教程 17 的"灰 0~29 / 绿 30~49 / 蓝 50~100 / 锻造 101~150 / 紫 151~999" → 那是 WH2 的分段，与 WH3 `ancillary_uniqueness_groupings_tables` 不符，颜色档位会错。

**验收**：装备图标边框颜色与上表一致；200 档装备不出现在随机掉落里。

## 9. 本地化键清单

文件：`text\db\<前缀>_<域>.loc.tsv`（参考实现：`参考mod\Just More Items\text\db\skulls_ma_ancillaries.loc.tsv`）。键可先在 `<VANILLA>\local_cn\text\localisation__.loc.tsv` 检索同类原版写法。

| 键模板 | 内容 |
|---|---|
| `ancillaries_onscreen_name_{key}` | 装备名称（必写） |
| `ancillaries_colour_text_{key}` | 背景/传说文本（必写，**只写叙事**） |
| `effects_description_{effect}` | 自定义效果的说明行 |
| `ancillary_sets_name_{set}` | 套装名 |
| `effect_bundles_localised_title_{bundle}` / `_description_{bundle}` | 方旗 bundle 标题/说明 |
| `unit_abilities_onscreen_name_{ability}` / `unit_abilities_tooltip_text_{ability}` | 技能名 / 技能描述 |
| `special_ability_phases_onscreen_name_{phase}` | 攻击附魔在目标身上的提示名（可带 `[[col:...]]`、`[[img:...]]`） |

**描述字段铁律**：`ancillaries_colour_text_*`、`unit_abilities_tooltip_text_*`、`special_ability_phases_onscreen_name_*` 内**禁止**出现数值、次数、冷却、范围、触发条件、等级、获取方式——机械信息由效果面板与 `effects_description_*` 承担。

**验收**：游戏内装备名与描述为中文且无键名残留；描述里没有任何数字型机制说明。

## 10. 获取方式

### 10.1 原版随机掉落池
`randomly_dropped=true` 即进入战后/事件掉落池；`uniqueness_score` 与 `faction_set` 约束稀有度与派系。

### 10.2 Lua 条件发放
文件：`script/campaign/mod/<name>.lua`（无 BOM，Lua 5.1，提交前 `luac5.1 -p`）。

```lua
-- 发放 API（依据 游戏原文件\script\ 中大量原版调用）
cm:force_add_ancillary(character, ancillary_key, bool, bool)      -- 直接给角色
cm:add_ancillary_to_faction(faction, ancillary_key, bool)         -- 进派系库存
faction:ancillary_exists(item_key)                                -- 防重复
```

**怎么做**：监听器写在 `cm:add_first_tick_callback` 内注册（否则读档后失效）；条件里判玩家 `faction:is_human()`、判角色 `character:rank()`/`character:is_caster()`/`cm:char_is_general_with_army()`；发之前用 `faction:ancillary_exists` 防重复。

> ⚠️ 坑：装备 key 没在 `ancillaries_tables` 注册就调用发放 → **静默失败**（无报错，装备不入包）。
> ⚠️ 坑：监听器注册在 `cm:add_first_tick_callback_new` 里 → 读档后不生效。

**验收**：触发条件满足后装备出现在角色/派系库存；存档再读一次不重复发放。

## 11. 必守规则与坑（速查）

1. 只引用原版 key（effect / `unit_set` / `stat_*` / `wh_type_*` / 视觉资源）；新增只限自己的装备、effect、bundle、套装、派系组。
2. 不新增 `category` / `subcategory` / `unit_attribute`。
3. 数字主键 ≤ 2,147,483,647（`faction_set_items_tables.id`、技能 `unique_id` 等）。
4. 每件装备在 `ancillary_info_tables` 有一行。
5. general 类装备必须注册 `ancillary_types_tables`。
