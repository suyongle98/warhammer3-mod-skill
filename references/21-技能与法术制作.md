## 0. 一页速览

1. 一条技能 = `unit_abilities_tables`（UI 层）+ `unit_special_abilities_tables`（战斗层），**两表 key 同名**。
2. 效果本体走 **phase**（`special_ability_phases*`）；投射物/轰炸/涡流/召唤是另一类出口。
3. `requires_effect_enabling=true` 的技能**必须**有 effect enable junction，否则战役里看不到。
4. `unique_id` 重复是致命错：技能点了没反应。
5. 攻击附魔**没有通用 effect**，必须自定义 passive + phase 的 `imbue_contact`；抄原版同形态整行再改，别从零填 70+ 列。
6. **「技能放不出来」有两大来源**：`unique_id` 冲突（第 4 条），以及**目标字段组不自洽**（`affect_self`/`target_*`/`only_affect_target`/`num_effected_*`，见 §3.1）——
   后者常伪装成「能对着别人点、却放不出」。

## 1. 四种技能形态与必填表

| 形态 | 判定字段 | 必填表 |
|---|---|---|
| **主动技能** | `source_type=active`；`passive=false`；出口填 `activated_projectile`/`bombardment`/`vortex` 之一 | ① `unit_abilities_tables` ② `unit_special_abilities_tables` ③ 出口表 ④ 启用 junction（§9） |
| **被动技能** | `passive=true`、`active_time=-1`、`recharge_time=-1`、`source_type=passive`、`effect_range=-1` 或半径 | ①②③ `special_ability_to_special_ability_phase_junctions_tables` ④ `special_ability_phases_tables` ⑤ 可选 stat/attribute 表 ⑥ 启用 junction |
| **法术** | `source_type=spell`（绑定法术 `bound`）、`mana_cost>0`、`type=wh_type_magic_missiles` 等 | 同主动 + 可选学派组（§5）+ 出口表 `is_spell=true` |
| **阵型技能** | `unit_abilities.type=wh_type_formation`；`unit_special_abilities.formation` 非空（值取自原版 `special_abilities_specific_formation_types_tables` 的 13 个枚举：`wedge_formation` / `flying_wedge_formation` / `testudo_formation` / `diamond_formation` / `square_formation` / `shield_wall_formation` …） | ① `unit_abilities_tables` ② `unit_special_abilities_tables` ③ `special_ability_to_special_ability_phase_junctions_tables` ④ `special_ability_phases_tables` ⑤ `special_ability_phase_stat_effects_tables` ⑥ **兵种挂载 junction（§9）** |

（军队技能见 §5，攻击附魔见 `26-技能后端与效果出口.md` §2。）

**阵型技能要点**（原版实例：`wh_dlc07_unit_formation_lance` 骑枪阵型、`wh3_dlc25_unit_formation_shieldwall` 盾墙阵型）：

- 阵型形状由**引擎硬编码**，`special_abilities_specific_formation_types_tables` 只是一张 key 列表，**不描述形状**；形状值必须从这 13 个枚举里取，不得自造。
- 形态特征：`active_time=-1`（常驻直到手动关闭）、`num_uses=-1`、`passive=false`、`formation` 非空。`unit_abilities.is_unit_upgrade` 原版 `lance=false`、`shieldwall=true`，两种都有先例，**该列不是能否显示的决定因素**。
- 阶段分两段：`order 1 = <ability>_buffer`（缓冲，`duration` 3~10 秒）+ `order 2 = <ability>`（主阶段，`duration=-1`）。参照原版 `wh_dlc07_unit_formation_lance` 与 `wh3_dlc25_unit_formation_shieldwall`。
- ⚠️ 坑：**原版 `special_ability_phases_tables` 里存在孤立 phase**（`wh_dlc07_unit_formation_flying_wedge`、`wh_dlc07_unit_formation_diamond`）——只有 phase 行，没有 `unit_abilities` / `unit_special_abilities` 行，**游戏里根本不存在这个技能**。看到 phases 表里有 key 不等于技能存在，必须回查 `unit_abilities_tables`。

**验收**：两表 key 完全一致；每张必填表有行；自定义战斗与战役都能释放。

## 2. 数据流（法术接 4 类出口）

```
unit_abilities_tables            名称/图标/type/source_type/requires_effect_enabling
      │ key 一一对应
unit_special_abilities_tables    时长/冷却/魔耗/目标/施法姿态/效果出口
      ├── activated_projectile ─► projectiles_tables ─► projectiles_explosions_tables
      │                                                / projectile_displays_tables
      │                                                / projectile_shrapnels_tables
      ├── bombardment ──────────► projectile_bombardments_tables ─► projectiles_tables
      ├── vortex ───────────────► battle_vortexs_tables ─ contact_effect ─► phases
      ├── spawned_unit ─────────► land_units_tables（召唤/变形/诱饵）
      └── special_ability_to_special_ability_phase_junctions_tables
                └──► special_ability_phases_tables（增益/减益/DoT/治疗/附魔）
                          ├── special_ability_phase_stat_effects_tables
                          └── special_ability_phase_attribute_effects_tables
```

**判定「这是法术」**：`source_type=spell`、`mana_cost>0`、`projectiles.is_spell`/`battle_vortexs.is_spell=true`。

## 3. 三张核心表关键字段

> 三张表的**逐列字段清单**（关键列语义、必填项、DoT 限制等）见 `26-技能后端与效果出口.md` §1。

### 3.1 目标字段组必须自洽 —— 不自洽 =「能对别人点、却放不出来」

`affect_self` / `target_self` / `target_friends` / `target_enemies` / `target_ground` / `only_affect_target` /
`num_effected_friendly_units` / `effect_range` / `target_intercept_range` 是**一组**字段：
**互相打架时引擎不报错**，只表现为技能放不出来（点了没反应 / 能对着别人点选却无效）。

| 形态 | affect_self | target_self | target_friends | target_enemies | target_ground | only_affect_target | num_effected_friendly_units | effect_range | target_intercept_range |
|---|---|---|---|---|---|---|---|---|---|
| **点击即自身增益**（最常用） | `true` | `false` | `false` | `false` | `false` | `false` | `0` 或 `1` | `0` | `0` |
| 对友军单体 | `false` | `false` | `true` | `false` | `false` | `false` | `1` | `0` | 100± |
| 友军光环 | `true` | `true` | `true` | `false` | `false` | `false` | `-1` | 半径 | `0` |
| 对敌单体 | `false` | `false` | `false` | `true` | `false` | `false` | `0` | `0` | 视射程 |

- `only_affect_target=true` = 强制「必须选一个目标单位」；原版 641 个"主动 + 自身增益"技能里**只有 3 个**用它。
- **实测踩坑（2026-09-10 · su_wzw 战旗「七进七出」）**：想做"点击即自身增益"，却克隆了
  `wh2_dlc09_item_abilities_elixir_of_might`（原版是**对友军施放**：`affect_self=false`、`target_friends=true`、`target_intercept_range=100`），
  再手填 `only_affect_target=true` + `target_self=true`、`num_effected_friendly_units` 留 `0`
  ⇒ 要选目标 × 四个 `target_*` 全 `false` 无合法目标 × `target_self=true` 把自身塞进可选集合 × 影响单位数 `0`
  ⇒ 游戏里**能对着别的部队点、点下去却放不出效果**。
  修法：整行改用语义同类的原版模板 `wh2_dlc15_item_abilities_lucky_banner`（战旗类物品的自身增益），
  只改 `active_time` / `recharge_time` / `num_uses` / `key` / `unique_id`，其余 66 列照抄。
- **克隆模板必须语义同类**：做"自身增益"抄 `wh2_dlc15_item_abilities_lucky_banner` /
  `wh2_dlc09_item_abilities_staff_of_nagash` / `wh2_dlc16_hero_abilities_warp_frenzy`；做"对友军"才抄 `..._elixir_of_might`。
  **动手前先看原版那一行的 `affect_self` 与 `target_friends`**；语义不对就换模板，别"改了字段就当自己的"。
- **改完必做逐字段对拍**：`scripts/diff-row.ps1`（mod 行 vs 原版模板行；支持 `-ModKey "*"` 全表扫），
  确认只剩你有意改的字段不同。

## 4. 多段阶段模型与四张条件表

`special_ability_to_special_ability_phase_junctions_tables` 列序：`order` `special_ability` `target_self` `target_friends` `target_enemies` `phase`

- 一个 ability 可挂**多个 phase**，每阶段独立 `duration`/`stat_effects`/`attribute_effects`，`order` 排序；各阶段 `duration` 之和 = ability 的 `active_time`，`recharge_time` 通常等于 `duration`，阶段才接续。
- 原版实例（诺斯卡狂怒）：`active_time=135`，三阶段 `wh_dlc08_unit_abilities_rage_i/ii/iii` 各 `45`，`order` 1/2/3。
- 目标先由 junction 的 `target_*` 决定，phase 的 `affects_allies`/`affects_enemies` 再过滤。
**四张条件表**（列序均为「flag + special_ability」；括号内为数据行数）：

| 表 | 列序 | 语义 |
|---|---|---|
| `special_ability_to_invalid_usage_flags_tables`（693） | `invalid_usage_flag` `special_ability` | 何时**不能用**（`engaged_in_melee`、`climbing`、`health_above_50%`…） |
| `special_ability_to_invalid_target_flags_tables`（672） | `invalid_target` `special_ability` | **不能选什么目标**（`unit_is_not_commander_class`、`flying_unit`…） |
| `special_ability_to_recharge_contexts_tables`（89） | `recharge_context` `special_ability` | **仅在某情境下充能**（如仅近战中） |
| `special_ability_to_auto_deactivate_flags_tables`（523） | `deactivate_flag` `special_ability` | 条件满足即**自动关闭**（被动的「生效条件」反读） |

- flag 全是**原版枚举**，全集见 `special_ability_invalid_usage_flags_tables` 等，用 loc 反查中文。
- `special_ability_phase_attribute_effects_tables` 列序：`attribute` `phase` `attribute_type`；`positive` 施加、`negative` 移除（可剥掉敌方属性）；「不灭」= `cannot_die` + `morale_is_lower_than_half_of_base_morale`。

**验收**：多阶段 `order` 连续、`duration` 之和 = `active_time`；条件表 flag 能在原版枚举表查到。

## 5. 技能启用 junction / 法术群组 / 军队技能

| 启用 junction | `bonus_value_id` | 目标列 | 用途 |
|---|---|---|---|
| `effect_bonus_value_unit_ability_junctions_tables` | `enable` | `unit_ability` | 启用主动/被动/法术技能（列序 `effect`\|`bonus_value_id`\|`unit_ability`） |
| `effect_bonus_value_military_force_ability_junctions_tables` | `enable` | `force_ability` | 启用军队技能 |
| `effect_bonus_value_special_ability_phase_record_junctions_tables` | `active` | `special_ability_phase` | 直接激活攻击附魔相位（无需 ability） |

> ⚠️ 坑：`requires_effect_enabling=true` 却没写 enable junction → 自定义战斗可见、**战役里根本看不到**（反读：战役看不到多半是这栏勾了没接 junction）。

**直接授予（不经 effect，把技能发给兵种）**：两张表，用途不同，不得混用。

| 表（列数） | 列序 | 用途 | 适用技能类型 |
|---|---|---|---|
| `land_units_to_unit_abilites_junctions_tables`（2） | `ability` \| `land_unit` | 逐单位显式挂载 | **主动 / 被动 / 法术 / 阵型，全部** |
| `unit_set_unit_ability_junctions_tables`（3） | `key` \| `unit_ability` \| `unit_set` | 给单位集整体授予 | **仅"显式列单位"的单位集**可靠（2026-09-23 快照中 227 行主动技能如此） |

**制作建议：给兵种批量加主动技能优先逐单位挂载。显式单位集存在原版主动技能先例；过滤型集合的已记录失败应按案例范围使用，不扩大成引擎通用禁令。**

- 依据（原版 `unit_set_unit_ability_junctions_tables` 全表 605 行交叉统计，2026-09-23 实测）：

| 单位集的定义方式 | 授予**主动**技能 | 授予**被动**技能 |
|---|---|---|
| 显式单位集（`unit_set_to_unit_junctions` 的 `unit_record` 逐条列单位） | 227 行 | 358 行 |
| 过滤集（`unit_caste` / `unit_class` / `unit_category`） | **0 行** | 19 行 |

- ⚠️ 坑：用 `unit_caste`（如 `melee_cavalry`）/ `unit_class` / `unit_category` 过滤出来的单位集去授予主动技能 → **技能在游戏里完全不出现，全程不报错**。该次快照未找到过滤型授予主动的先例；实测（`su_qbzx` 2026-09-23）自定义单位集里同时放 caste 行与 record 行授予阵型技能，游戏内两个技能按钮都不出现，改用 158 单位 × 2 技能的显式挂载后立即生效。
- 代价与取舍：显式挂载**覆盖不到其它 MOD 新增的兵种**（那些兵种不在原版 `main_units_tables` 里）。要覆盖只能自行补行，或用 Lua 战斗脚本兜底。
- 批次量级参考：158 个单位 × 2 技能 = 316 行；生成方式读 `main_units_tables.caste` 取 `melee_cavalry` / `monstrous_cavalry` 的 `land_unit` 去重。

**法术群组（学派）**：`special_ability_groups_tables`（`ability_group` 等 12 列）→ `special_ability_groups_to_unit_abilities_junctions_tables`（`special_ability_groups` | `unit_special_abilities`）→ `special_ability_groups_to_units_junctions_tables`（`ability_group` | `unit` | `group_page_order`）。

- 只挂**基础版**，超载版不单独进组；绑定法术（`bound`）可不进组。
- 施法单位的**每个坐骑状态**都要在 `…_to_units` 各加一行，漏一个该形态就没法术。
- 群组按目标施法单位的当前原版法术页结构接线，并在游戏中检查页签归属。

**军队技能**：`army_special_abilities_tables` 列序 `army_special_ability` `unit_special_ability` `unique_id` `enables_siege_assault`；再用 `effect_bonus_value_military_force_ability_junctions_tables`（`enable`）挂到建筑/科技/将军 effect。

**验收**：junction 行存在且 `bonus_value_id` 正确；`…_to_units` 覆盖全部坐骑形态。

## 7. 硬规则与坑

1. **`unique_id` 全局唯一且 ≤ 2,147,483,647**。重复后果：A 被 B 覆盖或 B 权重不够 → **技能无法释放**（需瞄准的不能瞄准、buff 不生效）。
2. **只改 `unit_abilities` 不改 `unit_special_abilities`** → 没有战斗实体。
3. **`requires_effect_enabling` 与 enable junction 必须配对**（§5）。
4. **phase DoT 不设 `max_damaged_entities`** → AOE 按实体数爆炸级放大。
5. **`autoresolver_usage` 留空** → 可能崩溃；**`battle_vortexs.shape` 留空** → 可能崩溃。
6. **军队技能 `initial_recharge=0`** → 易异常，给短初始冷却。
7. **群体单位挂投射物能力** → 每个兵模都会放，伤害 × 人数；**没有施法动画的单位挂投射物法术** → 可能瞬放并退还冷却/魔风。
8. **超载法术**：基础版 `overpower_option` 指向超载 key，两套 `unit_special_abilities`/投射物/涡流都要齐。
9. **不新增** `unit_attributes`、`intensity_source`、`unit_ability_types`、`stat_*`/`scalar_*` 键、phase display key——只引用原版；抄原版整行再改；描述字段只写背景。
10. **目标字段组不自洽 → 技能放不出来**：典型组合 `only_affect_target=true` + 四个 `target_*` 全 `false` + `num_effected_*_units=0`（§3.1）。
    根因多是**克隆了语义不同的模板**（做"自身增益"却抄了"对友军施放"的技能行）。**换模板，不要靠试字段**。
11. **`unit_abilities.source_type=banner` 的原版技能全表只有 1 个**（`wh2_dlc15_banner_passive_da_immortulz`，且 `is_hidden_in_ui=false`）。
    把 banner 技能设成 `is_hidden_in_ui=true` 属原版无先例的做法——只影响 UI 显示，但**用户看不到就会判定"没做"**，要可见性时别隐藏。
12. **批量给兵种加主动技能优先用显式挂载**：`unit_caste` / `unit_class` / `unit_category` 过滤出来的 `unit_set` 不能授予主动技能（2026-09-23 快照无先例；当前表 726 行，统计不能当新版本硬上限），必须用 `land_units_to_unit_abilites_junctions_tables` 逐单位挂载（§5）。
    后果：技能按钮**完全不出现且无任何报错**，最容易被误判成"打包/加载没生效"而反复排查加载问题。

## 8. 验收清单

- [ ] `unit_abilities.key` = `unit_special_abilities.key`；形态判定字段一致
- [ ] `requires_effect_enabling` 与 enable junction 配对；自定义战斗 + 战役都能释放
- [ ] 多阶段：`order` 连续、`duration` 之和 = `active_time`；四张条件表 flag 均为原版枚举
- [ ] 攻击附魔：`active` junction + `imbue_contact` + stat_effects + `phase_display`
- [ ] 被动光环：phase junction 的 `target_self/friends`、`duration=-1`、`affects_*` 正确
