## 2. 建表方式：按攻击动作挑原版模板（最稳）
- **怎么做**：① 先决定新兵种用哪套攻击/移动动作 → ② 在 `land_units_tables` 里找用同一动作的原版兵种 → ③ 整行复制当模板，只改 `key` 与数值 → ④ 连带复制 `main_units` / `unit_variants` 的对应行。
- **依据**：教程 05「这个判断通常用攻击动作，我的新兵种想使用谁的、或哪类攻击动作，就用其当模版」。
- **为什么最稳**：动作决定骨骼、武器槽格式、溅射与连发弹丸能否触发（§11）。
- 验收：进战斗能移动、攻击、装填；无摆大字、武器消失、射不出弹。
- > ⚠️ 坑：先定数值再随手挑模板 → 动作/骨骼不匹配，模型错乱或不会动，只能整行重做。

## 3. 血量按单位结构计算

**普通无载具步兵**：`总血量 = num_men × (bonus_hit_points + 乘员实体hit_points)`。原有WH3案例 `wh_main_emp_inf_swordsmen`：61额外血量、实体8、120人，合计8280。此式不能直接套到多乘员战车，也不能把载具每模组目标生命除以乘员数。

**`su_gmzc`双牵引、有关节战车的计算案例**：

```text
总血量 = num_men × 乘员基础生命
       + num_engines × num_mounts × 牵引实体基础生命
       + num_engines × (车体基础生命 + bonus_hit_points)
       + num_engines × 关节实体基础生命
```

- 接线：乘员取 `land_units.man_entity`；牵引取 `mounts_tables.entity`；车体取 `battlefield_engines_tables.battle_entity`；关节取 `land_unit_articulated_vehicles_tables.articulated_entity`；各自基础生命取 `battle_entities_tables.hit_points`。本例 `num_engines=4`、`num_mounts=2`、`num_men=8`，四种基础生命均8。
- 依据：项目 `_work/verify-final.cjs` 的 `health()` 与 `_work/final-verification.json`，计算方法参照项目留存的TWW Stats代码。本例旧配置 `bonus_hit_points=692`算得2960，复现项目记录的用户反馈；1652/1352分别算得整队6800/5600，即每车1700/1400。
- **【未验证】**：本次没有进游戏确认新目标或其他部队规模；上述载具公式只作为该结构的计算案例，不推广为所有骑兵、火炮、坦克或复杂乘员组合的引擎通式。
- 验收：先按实际实体链与数量复现已知面板，再检查修改后的新面板和不同部队规模；有独立乘员实体或特殊结构时分别计数，不能仅看 `num_men`。

## 4. 跨文化借用动作：必须登记，否则进战场不能动
表 `culture_to_battle_animation_tables_tables`（列：`battle_animations_table \| culture_pack`）。
- **怎么做**：为每个跨文化借用的动作键新增一行：`battle_animations_table` = `battle_animations_table_tables.key`；`culture_pack` 抄原版同表样例（WH3 样例：`wh2_dlc09_tmb_tomb_kings`、`wh2_dlc09_rogue_eyes_of_the_jungle`）。
- **覆盖范围**：兵种动作（`land_units.man_animation`）、**坐骑动作**（`mounts_tables.animation`）、**火炮/引擎开火动作**（`battlefield_engines_tables.gun_animation_table`）都要登记。
- 验收：进战场后单位能移动/攻击，坐骑能动，炮能开火；漏填表现为原地不动、摆大字（模型不破图）。
- > ⚠️ 坑：只登记兵种动作、漏了坐骑与引擎动作 → 坐骑不动、炮不开火。
- 【待核对】`culture_pack` 的合法取值域（列名像"文化"，实测样例是派系/文化包 key）。核对：在同表 `data__.tsv` 看同动作或同派系原版行。

## 5. 骑乘/战车/火炮：`man_animation` 与 `man_entity` 填「人」不填「载具」
| 单位类型 | `man_animation` | `man_entity` | 载具/坐骑实体去哪改 |
|---|---|---|---|
| 步兵 / 怪步 / 无载人巨兽 | 本人动作 | 本人实体 | — |
| 骑兵（含载人巨兽） | 骑手动作 | 骑手实体 | `mounts_tables.entity` |
| 战车 | 操作者/乘员动作 | 乘员实体 | `land_units.articulated_record` → `land_unit_articulated_vehicles_tables.articulated_entity` |
| 火炮 / 坦克 | 操作者动作 | 操作者实体 | `land_units.engine` → `battlefield_engines_tables.battle_entity` |
| 乘员 / 小队长 | 乘员动作 | 乘员实体 | `battle_personalities_tables.battle_entity` |
- WH2 的 `land_units.officers` 列在 WH3 **已移除**；乘员绑定改走 `land_units_to_battle_personalities_junctions_tables`（列：`battle_personality \| land_unit \| attach \| riders_attachment_point \| engine_articulation_index \| jettison_rider`；WH3 样例 `attach=autonomous_rider`、`riders_attachment_point=ap_riderposition_0`）。
- > ⚠️ 坑：把坐骑/车辆的 entity 填进 `man_entity` → 速度质量按载具算、乘员错位。
- 验收：改速度/质量后，面板与实战表现都变（战车面板速度按 `mounts_tables.entity` 显示，不是 articulated entity）【待核对】。

## 6. `num_mounts`：数量必须与实际匹配
| 类型 | 填法 | 教程例 |
|---|---|---|
| 骑兵 | = 队伍人数 | 小鸡一队 32 人 → 32 |
| 巨兽 | = 巨兽数量 | 三角龙一队 1 只 → 1 |
| 战车 | = 拉车牲畜数 | 狼战车 2 只狼 → 2；大帝车 4 匹马 → 4 |
- > ⚠️ 坑：`num_mounts` 与人数不符 → 无马可骑或多出空坐骑。
- 验收：全队骑手都有坐骑，无多余坐骑。

## 7. 招募建筑：每一级都要登记
表 `building_units_allowed_tables`（列：`key \| building \| unit \| XP \| conditions \| faction \| enabled`）。
- **怎么做**：建筑**逐级独立**。T1 能招 → T1/T2/T3/T4/T5 各写一行；只在 T5 招 → 只写 T5 一行。
- `key` 全局唯一（含其它 MOD），用带前缀的复杂名；`building` = `building_levels_tables` 的等级 key；`unit` = `main_units.unit`。
- > ⚠️ 坑：只填 T1 → 建筑升级后兵种从招募列表消失。
- 验收：把建筑从 T1 升到 T5，每一级都能招募该兵。

## 8. 军事组权限：漏填 = 战役里根本没有这个兵
表 `units_to_groupings_military_permissions_tables`（列：`unit \| military_group`）。
- **怎么做**：按 `factions_tables.military_group` 与 `groupings_military_tables.military_group` 取码；一个种族可能有多个军事组（教程例：帝国 `wh_main_group_empire` 与 `wh_main_group_empire_reikland`），要全派系可用就每个组写一行。
- > ⚠️ 坑：填了招募建筑但漏填本表 → 战役中看不到兵种（教程提到 CA 自己踩过：夜地精被塞进高精城防驻军却未加军事组）。
- 【待核对】`military_group` 的 WH3 取值（教程全是 WH2 代码）。核对：`Select-String -LiteralPath '<VANILLA>\db\factions_tables\data__.tsv' -Pattern 'emp'`。
- 验收：开战役，目标派系招募面板能看到该兵。

## 9. AI 招募：不填 AI 永不招募
表 `cdir_military_generator_unit_qualities_tables`（列：`group_key \| unit_key \| quality`）。
- **怎么做**：`group_key` 抄原版同类（如近战步兵 `Default_land_infantry_melee`【待核对】）；`unit_key` = `main_units.unit`；`quality` 越高 AI 越愿意招。
- 不想让 AI 用 → 故意不填。
- 验收：AI 派系在战役中会自然造出该兵。

## 11. 细节表要点（教程 07）
### 11.1 战斗实体按类型找对代码（`battle_entities_tables`，WH3 58 列）
| 单位类型 | entity 代码来源 |
|---|---|
| 步兵 / 怪步 / 无载人巨兽 | `land_units.man_entity` |
| 骑兵 / 载人巨兽 | `mounts_tables.entity` |
| 战车 | `land_unit_articulated_vehicles_tables.articulated_entity` |
| 火炮 / 坦克 | `battlefield_engines_tables.battle_entity` |
| 乘员 / 小队长 | `battle_personalities_tables.battle_entity` |
- > ⚠️ 坑：改错类型 → 改了没反应。
- 【待核对】面板速度 = `run_speed` / `fly_speed` × 10（教程）。核对：取原版单位，`run_speed` 与游戏内面板对照。
- Mass 影响碰撞与击倒；但**没有击倒动画的单位不会被击倒**，只会中断动作【待核对】。
### 11.2 溅射攻击（`melee_weapons_tables`）
| 列 | 含义 |
|---|---|
| `splash_attack_target_size` | 可被溅射的体型上限（对应 `battle_entities.size`） |
| `splash_attack_max_attacks` | 最多命中几个目标 |
| `splash_attack_power_multiplier` | 击飞物理效果 |
- **动作本身必须支持溅射**，否则怎么填都没效果；溅射范围由动作决定，不可改【待核对】。
- 溅射特效需 `battle_entities.vfx_filter_id` ≥ 1。
### 11.3 弹药池开关（`missile_weapons_tables.use_secondary_ammo_pool`）
- > ⚠️ 坑：主武器误勾 → 即使主武器弹药还在，也会因副弹药为 0 而射不出弹。
- 只有需要主/副弹药切换的武器才勾。教程提到 PFM 把该列显示成 `can_fire_at_buildings`，以 RPFM 列名为准。
### 11.4 多发弹丸三个值（`projectiles_tables`）
| 列 | 含义 | 受动作制约 |
|---|---|---|
| `projectile_number` | 同时发射弹丸数（霰弹） | 不受 |
| `burst_size` + `burst_shot_delay` | 连发弹丸数与间隔（喷火器） | **受** |
| `shots_per_volley` | 多管齐射弹丸数（鼠特林/连环炮） | **受** |
- > ⚠️ 坑：给单发动作的武器填 `burst_size`/`shots_per_volley` → 动作结束后子弹才陆续飞出。
### 11.5 爆炸与破片：子母套娃
链：`projectiles.explosion_type` → `projectiles_explosions.shrapnel` → `projectile_shrapnels.projectile` →（该投射物又可有自己的 `explosion_type`）→ 可多层套。
- 教程实例（**WH3 已核对 5 个 key 全部存在**）：雪崩迫击炮 `wh2_dlc14_skv_poison_wind_mortar_globe_ror` → 爆炸 `wh2_dlc14_skv_poison_wind_mortar_ror` → 破片 `wh2_dlc14_skv_poison_wind_mortar_ror_shrapnel` → 破片投射物 `wh2_dlc14_skv_poison_wind_mortar_globe_ror_shrapnel` → 其爆炸 `wh2_dlc14_skv_poison_wind_mortar_ror_shrapnel`。
- `projectiles_explosions.affects_allies` 不勾 = 爆炸无友伤（但直接碰撞仍有友伤）。
- 验收：发射一次能看到多层爆开；帧率可接受。
### 11.6 乘员绑定：一人一马 vs 多人一马
| 场景 | WH3 做法 |
|---|---|
| 一人一马（小队长/单乘员） | `land_units_to_battle_personalities_junctions_tables` 一行：`battle_personality` = 乘员键，`attach` = `officer`【待核对取值】 |
| 多人一马/多乘员 | 同一 `land_unit` 挂多行，每行一个 `battle_personality` + 不同 `riders_attachment_point` |
- 乘员武器：`battle_personalities.battle_entity_stats` → `battle_entity_stats_tables`（`key \| primary_melee_weapon \| primary_missile_weapon`）。
- > ⚠️ 坑：骑射/车上射手必须用专门的骑乘射击动作，套用步兵动作 → 不攻击。
### 11.7 单位集（`unit_set_to_unit_junctions_tables`）
- 机制：科技/建筑/领主技能树的加成 → `effect` → Unit Set → 使用该 Set 的兵种；同 Set 共享全部加成。
- 列：`unit_caste \| unit_category \| unit_class \| unit_record \| unit_set \| exclude`。
- **怎么做**：复制原版同类兵种所在 Set 的行，`unit_record` 换成你的兵种；要独立加成则在 `unit_sets_tables` 新建 Set。
- 兵牌颜色（紫色精英等）也由 Unit Set 决定（教程例 `wh2_main_ror_units_all`【待核对】）。
- 验收：挂一个作用于该 Set 的 effect，进战役确认新兵种吃到加成。

## 12. 远程命中五要素
