## 0. 一页速览

1. Effect = **三段式**：加成什么（`bonus_value_id`）+ 谁被加成（junction 的目标列）+ 加多少/范围（使用方表的 `value` / `effect_scope`）。
2. junction 表**没有** `value`/`effect_scope` 列，数值与作用域在使用方表（§7）。
3. 59 张 junction 表的**列序有 5 种模式**，必须读表头；能力表与属性表顺序相反（§3.1）。
4. 硬规则：**禁止新增 `unit_attributes`、禁止新增 `intensity_source`**。
5. 数值正负由 `effects_tables.is_positive_value_good` 决定：`false` 时负值才是有益。
6. 写任何 effect 前先查「它有没有 junction 行」——原版表里有 key 但没有 junction 的 effect 是**死键**。
7. 想「删掉」某单位原版自带的被动（受创、不稳定 …）→ 用 §3.4 的 unit_set + `disable` 链，**零覆盖原表**；不要为了删一行去 `data__` 整表覆盖。

## 1. Effect 三段式

| 段 | 回答什么 | 写在哪 | 实例 |
|---|---|---|---|
| 加成什么 | 哪一项数值/开关 | `effects_tables.effect`（效果本体）+ junction 表的 `bonus_value_id`（具体加成项） | `wh_main_effect_character_stat_melee_attack` + `melee_attack_mod` |
| 谁被加成 | 目标集合（Set） | junction 表的目标列：`faction` / `subculture` / `agent` / `subtype` / `building_set` / `unit_set` / `unit_record_key` / `unit_ability` / `unit_attribute` / `special_ability_phase` / `force_ability` … | `effect_bonus_value_ids_unit_sets_tables.unit_set = infantry_units_melee` |
| 加多少 / 范围 | 数值 + 生效层级 | **使用方表**的 `value` + `effect_scope`（§7）；bundle 也是使用方之一（§2） | `ancillary_to_effects_tables`：`character_to_character_own` + `40.0000` |

**怎么做**：先定「加成什么」→ 选 junction 表定「谁」→ 在载体表（装备/建筑/科技/技能树/难度）填 `value` 与 `effect_scope`。
**验收**：该 effect 在「谁」的 junction 表里有行；在载体表里有 `value` + `effect_scope`；两处 `effect` 键一致。

## 2. 三张主表（列序实测）

| 表 | 列序 | 作用 |
|---|---|---|
| `effects_tables` | `effect` `icon` `priority` `icon_negative` `category` `is_positive_value_good` | 效果注册：主键、图标、UI 排序、分类（`campaign`/`battle`/`both`）、正负含义 |
| `effect_bundles_tables` | `key` `localised_description` `localised_title` `bundle_target` `priority` `ui_icon` `is_global_effect` `show_in_3d_space` `owner_only` | 效果集注册：把多个 effect 打包给战旗/祭仪/派系特性等 |
| `effect_bundles_to_effects_junctions_tables` | `effect_bundle_key` `effect_key` `effect_scope` `value` `advancement_stage` | bundle ↔ effect 绑定，**自带 scope 与 value** |

- `advancement_stage` 多数填 `start_turn_completed`；不确定时抄原版同类 bundle。
- 名称/说明走 loc：`effect_bundles_localised_title_<key>` / `effect_bundles_localised_description_<key>`。
- Lua 动态 bundle 仍需在 `effect_bundles_tables` 预注册（`key` 列有行即可）。
- **验收**：`bundle` 有 `key` 行；每条 effect 在本 junction 有行且 scope/value 正确；loc 两键齐全。

## 3. bonus_value junction 家族：什么时候用哪张

### 3.1 列序陷阱（先读这节，再抄任何一行）

> ⚠️ 坑：照抄另一张 junction 表的列序 → 列错位 → `effect` 被写进目标列、目标键被写进 `bonus_value_id` → 效果静默失效或引用报错（不崩溃，最难查）。

**实测两种相反顺序**：

| junction 表 | 列序（实测表头） |
|---|---|
| `effect_bonus_value_unit_ability_junctions_tables`（能力） | `effect` \| `bonus_value_id` \| `unit_ability` |
| `effect_bonus_value_unit_attribute_junctions_tables`（属性） | `bonus_value_id` \| `effect` \| `unit_attribute` |

**列序共有 5 种模式**（全部实测）：

| 模式 | 表（举例） |
|---|---|
| `effect` \| `bonus_value_id` \| `<目标>` | `unit_ability`、`agent_junction`、`building_chain`、`resource_junction`；`basic_junction` 只有前两列 |
| `bonus_value_id` \| `effect` \| `<目标>` | 多数表：`unit_attribute`、`special_ability_phase_record`、`military_force_ability`、`unit_record`、`faction`、`subculture`、`agent_subtype`、`stance`、`unit_set_*` … |
| `bonus_value_id` \| `<目标>` \| `effect` | `building_set`、`diplomacy_manipulation_category`、`unit_list` |
| `<目标>` \| `bonus_value_id` \| `effect` | `armory_item_category`、`attrition_record`、`recruitment_source`（列名是 `bonus_value`，无 `_id`） |
| `bonus_value_id` \| `effect_key` \| `<目标>` | `battle_context_junctions`、`battle_context_unit_ability`（列名是 `effect_key`） |

**怎么做**：写任何 junction 行之前，先执行
`Get-Content '<VANILLA>\db\<表名>\data__.tsv' -TotalCount 1` 读表头，按表头顺序落列。
**验收**：把写好的行按 `\t` 拆开，列数与表头列数相同、每列语义与表头一致；再随机抽一行原版同表行对照。

### 3.2 按需求选表

| 需求 | 用哪张 junction | 目标列 | `bonus_value_id` 常用值 |
|---|---|---|---|
| 通用加成，不限对象 | `effect_bonus_value_basic_junction_tables` | 无 | 随 effect 而定 |
| 限定兵种集合（含兵种类别/经验档） | `effect_bonus_value_ids_unit_sets_tables` | `unit_set` | `melee_attack_mod`、`armour_mod`、`charge_add`、`upkeep_mod`、`ammo_mod`、`unit_cap` … |
| 限定单个兵种 | `effect_bonus_value_unit_record_junctions_tables` | `unit_record_key` | 同上 |
| 启用/禁用单位技能、改冷却魔耗次数 | `effect_bonus_value_unit_ability_junctions_tables` | `unit_ability` | `enable`、`disable`、`recharge_mod`、`cost_mod`、`uses_mod`、`active_time_mod`、`miscast_percentage_mod`、`enable_overchage` … |
| 军队技能 | `effect_bonus_value_military_force_ability_junctions_tables` | `force_ability` | `enable`、`disable`、`use_mod` |
| 启用属性（attribute） | `effect_bonus_value_unit_attribute_junctions_tables` | `unit_attribute` | `enable` |
| 启用攻击附魔相位 | `effect_bonus_value_special_ability_phase_record_junctions_tables` | `special_ability_phase` | `active` |
| 只给某个兵种组技能/属性/相位 | `effect_bonus_value_unit_set_unit_ability_junctions_tables` / `…_unit_attribute_junctions_tables` / `…_special_ability_phase_junctions_tables` | `unit_set_ability` / `unit_set_attribute` / `unit_set_special_ability_phase_junction` | `enable` / `enable` / `active` |
| 派系 / 子文化（外交等） | `effect_bonus_value_faction_junctions_tables` / `…_subculture_junctions_tables` | `faction` / `subculture` | `diplomatic_mod` |
| 事务官大分类 / 子分类 | `effect_bonus_value_agent_junction_tables` / `…_agent_subtype_junctions_tables` | `agent` / `subtype` | `cap`、`availability`、`success_mod`、`action_cost_mod`、`recruit_cost_mod` … |
| 建筑组 / 建筑链 | `effect_bonus_value_building_set_junctions_tables` / `…_building_chain_junctions_tables` | `building_set` / `building_chain` | `add_build_time`、`mod_cost`、`mod_gdp` |
| 特定战场/敌人 | `effect_bonus_value_battle_context_*_junctions_tables` | `battle_context_key` | — |
| 替换远程武器（改弹药） | `effect_bonus_value_missile_weapon_junctions_tables` | `missile_weapon_junction`（I32，指 `unit_missile_weapon_junctions_tables.id`） | `enable` |
| 池资源 / 仪式 / 瘟疫 / 攻城器械 / 姿态 / 学派组 | 各 `effect_bonus_value_<域>_junctions_tables` | 见 §8 命令 | 抄原版同表行 |

**两条实测结论（不要照抄教程 11 的表名）**：

- WH3 原文件里**没有** `effect_bonus_value_character_*` 目标为角色的 junction；「角色本人/其军队」用 `effect_scope` + 使用方表 `character_skill_level_to_effects_junctions_tables` 实现。

**验收**：`Get-ChildItem '<VANILLA>\db' -Directory -Filter 'effect_bonus_value*'` 里能搜到你写的表名；目标键在同域主表（如 `unit_sets_tables`）中存在。

### 3.3 unit_set 限定链（自定义「只给某组单位」的标准做法）

```
① effects_tables                新增自定义 effect（如 wh_my_effect_enable_melee_frenzy）
② effect_bonus_value_unit_set_unit_ability_junctions_tables
                                bonus_value_id=enable | effect | unit_set_ability=组键
③ unit_set_unit_ability_junctions_tables
                                key=组键 | unit_ability=技能键 | unit_set=melee_units
④ 组键：用原版 unit_sets_tables 键，或自建行 + unit_set_to_unit_junctions_tables 指定成员
```

同型变体：`…_unit_attribute_…`（限属性）、`…_special_ability_phase_…`（限相位，`bonus_value_id=active`）。

- 可直接用的原版组键（实测存在）：`all_units`、`all_units_rank_0_to_3`、`all_units_excluding_flying`、`all_land_units`、`all_land_artillery`、`melee_units`、`missile_units`、`cavalry_units`、`artillery_units`、`infantry_units_melee`、`infantry_units_missile`、`infantry_monstrous` …
- 注意 `wh_main_infantry_melee`（WH2 老键）不存在，近战步兵用 `infantry_units_melee`。

> ⚠️ 坑：靠改自定义 effect 键名自造限定（如 `wh_my_effect_force_stat_melee_attack_my_units`）→ 引擎不认，加成不生效。限定只能走 unit_set 链或引用原版自带限定的键。

### 3.4 屏蔽/移除某组单位「已有」的能力（`disable` 方向）

**用途**：想删掉某单位原版自带的被动（`受创`、`不稳定`、`约束衰减`、`狂暴` …），但该能力写在几千行的 `land_units_to_unit_abilites_junctions_tables` 里 —— 删行必须用 `data__` **整表覆盖**（兼容性极差）。改用下面这条链可以**零覆盖原表**达成。

| 步 | 表 | 写什么（字段间用 `·` 分隔） |
|---|---|---|
| ① | `unit_sets_tables` | 自建组键：`组键 · false · -1 · -1 ·（空）` |
| ② | `unit_set_to_unit_junctions_tables` | 成员：`（空）·（空）·（空）· land_unit 键 · 组键 · false`（列序见 12 册 §8） |
| ③ | `unit_set_unit_ability_junctions_tables` | `关联键 · unit_ability 能力键 · 组键` |
| ④ | `effect_bonus_value_unit_set_unit_ability_junctions_tables` | `disable · 自定义 effect · 关联键`（**引用的是 ③ 的 key，不是组键**） |
| ⑤ | `effects_tables` | 新建 effect，**必须独立**（见坑 1） |

**关键语义：`disable` 与该能力的来源无关。** 原版恐蜥的 `受创` **同时**存在于 `land_units_to_unit_abilites_junctions_tables`（恐蜥 3 行）和 unit_set 关联里，而 CA 的科技只 `disable` 了 unit_set 那条就实现了「移除恐蜥受创」（`wh3_main_effect_attribute_disable_wounds_dread_saurians_rank7`）—— 若 `disable` 只作用于该条关联，那个科技就是废的。**结论：只要单位属于该 unit_set，它的该能力一律被屏蔽。**

**坑 1（必须自建独立 effect）**：不要复用原版已有的 `wh3_main_effect_attribute_disable_wounds` —— 它在 `effect_bonus_value_unit_ability_junctions_tables` 里挂着一条**不带单位限定**的全局 `disable` 关联，一旦施加，**该派系全部单体单位**都会失去受创（参考 MOD 里"作用全派系所有兵种"的效果就是这么来的）。自建 effect 才只有你写的 unit_set 限定。

**坑 2（生效范围由施加渠道决定）**：同一条链，换载体就换范围 ——
- `campaign_difficulty_handicap_effects_tables`（`human=true` + 难度 `-3`~`3` 七档全填 + `faction_to_force_own_unseen`）= **只对玩家派系的该组单位**
- `technology_effects_junction_tables` = 研究了该科技的派系（恐蜥就是这个渠道）
- `character_skill_level_to_effects_junctions_tables` = 该角色的军队（原版古墓王「安息长眠」`wh3_main_skill_tmb_never_say_die` 即此，scope `character_to_character_own`）

**坑 3（测试环境）**：走难度表的效果**只在战役生效，自定义战斗不生效** —— 别在自定义战斗里测出"没效果"就推翻方案；且 AI 单位的同一能力**不会**被移除（这正是"只作用玩家派系"的预期表现）。

> 实测案例（2026-09-15，`su_tiandeng`）：移除玩家震旦天灯 `wh3_main_cth_veh_sky_lantern_0` 的 `受创`（= `wh3_main_unit_passive_single_entity`）。6 张表（①~⑤ + 难度表）全部用非 `data__` 文件名追加，1 条 loc；`modcheck` 0 错 0 警；游戏内确认生效。

## 4. effect_scope：同一 Effect 换 Scope 决定谁受益

`campaign_effect_scopes_tables`（540 行）结构：`key` = `<source>_to_<target>_<ownership>_<location>`，五列 `location` `ownership` `source` `target` `territory`。

| scope | location | ownership | source | target | 受益者 |
|---|---|---|---|---|---|
| `character_to_character_own` | `character` | `yours` | `character` | `character` | 装备/技能持有者本人 |
| `character_to_character_own_banner` | `character` | `yours` | `character` | `character` | 方旗携带单位（方旗专属） |
| `character_to_force_own` | `forcewide` | `yours` | `character` | `force` | 持有者所在军队（可见文本） |
| `character_to_force_own_unseen` | `forcewide` | `yours` | `character` | `force` | 同上但隐藏文本 |
| `character_to_faction_unseen` | `factionwide` | `yours` | `character` | `faction` | 持有者所属派系（科研、外交） |
| `character_to_province_any` | `provincewide` | `any` | `character` | `province` | 角色所在行省（公共秩序） |
| `faction_to_faction_own_unseen` | `factionwide` | `yours` | `faction` | `faction` | 派系全局（收入、招募费） |
| `faction_to_province_own_unseen` | `factionwide` | `yours` | `faction` | `province` | 自有行省 |
| `faction_to_force_own_unseen` | `factionwide` | `yours` | `faction` | `force` | 自有军队（维持费、补员） |
| `force_to_force_own` | `forcewide` | `yours` | `force` | `force` | 军队级技能启用 |
| `province_to_region_own_factionwide` | `factionwide` | `yours` | `province` | `region` | 建筑效果 |
| `region_to_force_own_factionwide` | `factionwide` | `yours` | `region` | `force` | 区域 → 全派系军队 |

**同一 effect 换 scope 的效果**（原版 `wh_main_effect_character_stat_armour`）：`character_to_character_own` = 只给角色本人护甲；`character_to_force_own` = 给整支军队；`character_to_character_own_banner` = 只给方旗携带单位。
**怎么做**：先定「谁受益」，再选 scope；scope 名字拆开读就是答案。
**验收**：`Select-String -Path '...\campaign_effect_scopes_tables\data__.tsv' -Pattern '^<scope>\t'` 有结果。

## 5. 数值与算法

| 场景 | 怎么写 | 实例 |
|---|---|---|
| 加算增益 | `add` + 正数 | `stat_melee_attack` `add` `10` = +10 |
| 加算减益 | `add` + 负数 | `stat_armour` `add` `-30` = -30 护甲 |
| 乘算增益 | `mult` + 大于 1 | `scalar_speed` `mult` `2` = +100%（UI 显示） |
| 乘算减益 | `mult` + 小于 1 | `scalar_speed` `mult` `0.7` = -30% |
| 属性型 effect | `value` 直接写数值 | `wh_main_effect_character_stat_armour` → `40.0000` = +40 |
| 百分比型 effect | `value` 写百分数 | `wh_main_effect_technology_research_points` → `15.0000` = +15% |
| 启用/禁用型 | `value = 1` | `wh_main_effect_ability_enable_red_fury` → `1.0000` |

**`is_positive_value_good` 规则**：

- `true`：正值有益（收入、发展、科研、领导力）→ 加益写正数。
- `false`：负值有益（维持费、招募费、建筑时间、装填时间、体力损耗）→ 减益写负数。UI 颜色随该字段变化。
- 减少维持费 30% → `-30`；减少建筑时间 1 回合 → `-1`；体力损耗减免 → `-20`。

**两个易错细节**：

- 键名自带「减少」的键（`…_reload_time_reduction`、`…_vigour_loss_reduction`）填负值才是加快/减少。
- 非破甲与破甲伤害**各写一行**（`stat_melee_damage_base` / `stat_melee_damage_ap`）。
- 【B】`stat_resistance_flame` 减抗最多减到 0，要压到负抗用 `stat_weakness_flame`（来源：教程 08 评论区实测，WH3 未复核）。

**验收**：`value` 正负与 `effects_tables.is_positive_value_good` 一致；游戏内显示为预期绿/红字；面板数值变化等于填写值。

## 6. 效果文本

| 内容 | loc 键 | 写法 |
|---|---|---|
| 效果显示行 | `effects_description_<effect>` | `近战攻击：%n` |
| 比率型效果 | `effects_description_<effect>` | `武器威力：%n%`（末尾加 `%`） |
| 限定对象的效果 | 同上 | 自己写清限定：`近战攻击：奴隶鼠部队%n` |
| 效果集名称/说明 | `effect_bundles_localised_title_<key>` / `effect_bundles_localised_description_<key>` | 名称 / 说明 |

- `%n` 是数值占位符，由引擎替换为 `value`；文本与实际数值**无强绑定**，必须自己写对。
- 描述字段只写背景文案，**不得罗列机械效果**（数值、次数、冷却、范围、触发条件）。
- 效果图标：`effects_tables.icon`/`icon_negative` 填图名（含 `.png`），路径在 `ui\campaign ui\effect_bundles\`【未验证：作者环境未导出该目录】。
- **验收**：`effects_description_<effect>` 在 `localisation__.loc.tsv` 可查到；游戏内文案与数值正确。

## 7. 五张「使用方表」（value + scope 写在这里）

| 表 | 列序（实测） | 用途 |
|---|---|---|
| `ancillary_to_effects_tables` | `ancillary` `effect` `effect_scope` `value` | 装备/随从/方旗提供的加成 |
| `building_effects_junction_tables` | `building` `effect` `context_requirement` `effect_scope` `value` `value_damaged` `value_ruined` | 建筑加成（含受损/毁坏时不同值） |
| `campaign_difficulty_handicap_effects_tables` | `campaign_difficulty_handicap` `human` `effect` `optional_campaign_key` `effect_scope` `effect_value` | 难度档位加成（列名是 `effect_value`，不是 `value`） |
| `character_skill_level_to_effects_junctions_tables` | `character_skill_key` `effect_key` `level` `effect_scope` `value` | 角色技能树每级效果（列名是 `effect_key`） |
| `technology_effects_junction_tables` | `technology` `effect` `effect_scope` `value` | 科技加成 |

- `campaign_difficulty_handicap_effects_tables.human`：`true` = 人类玩家、`false` = AI；难度档 `-3`~`3` **七档都要填**，漏档则那个难度下该效果不存在。

第六种使用方：`effect_bundles_to_effects_junctions_tables`（§2）。
**怎么做**：junction 表定好「谁」后，到对应载体表加一行，填 `effect` + `effect_scope` + `value`。
**验收**：同一 `effect` 键在 junction 表与使用方表中拼写完全一致。

## 9. 硬规则与坑

1. **禁止新增 `unit_attributes`**：只能引用原版已有枚举（**83** 条，查 `unit_attributes_tables`；实测 85 行 − 列名 − 元数据行）。新增键引擎不识别，属性静默失效。
2. **禁止新增 `intensity_source`**：只能用 `special_ability_intensity_sources_tables` 的 26 条枚举（见 `26-技能后端与效果出口.md` §3）。
3. **不新增 `category` / `subcategory` / `unit_set` 特殊类别**；限定走 §3.3 的 unit_set 链或原版限定键。
4. **junction 列序必须读表头**（§3.1），五套顺序。
5. **junction 表没有 `value` / `effect_scope`**；数值与范围写在使用方表（§7）。
6. **自定义 effect 必须在 `effects_tables` 注册**，且该键在引擎内有对应逻辑；纯属性加成优先直接引用原版 effect 键，不要自造。
7. **原版有 key 但没有 junction 行的 effect 是死键**（实测例：`wh3_dlc27_effect_attribute_enable_glorious_charge_all_units`、`wh3_dlc27_effect_ability_enable_frenzy_all`）。用前跑 §8 命令 ④。
8. **数字主键 ≤ 2,147,483,647**（I32），并用 MOD 专属号段；覆盖原版行要**抄整行**，只改目标列。
9. **中文名/说明必须补 loc**，否则显示为空或键名原文。
10. **用 `disable` 屏蔽某 unit_set 的能力时必须自建独立 effect**：复用原版已挂全局关联的键（如 `wh3_main_effect_attribute_disable_wounds`）会连带把该能力对所有单位禁用（§3.4 坑 1）。

> ⚠️ 坑：把教程 11 的 `effect_bonus_value_religion_junction_tables`、`effect_bonus_value_building_set_junctions_tables` 列序照抄 → 前者 WH3 不存在（引用报错），后者实际列序是 `bonus_value_id | building_set | effect`（目标在中间），照抄必错位。
