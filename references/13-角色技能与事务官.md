## 1. 技能树数据流（WH3 现行）

```
character_skills_tables                       技能定义（图标 / 背景特性 / 影响力）
  ├─ character_skill_nodes_tables             节点（indent/tier/visible_in_ui/点数）
  │    ├─ character_skill_node_links_tables   父子串联 REQUIRED / SUBSET_REQUIRED
  │    └─ character_skill_node_set_items_tables  ★WH3：节点 ↔ 技能树的唯一绑定处
  ├─ character_skill_node_sets_tables         技能树（agent_key + agent_subtype_key 决定谁看到）
  ├─ character_skill_level_details_tables     每级解锁等级 unlocked_at_rank
  ├─ character_skill_level_to_effects_junctions_tables   每级 → effect + scope + value
  ├─ character_skill_level_to_ancillaries_junctions_tables 每级 → 装备
  ├─ character_skills_to_quest_ancillaries_tables        技能 → 神器任务
  └─ character_skill_categories_tables        技能线颜色（col_hex）
```

**怎么做**：新建技能树按上表自下而上落地——先 `character_skills_tables` 注册技能 key，再 `character_skill_nodes_tables` 建节点，再 `character_skill_node_set_items_tables` 把节点挂进树，最后补 level_details / level_to_effects。
**验收**：任意节点 key 在 `set_items` 里能反查到 `set`；该 `set` 在 `node_sets` 里能查到目标 `agent_subtype_key`。

## 2. 表与字段清单（列名按 WH3 实测顺序）

### 2.1 `character_skills_tables`（版本 5，5,946 行）

| 列 | 填法 |
|---|---|
| `key` | 技能 key，主键，MOD 专属前缀 |
| `image_path` | **只填文件名**（含 `.png`），如 `wh_main_spell_fire_fireball.png`；目录固定见 §8 |
| `localised_description` / `localised_name` | 留空即可，显示文本靠 loc（见 §8、`50-本地化与翻译.md`） |
| `unlocked_at_rank` | 原版 4,831/5,946 行填 0；解锁实际由 `character_skill_level_details_tables` 决定（§4） |
| `is_background_skill` | 背景特性（角色特性）勾选；普通技能不勾 |
| `is_female_only_background_skill` / `is_male_only_background_skill` | 特性性别限定 |
| `background_weighting` | 特性权重填 >0（原版多为 `0.0000` 之外的数值）；普通技能填 0 |
| `influence_cost` | 影响力花费（高精特性类），普通技能 0 |

**验收**：`grep` 技能 key 在 `nodes`、`level_details`、`level_to_effects` 中均有对应行，无悬空。

### 2.2 `character_skill_nodes_tables`（版本 6，24,651 行）

| 列 | 填法 |
|---|---|
| `key` | 节点 key，主键（≠技能 key） |
| `campaign_key` / `faction_key` / `subculture` | 原版基本留空；填了即限定该战役/派系/子文化才可见 |
| `character_skill_key` | → `character_skills_tables.key` |
| `indent` | 行（技能线位置），见 §6 与 §9 |
| `tier` | 列，最左 0，向右递增 |
| `points_on_creation` | 建角色时已投入的点数。装备/坐骑技能填 1 只让面板显示为已点，**不会真的发放装备**（发放见 `character_skill_level_to_ancillaries_junctions_tables`） |
| `required_num_parents` | 需要的前置节点数 |
| `visible_in_ui` | 是否在技能面板显示，见 §9 |

> ⚠️ 坑：本表**没有** `character_skill_node_set_key` 列（WH3 实测 10 列）→ 填了也无处可填，节点挂不上技能树，游戏里技能面板空白。绑定改到 `character_skill_node_set_items_tables`（§3）。

### 2.3 `character_skill_node_sets_tables`（版本 0，549 行）

列：`key`、`agent_key`、`for_army`、`faction_key`、`for_navy`、`campaign_key`、`subculture`、`agent_subtype_key`。

| 列 | 填法 |
|---|---|
| `key` | 技能树 key |
| `agent_key` | Agent 大分类（`general`/`wizard`/`champion`…），与 `agent_culture_details_tables.agent` 同值域 |
| `agent_subtype_key` | → `agent_subtypes_tables.key`，**决定谁看到这棵树** |
| `for_army` / `for_navy` | 原版均 false |
| `faction_key` / `campaign_key` / `subculture` | 原版基本留空，填了即限定 |

**验收**：新角色的技能树行 `agent_subtype_key` 等于该角色 `agent_subtypes_tables.key`，且 `agent_key` 与 `agent_culture_details_tables` 中该 Agent 的登记一致。

### 2.4 `character_skill_node_set_items_tables`（版本 0，29,519 行）

三列，无主键约束，**一对一行**：

| 列 | 填法 |
|---|---|
| `set` | 技能树 key → `character_skill_node_sets_tables.key` |
| `item` | 节点 key → `character_skill_nodes_tables.key` |
| `mod_disabled` | 填 `false`（不勾） |

原版样例：`wh2_dlc09_skill_node_set_skv_tretch_craventail` → `wh2_dlc09_skill_innate_skv_tretch_craventail` / `..._army_0` / `..._army_1_1` …

**验收**：该角色技能树下的每个节点都有一行；游戏内面板显示的技能数量 = 本表该 `set` 的行数。

### 2.5 `character_skill_node_links_tables`（版本 3，20,592 行）

列：`child_key`、`parent_key`、`initial_descent_tiers`、`parent_link_position`、`child_link_position`、`parent_link_position_offset`、`child_link_position_offset`、`link_type`。

| 列 | 填法 |
|---|---|
| `parent_key` / `child_key` | 均为 `character_skill_nodes_tables.key` |
| `link_type` | `REQUIRED`（单父）／`SUBSET_REQUIRED`（一组父），实测值域仅此两种（10,470 / 10,120） |
| `initial_descent_tiers` | 原版 0 |
| `parent_link_position` / `child_link_position` | 原版填 1 |
| `parent_link_position_offset` / `child_link_position_offset` | 原版填 0 |

**怎么做**：一条技能线的相邻节点各写一行；有多个前置时，为每个前置各写一行且 `link_type=SUBSET_REQUIRED`。
**验收**：除线首节点外，每个节点都有 ≥1 行 `child_key` 命中它；`link_type` 只有上述两值。

### 2.6 `character_skill_level_details_tables`（版本 1，2,102 行）

列：`campaign_key`、`faction_key`、`level`、`skill_key`、`subculture_key`、`image_path`、`unlocked_at_rank`。

| 列 | 填法 |
|---|---|
| `skill_key` | → `character_skills_tables.key` |
| `level` | 技能等级（1、2、3…），**每级一行** |
| `unlocked_at_rank` | 解锁所需角色等级（见 §9 的"少 1"规则） |
| `image_path` | 原版统一填 `x`（占位，不生效） |
| `campaign_key` / `faction_key` / `subculture_key` | 原版留空 |

**验收**：某技能有 N 级，本表就有 N 行；每行的 `unlocked_at_rank` 单调不降。

### 2.7 `character_skill_level_to_effects_junctions_tables`（版本 1，16,846 行）

列：`character_skill_key`、`effect_key`、`level`、`effect_scope`、`value`。

| 列 | 填法 |
|---|---|
| `character_skill_key` | → `character_skills_tables.key` |
| `effect_key` | → `effects_tables.effect`（效果语义见 `11-效果系统.md`） |
| `level` | 技能等级，**每一级都要有行**（§4） |
| `effect_scope` | 作用域 → `campaign_effect_scopes_tables.key`，随军效果见 §9 |
| `value` | 数值 |

### 2.8 其余技能表

| 表 | 列 | 用途 |
|---|---|---|
| `character_skill_level_to_ancillaries_junctions_tables`（740 行） | `granted_ancillary`、`skill`、`level` | 学到某级发放装备（`level` 必须有值，见 §9） |
| `character_skills_to_quest_ancillaries_tables`（15 行） | `ancillary`、`skill`、`use_quest_for_prefix` | 技能关联神器任务；仅为面板显示装备数据，任务本体需脚本 |
| `character_skill_nodes_skill_locks_tables`（2,548 行） | `character_skill`、`character_skill_node`、`level` | 学会某技能到某级后**锁定**指定节点（注意：第 1 列是技能、第 2 列才是被锁节点） |
| `character_skill_node_ancillary_locks_tables`（8 行） | `ancillary_lock`、`character_skill_node` | 需持有某装备才解锁该节点 |

> ⚠️ 坑：把 `character_skill_nodes_skill_locks_tables` 两列写反（以为先节点后技能）→ 锁错节点，技能线整段点不开。

## 3. WH3 变化：节点与技能树的绑定（必须照此做）

**结论**：节点归属技能树，只写在 `character_skill_node_set_items_tables`；`character_skill_nodes_tables` 不再承载该关系。

- 依据：实测 `character_skill_nodes_tables` 列 = `key, campaign_key, character_skill_key, faction_key, indent, tier, subculture, points_on_creation, required_num_parents, visible_in_ui`（无 node_set 列）；`character_skill_node_set_items_tables` = `set, item, mod_disabled`。
- 怎么做：每新增一个节点，就在 `set_items` 追加一行（`set`=该角色技能树、`item`=节点 key、`mod_disabled=false`）。
- 验收：游戏内该角色技能面板能显示全部节点且可正常点亮；若整棵树空白，先查本表是否漏行。


## 4. 技能等级效果：每一级都要填

**结论**：一个技能有几级，`character_skill_level_to_effects_junctions_tables` 就要为**每一级**写行；只写 `level=1`，2、3 级就没有任何效果。

- 依据：原版 `wh_main_skill_all_magic_fire_01_fireball` 实测——`level=1` 2 行（overcast、cooldown −30）、`level=2` 5 行（miscast −15、overcast、wom_cost −1/−2、cooldown −50）。
- 怎么做：按级数逐级复制行、只改 `level` 与 `value`；同一效果跨级存在时，每级各写一行。
- 验收：`grep "<skill_key>\t"` 的结果中 `level` 覆盖 1..N，无缺级。

> ⚠️ 坑：只填 Level 1 就以为"效果随等级自动叠加" → 技能点到 2、3 级毫无加成，面板效果栏空。

## 5. 串联规则：REQUIRED 与 SUBSET_REQUIRED

**结论**：`link_type=REQUIRED` 用于只有一个父节点的连接；`link_type=SUBSET_REQUIRED` 用于"需要满足一组父节点中的若干"的连接。

- 依据：`character_skill_node_links_tables.link_type` 实测值域仅 `REQUIRED`(10,470) / `SUBSET_REQUIRED`(10,120)。
- 怎么做：① 画出技能线草图（节点 key + indent/tier）→ ② 相邻节点写 link 行 → ③ 多前置的节点，每个前置一行、全部标 `SUBSET_REQUIRED` → ④ 线首节点不写 link。
- 验收：面板上技能线连贯、前置未点满时后续节点灰显。

## 6. 技能线颜色（`character_skill_categories_tables`，44 行）

列：`key`、`max_indent`、`min_indent`、`order`、`agent_subtype_override`、`col_hex`。

| 列 | 填法 |
|---|---|
| `min_indent` / `max_indent` | 应用的行范围（如 0~3 个人线、4 红线、5 蓝线） |
| `order` | 排序，原版个人线 0 / 红线 1 / 蓝线 2 |
| `agent_subtype_override` | 仅对该 Agent Subtype 生效；留空=通用 |
| `col_hex` | **六位十六进制颜色（无 `#`）**，实测样例 `F1413D`（红线）、`43DDF8`（蓝线） |

> ⚠️ 坑：照教程 15 找 `Col R` / `Col G` / `Col B` 三列 → WH3 只有一列 `col_hex`；填三列会列错位。

### 7.3 派系许可（不填就无法招募）

**结论**：`faction_agent_permitted_subtypes_tables` 必须为每个可招募该 subtype 的派系逐行登记，缺行则该派系无法招募。

- 依据：原版样例 `colonel | wh2_dlc09_rogue_black_creek_raiders | wh2_main_def_dreadlord | false`。
- 怎么做：照抄目标 MOD 现有同文化角色在该表的全部行，替换 `subtype`。
- 验收：`grep "<subtype>" faction_agent_permitted_subtypes_tables` 的行数 = 该文化应招募它的派系数。

> ⚠️ 坑：只在 `effect_bonus_value_agent_subtype_junctions_tables` 给 `availability`/`cap` → Agent 未解锁，仍招募不了；招募许可与容量必须同时关联 Agent 与 Subtype（教程 20，B 级）。

## 8. 技能图标路径与字段

- 目录：`ui\campaign ui\skills\`（pack 内路径；同级结构见 `<REFERENCE>\Just More Items\ui\campaign ui\`）。
- `character_skills_tables.image_path` **只写文件名**（实测原版值如 `wh_main_spell_fire_fireball.png`、`character_attack.png`），不写目录。
- `character_skill_level_details_tables.image_path` 原版统一填 `x`（占位）。
- **角色技能图标尺寸与单位能力（ability）图标不同**，不要互相挪用；尺寸、抠图与生成脚本见 `31-技能图标.md`。
- 本地化键：`character_skills_localised_name_<skill_key>` / `character_skills_localised_description_<skill_key>`（键命名规范见 `50-本地化与翻译.md`）。

**验收**：pack 内 `ui\campaign ui\skills\<image_path>` 文件存在且尺寸符合 `31` 册；面板无空图标。

## 9. 硬坑（教程 15/20 结论 + 实测校正）

| # | 规则 | 怎么做 / 验收 |
|---|---|---|
| 1 | `indent` 0~5 必须勾 `visible_in_ui`，6~8 不勾 | 实测：0~5 共 19,366 行几乎全 true（false 344 行）；6 有 5,008 false / 5 true；8 全 false。另有极少数 9~12/20/90/98/99。验收：勾错会"技能树看不到"或"面板多出幽灵节点" |
| 2 | 技能点消耗（`required_num_parents`）与解锁等级（`level_details`）**只生效一个** | B 级教程结论。一个节点只用一种限制。验收：设了两处时以游戏内表现为准并只留一处 |
| 3 | **随军给所在军队加成（移动力等）的正规通道是「英雄行动」，不是技能里的 effect** | 实测（2026-09-20，su_zdxn 拉克里玛『异世陌客』）：① 技能里直接写 `wh_main_effect_agent_movement_range_mod`（`character_to_character_own` / `agent_to_parent_army_own` / `agent_to_parent_army_general_own` 三种 scope 都试过）或换成 `wh_main_effect_force_all_campaign_movement_range` + `agent_to_parent_army_own`，**军队移动力都毫无变化**（玩家实机实测三次无效）。② 真正生效的是原版 **agent action**：`agent_actions_tables` 里 `agent = spy` 的 `wh2_main_agent_action_spy_assist_army_increase_mobility`（UI 名 `{{tr:agent_action_name_increase_mobility}}`，中文「增加行动力」，描述：使所在军队战略地图移动距离 +%n%），**但默认不解锁** —— 必须由 `active` 绑定（见 `effect_bonus_value_agent_action_record_junctions_tables`）对应的 `wh2_main_effect_agent_action_enable_spy_assist_army_**enhance**_mobility` 打开，通常挂在角色的隐藏 dummy 技能上（原版：`wh2_main_skill_all_dummy_agent_actions_vmp_banshee`、`wh3_main_skill_all_dummy_agent_actions_ogr_hunter`）。③ 行动的 %n% 数值另由 `wh2_main_effect_agent_action_assist_army_increase_mobility_buff` 提供（原版 `wh2_main_skill_all_hero_assist_army_increase_mobility` = 5/10/15%，scope `character_to_character_own`）。⚠️ **命名坑**：行动 record 叫 `increase_mobility`，解锁它的 enable effect 叫 `enhance_mobility`，两个词不一样；同名家族还有 `assist_army_training`（军事训练，enable + `..._training_buff`）、`replenish_troops`、`scavenge`。附 scope 语义备查：`campaign_effect_scopes_tables` 中 `agent_to_parent_army_general_own` → target=`character_when_commanding`、`agent_to_parent_army_own` → target=`force`、`character_to_force_own` → target=`force` |
| 4 | 获得装备的技能必须有等级限制 | B 级教程结论：不设限制时技能显示"已使用"无法点选。在 `character_skill_level_details_tables` 给该技能加行 |
| 5 | `unlocked_at_rank` 数值 = 游戏内解锁等级 **−1** | B 级教程结论（游戏内 10 级解锁 → 填 9）；WH3 未逐条复验【未验证】。验收：进游戏看技能灰显等级 |
| 6 | `character_skills_tables.unlocked_at_rank` 无实际作用 | 实测 4,831/5,946 行填 0；解锁以 `level_details` 为准【未验证：WH3 是否仍忽略该列】 |
| 7 | `indent=8` 的事务官行动节点，其 Agent 类型必须与本事务官相同 | 实测 `indent=8` 样例均为 `*_campaign_actions_dummy` 技能且 `visible_in_ui=false`。怎么做：从原版同 `agent` 类型的事务官中取行动节点；跨 Agent 类型套用不生效 |
| 8 | 技能线颜色只有一列 `col_hex` | 见 §6 |
| 9 | 装备/坐骑技能"面板显示已点"≠"已发放" | `points_on_creation=1` 只改显示；发放靠 `character_skill_level_to_ancillaries_junctions` |
| 10 | 装备技能"效果栏空白" | 该技能绑定的 unlock effect 缺 `effects_description_<effect_key>` loc；补文本即可，与 `tier`/`indent` 无关 |
