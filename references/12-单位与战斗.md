## 0. 数据流
```
main_units_tables（招募层）→ land_units_tables（战场层）
   ├─ melee_weapons_tables / missile_weapons_tables → missile_weapons_to_projectiles_tables → projectiles_tables
   │     ├─ explosion_type → projectiles_explosions_tables → shrapnel → projectile_shrapnels_tables → projectiles_tables（可套娃）
   │     └─ projectile_penetration → projectile_penetration_junctions_tables
   ├─ unit_armour_types_tables / unit_shield_types_tables ｜ battle_entities_tables（man_entity）
   ├─ mounts_tables（mount）→ battle_entities_tables / variants_tables
   └─ battlefield_engines_tables（engine）→ warscape_animated_tables ｜ land_unit_articulated_vehicles_tables ｜ land_units_to_battle_personalities_junctions_tables → battle_personalities_tables
unit_variants_tables → variants_tables ｜ unit_set_to_unit_junctions_tables → unit_sets_tables（战役加成）
```

## 1. 招募层 `main_units_tables`（WH3 45 列）
主键 `unit`。被引用：`building_units_allowed_tables`、`units_to_groupings_military_permissions_tables`、`units_custom_battle_permissions_tables`、`cdir_military_generator_unit_qualities_tables.unit_key`、`unit_set_to_unit_junctions_tables.unit_record`、`unit_to_unit_list_junctions_tables`、`unit_purchasable_effect_sets_tables`、`unit_banner_unit_height_offsets_tables`。

| 列 | 语义 / 常见改动 |
|---|---|
| `land_unit` / `num_men` | → `land_units.key`（必须存在）；每队人数，改人数连带改总血量（23 册 §3） |
| `caste` / `ui_unit_group_land` | → `unit_castes_tables` / `ui_unit_groupings_tables`（UI 分类 + 战役加成） |
| `recruitment_cost` / `upkeep_cost` / `create_time` / `campaign_cap` | 招募费 / 维持费 / 回合 / 上限（-1 无上限） |
| `additional_building_requirement` / `tier` / `can_siege` | 额外建筑需求 → `building_levels_tables` / 招募层级 / 可攻城 |
| `use_hitpoints_in_campaign` / `barrier_health` / `is_monstrous` / `is_renown` / `weight` / `food_cost` / `melee_cp` / `missile_cp` / `porthole_*` / `mount` | 血条用血量制 / 屏障 / 怪兽 / 精英 / 重量 / 食物 / 自动分 / 头像，抄原版 |
- 教程的 `unit_scaling` 在 WH3 **不存在**；海军列（`is_naval`/`naval_unit`/`num_ships`/`min/max_men_per_ship`）仍在，WH3 无海战，抄原版【待核对】。
- 验收：改完进战役，招募面板费用/回合/人数与表一致。

## 2. 战场层 `land_units_tables`（WH3 60 列）
主键 `key`，被 `main_units.land_unit` 引用；绝大多数面板数据出自本表。

| 列（分组） | 语义 / 指向 |
|---|---|
| `category` / `class` | → `unit_category_tables` / `unit_class_tables` |
| `melee_attack` / `melee_defence` / `charge_bonus` / `rank_depth` / `spacing` | 近战面板 |
| `accuracy` / `reload` / `primary_ammo` / `secondary_ammo` / `infinite_secondary_ammo` | 远程面板 |
| `bonus_hit_points` / `primary_melee_weapon` / `primary_missile_weapon` | 每人额外血量（23 册 §3）；武器 → `melee_weapons_tables` / `missile_weapons_tables` |
| `armour` / `shield` | **`armour` 存护甲类型 key**（实测如 `wh2_main_heavy_metal_90`），不是数字；`shield` → `unit_shield_types_tables` |
| `man_entity` / `mount` / `num_mounts` / `articulated_record` / `engine` / `num_engines` | 实体与载具（23 册 §5–§6） |
| `man_animation` / `attribute_group` | → `battle_animations_table_tables` / `unit_attributes_groups_tables` |
| `damage_mod_flame` / `_magic` / `_physical` / `_missile` / `_all` | 抗性，负值 = 受伤增加 |
| `short_description_text` / `historical_description_text` / `campaign_action_points`（原版 2100） / `capture_tier` | 描述 key（文本在 loc）/ 战役点 / 占领 |
| `visibility_spotting_range_min` / `_max` / `spot_dist_tree` / `spot_dist_scrub` / `hiding_scalar` | 视野与隐匿 |
- WH2 列 `officers` / `dismounted_*` / `animal` / `num_animals` / `ability_global_recharge` / `strength_weaknesses_text` / `loose_spacing` 在 WH3 **已不存在**；`supports_first_person`→`first_person`，`capture_power`→`capture_tier`，`num_engine`→`num_engines`（23 册 §0.2）。
- 【待核对】`training_level`、`reload`、`ground_stat_effect_group`、`mounted_draughts`、`sync_locomotion`、`visibility_spotting_range_*` 的影响（教程自认不确定）；`resource_requirement`、`special_edition_mask`、`audio_voiceover_culture*` 语义（对比原版同类行）。
- 验收：游戏内面板逐项与表值对照。

## 3. 武器系统
### 3.1 `melee_weapons_tables`（WH3 20 列）
主键 `key`，被 `land_units.primary_melee_weapon`、`battle_entity_stats.primary_melee_weapon` 引用。
- 伤害：`damage` / `ap_damage`；反大/反步：`bonus_v_large` / `bonus_v_infantry`（WH3 **无** `bonus_v_cavalry`）。
- 溅射：`splash_attack_target_size` / `_max_attacks` / `_power_multiplier`（需动作支持，23 册 §11.2）。
- 特殊：`building_damage_multiplier` / `ignition_amount` / `is_magical` / `is_spell` / `contact_phase` / `scaling_damage` / `collision_attack_max_targets`（+`_cooldown`）/ `melee_attack_interval`。
### 3.2 `missile_weapons_tables`（5 列）
`key` / `precursor`（先导射击）/ `default_projectile` / `audio_type` / `use_secondary_ammo_pool`（23 册 §11.3）。
### 3.3 武器 ↔ 投射物
- `missile_weapons_to_projectiles_tables`（`missile_weapon` / `projectile`）：一把武器挂多发弹药（切换需不同 `shot_type`）。
- `unit_missile_weapon_junctions_tables`（`missile_weapon` / `unit` / `battle_entity_stats_override`）：单位额外（副）远程武器。
- 验收：换武器后游戏内面板伤害/反大/反步与表一致。

## 4. 投射物系统
### 4.1 `projectiles_tables`（WH3 58 列）
| 分组 | 关键列 |
|---|---|
| 弹道 | `shot_type` / `muzzle_velocity` / `gravity` / `effective_range` / `expiry_range` |
| 命中 | `marksmanship_bonus` / `spread` / `calibration_distance` / `calibration_area`（23 册 §12） |
| 伤害 | `damage` / `ap_damage` / `bonus_v_infantry` / `bonus_v_large` / `shockwave_radius` / `ignition_amount` / `is_magical` / `scaling_damage` |
| 多发 | `projectile_number` / `burst_size` + `burst_shot_delay` / `shots_per_volley`（23 册 §11.4） |
| 爆炸 / 穿透 / 外观 | `explosion_type` / `overhead_stat_effect` / `contact_stat_effect` / `projectile_penetration`（§4.3） / `projectile_display` |
- `base_reload_time` 填 0 也有最小装填时间 2；有装填动作时以动作时长为准【待核对】。
- `expiry_range` 必须 ≥ 实际射程，否则弹丸中途消失（叠射程 buff 的种族尤其注意）。
### 4.2 爆炸与破片
| 表（列数） | 主键 | 被谁引用 | 关键列 |
|---|---|---|---|
| `projectiles_explosions_tables`（21） | `key` | `projectiles.explosion_type` | `detonator_type`（`fuse` 空爆 / `percussive` 接触）/ `detonation_radius` / `detonation_damage` / `detonation_damage_ap` / `shrapnel` / `affects_allies` |
| `projectile_shrapnels_tables`（5） | `key` | `projectiles_explosions.shrapnel` | `projectile` / `amount` / `launch_type`（`hemisphere` / `sector`）/ `sector_angle` |
| `projectile_displays_tables`（19） / `projectile_shot_type_displays_tables`（3） / `projectiles_scaling_damages_tables`（5） | `key` | `projectiles` 对应列 | `display_model` / `icon_name` / `max/min_damage_multiplier` |
- 破片本身是投射物：`projectile_shrapnels.projectile` 指回 `projectiles_tables`，该投射物还能有自己的 `explosion_type` → 子母套娃（实例见 23 册 §11.5）。
- 验收：`fuse` 类空中爆开、`percussive` 接触爆开；`affects_allies` 关闭后友军不被爆炸波及。
### 4.3 穿透：两张表联动（改穿透必看）
- `projectiles_tables.projectile_penetration` → `projectile_penetration_junctions_tables.key`（WH3 4 列：`key` / `description` / `entity_size_cap` / `max_penetration`）。
- 语义：`entity_size_cap` = **会被立即挡下**的实体体型上限（不是能穿过的体型）；`max_penetration` = 穿透容量（`-1` 无限）。
- 原版速查：`very_low`(very_small,0) / `low`(small,2) / `medium`(medium,5) / `high`(large,10) / `very_high`(very_large,20) / `all`(-1)。
- **怎么做**：想要的「体型上限 + 容量」组合原版没有时，在 junction 表**新增一行**（如 `large_5`）再让投射物指向它；**不要改原版已有关键字**（会波及所有引用者）。覆盖原版投射物时用**整行**，只改目标列。两张表必须打进同一个 pack。
- 验收：射击多排目标，穿透数量与 `max_penetration` 一致；要贯穿 large 级大怪需 `entity_size_cap=very_large`。

## 6. 战斗实体与动画
### 6.1 `battle_entities_tables`（WH3 58 列）
主键 `key`。被 `land_units.man_entity`、`mounts_tables.entity`、`battle_personalities_tables.battle_entity`、`battlefield_engines_tables.battle_entity`、`land_unit_articulated_vehicles_tables.articulated_entity` 引用。

| 分组 | 关键列 |
|---|---|
| 速度 / 冲锋 | `walk_speed` / `run_speed` / `charge_speed` / `fly_speed` / `flying_charge_speed` / `acceleration` / `deceleration` / `turn_speed` / `charge_distance_*` |
| 物理 / 体型 / 血量 | `mass` / `height` / `radius` / `shape` / `size`（very_small…very_large，medium 及以上算大型）/ `hit_points`（每人血量，23 册 §3） |
| 反应 / 远程受击 | `hit_reactions_ignore_chance` / `knock_interrupts_ignore_chance` / `projectile_intersection_radius_ratio` / `projectile_penetration_speed_change` / `projectile_penetration_resistance` |
| 特效 / 表现 | `aura_vfx` / `vfx_filter_id`（溅射与武器特效需 ≥1）/ `has_blood` / `can_dismember` / `jump_attack_chance` |
- **面板速度 = `run_speed`/`fly_speed` × 10**【待核对】。战车面板速度按 `mounts_tables.entity` 显示，不是 articulated entity【待核对】。
- 【待核对】`projectile_intersection_radius_ratio`（教程称改 0 近乎免疫远程）、`projectile_penetration_*` 三列（教程自认未验证）。
- **模型缩放不改判定**：被命中的"底盘"是 `radius`（＋`shape` / `height` / `projectile_intersection_radius_ratio`），与 `variants_tables.scale` / `mount_scale` 是两套数据；只缩模型不缩 `radius` → 打空也算命中。改大小必看 27 册 §1.8。
- 验收：改 `run_speed` 后面板速度与实战移速同步变化。
### 6.2 动画
动作片段、骨骼接线、移动射击及姿态异常见 `28-骨骼动作与移动射击.md`；不能把接站立射击概括为移动必然僵化。
- `battle_animations_table_tables`（`key` / `skeleton`）：`skeleton` 是骨骼枚举（`humanoid01`…`humanoid17`、`horse01` 等）。
- `culture_to_battle_animation_tables_tables`（`battle_animations_table` / `culture_pack`）：跨文化登记（23 册 §4）。
### 6.3 乘员 / 引擎 / 战车
- 乘员：`land_units_to_battle_personalities_junctions_tables`（6 列，`battle_personality`+`land_unit`；`attach` / `riders_attachment_point`）→ `battle_personalities_tables`（8 列，`key`；`man_animations_table` / `variant` / `battle_entity` / `battle_entity_stats`）→ `battle_entity_stats_tables`（3 列，乘员武器）。
- 引擎：`battlefield_engines_tables`（19 列，`key`；`gun_animation_table` / `missile_weapon` / `model` / `battle_entity` / `destroyed_model`）→ `warscape_animated_tables` → `warscape_animated_lod_tables`（`filename` = rigid_model_v2）。
- 战车：`land_unit_articulated_vehicles_tables`（10 列，`articulated_entity`）。
- WH2 的 `land_units_officers_tables` 与 `land_units_additional_personalities_groups_junctions_tables` 在 WH3 **不存在**，乘员统一走 junction 表（23 册 §11.6）。
- 验收：乘员出现在正确挂点；引擎毁坏时播毁坏模型/动作。

## 7. 单位变体与外观
- `unit_variants_tables`（5 列，`faction`+`unit`）：`name`（→ `unit_variants_colours.unit_variant`）/ `variant`（→ `variants_tables.variant_name`）/ `unit_card`。
- `variants_tables`（8 列，`variant_name`）：`variant_filename` / `mount_scale` / `scale` / `scale_variation`；被 `unit_variants.variant`、`mounts.variant` 引用。

- WH3 配色已改为 **hex** 三列（教程的 RGB 三组列已不存在）；派系配色另见 `factions_tables` 的 `*_colour_hex` 列。
- 验收：同单位在不同派系显示各自配色；`scale` 只缩放骑乘者、`mount_scale` 只缩放坐骑。
- > ⚠️ 坑：两者都**只改渲染**，不改碰撞体与命中判定；模型缩放后要按同一比例同步 `battle_entities.radius`（27 册 §1.8）。

| 表（列数） | 关键列 | 用途 |
|---|---|---|
| `unit_sets_tables`（5） | `key` / `use_unit_exp_level_range` / `min/max_unit_exp_level_inclusive` / `special_category` | 定义单位集（可带经验等级范围） |
| `unit_set_to_unit_junctions_tables`（6） | `unit_caste` / `unit_category` / `unit_class` / `unit_record` / `unit_set` / `exclude` | 兵种 ↔ 单位集，决定战役加成与兵牌颜色 |

| `unit_lists_tables` / `unit_to_unit_list_junctions_tables` / `unit_allowances_tables` / `unit_set_*_junctions_tables` | `key` / `unit`+`unit_list` / `faction_set`+`point_cap` / 目标列+`unit_set` | 列表、容量许可、单位集 ↔ 技能阶段/能力/属性 |
- 加成链：科技/建筑/技能树 → `effect` → Unit Set → 兵种（见 23 册 §11.7）。

- 验收：挂一个作用于该 Set 的 effect，新兵种吃到加成。

### 8.1 单位容量许可 `unit_allowances_tables`（3 列：`unit_list` / `faction_set` / `point_cap`）

**是什么**：给"某个派系集合"限制"某类单位"能保有多少个 —— 新版本的车/巨兽/特殊兵限额系统。
与 `main_units_tables.campaign_cap` 是**两套独立机制**：`campaign_cap` 是单表全局上限（`-1` = 无上限），本表是"派系集合 × 单位类别"的细粒度容量。

**查法（三步）**

1. 在 `unit_to_unit_list_junctions_tables` 里找目标单位挂了哪些 `unit_list` —— 容量用的列表键长这样：`wh3_unit_cap_vmp_veh_black_coach`；
2. 拿这个 `unit_list` 去 `unit_allowances_tables` 查行，`faction_set` 就是要限制的派系集合（键定义在 `faction_sets_tables`，成员在 `faction_set_items_tables`）；
3. `point_cap` = 该集合下的容量上限（`2147483647` 原版用作"无限"）。

**加容量的唯一合法出口是 effect，不是改本表**

- 效果键在 `effects_tables`（命名如 `wh3_unit_cap_<...>` / `<dlc>_effect_unit_cap_<...>`，`icon` 一般是 `unit_capacity.png`）；
- 效果必须经 **`effect_bonus_value_unit_list_junctions_tables`** 绑定到具体列表：`bonus_value_id` 用 **`unit_allowance_point_cap_mod`**，`unit_list` 填第 1 步查到的那个键；
- 授予渠道四条：`building_effects_junction_tables`（建筑）、`technology_effects_junction_tables`（科技）、`character_skill_level_to_effects_junctions_tables`（技能树）、`effect_bundles_to_effects_junctions_tables`（效果组，可被事件/两难/脚本动态施加，见 25 册 §3）。

**效果组的 scope 与阶段**（照原版容量类效果抄）：

```
effect_bundle_key      effect_key         effect_scope                    value    advancement_stage
<你的 bundle>          <容量 effect>      faction_to_faction_own_unseen   1.0000   start_turn_completed
```

`unseen` = 不显示在 UI 提示里。原版参考实例：`wh2_dlc09_agent_choice`（古墓王事务官容量）、`wh3_dlc29_nag_dilemma_eternal_servant`（永仆）、`wh2_dlc11_vmp_ritual_bloodline_awaken_*`（血裔容量）。

- 验收：招募面板上该单位的容量数字 = 基础值 + 已获得的各渠道加成。
- > ⚠️ 坑：**直接覆盖 `unit_allowances_tables` 是改基础值、对该 faction_set 全局生效**；要"买了才 +N"必须走 effect（实测案例见 25 册 §3）。

## 9. 属性组（被动状态）
- `unit_attributes_groups_tables`（`group_name`）：被 `land_units.attribute_group` 引用；`unit_attributes_to_groups_junctions_tables`（`attribute` / `attribute_group`）：属性 → 组；`unit_attributes_tables`（`key`）：属性键清单。
- **禁止新增 `unit_attributes` 键**（`SKILL.md` §2 硬规则）：只能引用原版已有键，新增键不被引擎识别。
- 常用键（WH3 已核对）：`causes_fear`（引发恐惧）、`causes_terror`（惊骇）、`charge_defense` / `charge_defense_vs_large`（抵御冲锋）、`fatigue_immune`（精力充沛）、`immune_to_psychology`（心理免疫）、`stalk`（潜行）、`snipe`（狙击）、`unbreakable`（永不战败）、`undead`（亡灵）、`wallbreaker`（破墙者）、`guerrilla_deploy`（先锋部署）、`hide_forest`（森林隐匿）、`mounted_fire_move`（移动射击，**需对应动作**）。WH3 共 **87** 个键（2026-09-25 实测；新增 `must_resist` / `shrouded` / `tomb_king` / `vampire`，中文文本暂缺）。
- 教程的 `charge_reflector` / `_vs_large` 在 WH3 **不存在**（已改名）；`all_ranks_fire`、`hide_building`、`mighty_knockback`、`run_amok` 也不存在，不要用。
- **`unit_attribute`（属性组，本节）≠ `unit_ability`（单位被动能力）**：后者如「受创」`wh3_main_unit_passive_single_entity`（单体专属惩罚 —— 身受重伤后战斗力下降）、「不稳定」「约束衰减」，来自 `land_units_to_unit_abilites_junctions_tables` 或 unit_set 链。**要移除某个被动能力，见 11 册 §3.4**（unit_set + `disable`，零覆盖原表）。
- 验收：进战斗确认被动状态图标与效果出现，无静默失效。

## 10. UI / 描述 / 权限
- `ui_unit_groupings_tables`（3 列）：`key` / `icon` / `parent_group`；loc 键 `ui_unit_groupings_onscreen_<key>`。
- `ui_unit_bullet_point_unit_overrides_tables`（2 列）`bullet_point`+`unit_key`；`ui_unit_bullet_point_enums_tables`（4 列）`key` / `state` / `sort_order` / `icon_path`（`state` 即教程的 `stat`）。
- `unit_description_short_texts_tables` / `unit_description_historical_texts_tables`（仅 `key`）：文本在 loc。
- `units_custom_battle_permissions_tables`（11 列）：`faction` / `general_unit` / `unit` / `siege_unit_attacker` / `siege_unit_defender` / `campaign_exclusive`。
- `units_to_groupings_military_permissions_tables`（2 列）：`unit` / `military_group`；**漏填 = 战役看不到该兵**。
- `unit_banner_unit_height_offsets_tables`（3 列）：`unit_record` / `height_offset` / `campaign_height_offset`。
- 验收：自定义战斗能选到该兵；战役招募面板能招到；标签与描述正常显示。

## 11. 可购买效果（单位升级）
- `unit_purchasable_effects_tables`（5 列）：`key` / `cost` / `effect_bundle`（→ `effect_bundles_tables`）/ `category` / `pre_requisite_set`。
- `unit_purchasable_effect_sets_tables`（3 列）：`unit` / `purchasable_effect` / `is_exclusive`。
- 验收：战役中该单位能购买对应升级，花费与 `cost` 一致。

## 12. AI 生成器
- `cdir_military_generator_unit_groups_tables`（`key`）：招募类型组。
- `cdir_military_generator_unit_qualities_tables`（`group_key` / `unit_key` / `quality`）：AI 招募倾向；不填 = AI 不招募（23 册 §9）。
- 验收：AI 派系会自然造出该兵种。

## 13. 特殊能力相关表（做法见 `references/21-技能与法术制作.md`）
- 兵种 ↔ 能力：`land_units_to_unit_abilites_junctions_tables`（`ability` / `land_unit`）；能力定义：`unit_abilities_tables`（12 列，`key`）；附加 UI 效果：`unit_abilities_to_additional_ui_effects_juncs_tables`。
- **给兵种批量加战斗主动技能**：优先逐单位写 `land_units_to_unit_abilites_junctions_tables`；不得用过滤型 `unit_set`（技能会完全不出现，详见 `21` §5）。批次可按 `main_units_tables.caste` 筛选后生成。
- **阵型技能**（`type=wh_type_formation` + `unit_special_abilities.formation`）：形状值取自 `special_abilities_specific_formation_types_tables` 的 13 个枚举，引擎硬编码。做法见 `21` §1。
- ⚠️ 坑：`special_ability_phases_tables` 里有**孤立 phase**（`wh_dlc07_unit_formation_flying_wedge`、`wh_dlc07_unit_formation_diamond`）——没有 `unit_abilities` / `unit_special_abilities` 行，技能在游戏里不存在。查技能存在性一律回查 `unit_abilities_tables`。
- 特殊技能：`unit_special_abilities_tables`（71 列，`key`；`active_time` / `recharge_time` / `initial_recharge` / `num_uses` / `effect_range` / `passive` / `activated_projectile` / `bombardment` / `spawned_unit` / `vortex`）；军队级：`army_special_abilities_tables`。
- 技能阶段：`special_ability_phases_tables`（31 列，`id`；`duration` / `effect_type` / `damage_amount` / `heal_amount` / `mana_regen_mod` / `imbue_*` / `affects_allies` / `affects_enemies`）；技能 ↔ 阶段：`special_ability_to_special_ability_phase_junctions_tables`。
- 阶段效果与强度：`special_ability_phase_stat_effects_tables` / `special_ability_phase_attribute_effects_tables` / `special_ability_intensity_settings_tables`（8 列，`default_amount` / `max_amount` / `intensity_source` / `intensity_type`）。
- 标志类（各 2 列）：`special_ability_to_recharge_contexts_tables` / `_invalid_target_flags_tables` / `_invalid_usage_flags_tables` / `_auto_deactivate_flags_tables`。
- **禁止新增 `intensity_source`**：只能用原版枚举（`SKILL.md` §2 硬规则）。
- 验收：能力图标、冷却、作用目标与阶段效果在游戏内与表一致。

## 14. 全局战斗规则 `_kv_rules_tables`（2 列：`key` / `value`）

> 这张表是**全局物理参数**，与具体兵种无关：改一行 = 全游戏所有单位一起变。做"冲锋手感""撞击力度""击倒率"这类需求时，先看这里，不要先去改兵种或技能数值。
> 系数影响为**经验性**（来自参考 mod 的取值与实际体感差异），未做逐参数定量实测。

| 键 | 原版 | 作用 |
|---|---|---|
| `collision_damage_modifier` | 0.6 | 撞击伤害系数 |
| `collision_damage_maximum` | 70 | 单次撞击伤害上限 |
| `collision_damage_normaliser` | 0.8 | 撞击伤害归一化系数 |
| `collision_damage_armour_penetration_ratio` | 0.7 | 撞击伤害的破甲比例 |
| `collision_damage_immunity_timer` | 4.0 | 同一目标的撞击伤害冷却（秒）。调低 = 一次冲锋可反复造成撞击伤害 |
| `collision_restitution_coefficient` | 0.3 | 碰撞反弹系数 |
| `collision_speed_delta_threshold_knocked_back` | 4.0 | 判定"击退"所需速度差 |
| `collision_speed_delta_threshold_knocked_down` | 7.0 | 判定"击倒"所需速度差 |
| `collision_speed_delta_threshold_knocked_flying` | 10.5 | 判定"撞飞"所需速度差 |
| `collision_speed_delta_threshold_step_back` | 3.0 | 判定"踉跄"所需速度差 |
| `knockdown_getting_up_delay_min` / `_max` | 1.0 / 2.7 | 被撞倒后的爬起延迟区间（秒） |
| `collision_disable_delay_knocked_*_vs_enemies` / `_vs_friends` | 2.0 / 0.0 | 被撞后的僵直时长；`_vs_friends` 原版即 0 |

- 实测案例（`su_qbzx` 2026-09-23）：参考 mod `arkbrtoverhaul.pack` 的"冲锋威力"来自本表——`collision_damage_modifier` 0.6→0.9、`collision_damage_maximum` 70→100、`collision_damage_immunity_timer` 4.0→1.0、三档速度差阈值 4.0/7.0/3.0 → 1.5/2.5/1.2、爬起延迟 1.0/2.7 → 2.5/4.5。同一份数据里巴托骑兵的 `charge_bonus` 只上调了 5 点、坐骑质量基本未变——**"冲锋威力"的差距几乎全部来自本表，而不是兵种数值或体型质量**。
- ⚠️ 坑：把本表当成"骑兵专属强化" → 实际影响所有单位的碰撞，步兵互撞、战车与怪兽撞击一并变化；与其它 MOD 同改本表时按加载顺序整行覆盖（`03` §5）。
- 验收：改后进自定义战斗，用同一兵种对同一目标做一次冲锋，观察撞击伤害数字、被撞单位倒地数量与爬起时间。
