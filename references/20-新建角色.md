## 4. 命名与 ID 分配调查方法（不假设，先查）

**结论**：新角色的一切命名与数字 ID 都先调查目标 MOD 现状再分配，不套用其他 MOD 的号段。

- **key 前缀**：看现有角色文件名与 unit key（如 `wyccc_lord_*`），沿用之。
- **art_set_id / uniform / variant 命名**：照现有角色模式；`variant_filename` 对应 `variantmeshes/variantmeshdefinitions/<名>.variantmeshdefinition`。
- **数字 ID**：`campaign_character_arts.id`、`unit_special_abilities.unique_id`、`names_tables.id`、`unit_variants_colours.key` 等——`grep` 现有文件找已用段，取未占用新段并复查无跨文件撞号；必须 ≤ 2,147,483,647。
- **loc 键**：由「表前缀 + 完整 key」拼成，见 `50-本地化与翻译.md`。

**怎么做**：① `grep -h "^<前缀>"` 汇总现有 key → ② 取最大数字 ID 并留间隔 → ③ 全 MOD 搜新 key 确认零命中。
**验收**：`grep` 新 key 在目标 MOD 全目录只有你新加的行；ID 段无跨文件重叠。

## 5. Agent 与 Agent Subtype 双层分类（教程 20）

**结论**：每个英雄单位都同时有 **Agent 大分类**与 **Agent Subtype 小分类**；大分类决定"事务官行动模板"，小分类决定"模型/技能/身份"。

| 层 | 注册表 | 语义 |
|---|---|---|
| Agent（大分类） | `agent_culture_details_tables` | 该**文化**拥有哪些 Agent 类型；决定可用的事务官行动组。`champion` 在帝国=队长、矮人=族长；**所有领主的 Agent 都是 `general`** |
| Agent Subtype（小分类） | `agent_subtypes_tables` | 每个英雄单位专属；关联模型/技能/身份。帝国领主位的将军、大诵经师、猎人将军 Agent 都是 `general`，Subtype 各不相同 |

- **实测值域**：`agent_culture_details_tables.agent` 有 9 种（含 `colonel`、`minister`）；`agent_actions_tables.agent` 只有 6 种（无 `general`/`colonel`/`minister`）。完整枚举见 `13` 册 §7.1。
- **怎么做**：新增领主通常**不必**改 `agent_culture_details_tables`（Agent 已是 `general`）；新增事务官先确认该文化是否已有目标 Agent 类型，有则只加 Subtype 行。
- **验收**：`agent_subtypes.associated_unit_override` 指向存在的 `main_units.unit`；角色在战役里能被招募且行动面板可用。

## 7. 教程 20 硬坑

> ⚠️ 坑：`campaign_character_art_sets_tables.is_custom` 勾选 → 无论传奇还是大众脸都**抓不到模型**（原版传奇会勾，自定义必须不勾）。

> ⚠️ 坑：`is_male` 与 `agent_culture_details_tables.gender` 冲突（如 culture 填 `f`、art set 勾男性）→ 该 art set 在战役中不出现（大众脸确定；传奇未验证）。

> ⚠️ 坑：用 Effect 控制招募/容量时只填 Subtype 侧 → Agent 未解锁，仍招募不了。**必须同时**在 `effect_bonus_value_agent_junction_tables`（列序 `effect, bonus_value_id, agent`）与 `effect_bonus_value_agent_subtype_junctions_tables`（列序 `bonus_value_id, effect, subtype`，**顺序不同**）各写行；`bonus_value_id` 用 `availability`/`cap`/`recruitment_level`。

> ⚠️ 坑：不填 `faction_agent_permitted_subtypes_tables` → 即使 Effect 已启用，该派系也**无法招募**。

> ⚠️ 坑：`indent=8` 的事务官行动节点套用别族行动 → 不生效；该节点的 **Agent 类型必须与本事务官相同**（`champion` 只取原版 `champion` 的行动）。

**验收**：招募面板能看到该角色；招募按钮可用；行动列表是目标 Agent 类型的行动。

## 8. 战役动作链与骑手排查（硬规则）

### 8.1 三项必须同骨骼

`campaign_character_arts_tables.land_animation`、模型实际骨骼、`campaign_mount_animation_set_overrides_tables` 的 `character_animation_set`/`rider_animation_set` 必须同骨骼类型。**跨骨骼 = 大地图摆大字**。

- 骨骼前缀必须一致：hu1 模型只用 `cam_hu1_*`，hu1e 只用 `cam_hu1e_*`。
- 可用的 `cam_*` 键以原版 `<VANILLA>\db\campaign_character_arts_tables\data__.tsv` 与 `campaign_mount_animation_set_overrides_tables\data__.tsv` 中出现的为准，**不得自创键名**。
- 实测可用基准：hu1 双手剑女性 = 赫潘丝 `cam_lord_hu1_dlc14_repanse_2handed_sword`（战马骑手 `cam_hu1_dlc14_hr1_warhorse_repanse_2handed_sword`）；hu1e 女法师 = `cam_hu1e_hr1_mage_female_hero`。

### 8.2 战斗键是独立键域

`land_units_tables.man_animation` 与 `battle_personalities_tables.man_animations_table` 都引用 `battle_animations_table_tables.key`（列 `key`/`skeleton`）。**`cam_*` 只属大地图，绝不能填进战斗字段，也不能靠删 `cam_` 前缀推导战斗键**——`cam_hu1_empire_dr1_dragon_wb_sword_and_shield` 合法，对应的战斗键未必存在。

**怎么做**：先在 `<VANILLA>\db\battle_animations_table_tables\data__.tsv` 查精确键，再按骑手骨骼/武器/坐骑选原版基准。
**验收**：RPFM 导入不报 `Invalid reference`；进战斗骑手动作正确。

### 8.3 骑手错位 / 挂点 / 飞行坐骑排查顺序（按序，不要跳步）

1. **挂点优先**：骑手动作会播但不坐对位置 → 先查 `land_units_to_battle_personalities_junctions_tables.attach` 与 `riders_attachment_point`，以**相同 `mount` key 的原版单位**为基准，挂点名不可跨坐骑套用（高精耀星龙用 `autonomous_rider` + `ap_riderpos_0`；`ap_riderposition_0` 是别的坐骑的挂点，拼写近似也会错位）。
2. **动作键**：挂点正确后再同时核对 `land_units.man_animation`、`battle_personalities.man_animations_table` 与骑手 RMV2 骨骼；两张战斗表用同一或原版证明兼容的键，且其 `skeleton` 匹配。
3. **`animroot` 大小写**：仅当 `.variantmeshdefinition → .wsmodel → .rigid_model_v2` 链明确显示根骨骼名不一致时才处理；先备份，等长替换、只改目标字节。它不是挂点错误的替代诊断。
4. **飞行坐骑**：不能只看 `mounts_tables`、`land_units` 的 `flying_*` AI 分组或 UI 的 `can_fly` 文案；必须沿 `land_units_tables.attribute_group → unit_attributes_to_groups_junctions_tables` 确认该单位**实际获得原版 `flying` 属性**。
5. **自定义坐骑复用不含 `flying` 的原版属性组** → 不要改共享原版组（会影响其他单位）；把原组属性复制到 MOD 自有组、加 `flying`，只让该 `land_units` 指向新组。仍不能飞再核对 `unit_set_to_unit_junctions_tables` 的 `all_units_excluding_flying` 与 `always_flying`。

**验收**：大地图与战场骑手均坐姿正确；飞行坐骑能起飞；`git diff --check` 无空白错误；属性键来自原版 `unit_attributes_tables`。

## 9. 美术与本地化清单

### 9.1 每角色美术（尺寸/抠图规范见 `30`/`31`/`32`，本册不重复）

| 资源 | 路径 |
