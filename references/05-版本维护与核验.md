# 05 · 版本维护与核验

> 游戏字段、schema、工具接口与游戏实测分别核验。发布维护：2026-10-21。

## 1. 随包参考基线

作者核验基线 WH3 9.0.2 / Steam build 25649450，1,602 个 DB 表目录，1,601 TSV + 1 未解码二进制表。指纹在 `assets/version-baseline.json`，已移除作者路径。这是作者快照，不能视为读者版本或后来最新版。

作者对 db.pack 重导并对拍；本包仅带表名/版本/列名/计数/哈希等核验元数据，不带游戏表内容。原不可解码的 `initiative_sets_tables`、`ritual_character_target_criterias_tables` 已导成 TSV；`autoresolver_unit_group_categories_enums_tables` 仍为 raw，未验证其行/字段。

2026-10-16 后续资料参考为 WH3 9.0.4.0 / build 25961564：1,603 个表目录（1,600 TSV、3 张未解码二进制）。新增 `ritual_calculation_overrides_tables`，`ui_mercenary_recruitment_infos_tables` 本次仅保留二进制，原有 `autoresolver_unit_group_categories_enums_tables` 仍未解码。**随包 `assets/version-baseline.json` 仍为 9.0.2 快照**，没有因文档表数同步而接纳新版机器指纹；更新后差异须审查，不能直接当作通过。

## 2. 取得自己的原版

确认游戏安装、可执行文件版本、Steam build 和 RPFM schema。从实际 `<GAME>/data/` 导出所需 pack，TSV 表使用 `db/<table>/data__.tsv` 并保留 RPFM 元数据第 2 行；未解码表保留为同目录 `data__`。本地化和脚本另导出，所用语言包按自己的安装选择。

游戏更新后比较新旧导出：表增删、列序/字段类型、表版本、key 与枚举、脚本 API。对受影响 MOD 迁移并静态检查，关键行为进游戏验证。未使用的旧表不必机械全库重写。不要仅改 TSV 版本号却保留旧列序。

含原生 DLL 的 MOD 还需按 [61](61-原生反编译与版本适配.md) 检查输入身份、地址定位、对象链、ABI 和重入。仅改 EXE 大小/hash，或仅通过 DB 自检，均不能证明原生模块适配完成。

## 3. 随包审计工具

`scripts/audit-version.js` 默认只读；要求 `--source <导出根>` 或环境变量 `WH3_EXPORT_DIR`。默认与作者参考基线比；可用 `--baseline <自己的快照>` 比。

```powershell
node (Join-Path $SkillRoot 'scripts/audit-version.js') --source $Vanilla --json
node (Join-Path $SkillRoot 'scripts/audit-version.js') --source $Vanilla --game (Read-Host '输入游戏根目录') --schema (Read-Host '输入 schema_wh3.ron 路径')
```

可选 `--game` 检查安装 pack/Steam build，`--schema` 检查 schema 哈希。不提供时明确跳过，不会读取历史案例。语言 pack 未安装属于记录项；指定游戏目录缺 db.pack/data_script.pack 是错误。若保留同名原版 pack 副本，检查其与安装文件哈希是否相同；它不证明每个 TSV 都是从该副本重导，导出来源仍需自己确认。

新快照需显式 `--snapshot <新文件>`，可附 `--game-version <已核实版本>`；不提供版本标为 unknown，不继承作者版本。拒绝坏导出和覆盖已有快照。新快照会记录使用者目录，分享自己的快照前去掉 sourceRoot/gameRoot/schema.path。

退出码：0 = 已选检查通过（或成功建快照）；1 = 漂移/坏导出；2 = 参数/环境错误。原版语言、RPFM 解码版本或导出命名改变也可能造成漂移，先查原因再认定游戏机制变化。只导部分 DB 会报告其他表缺失，这是与全库快照比较的预期结果。

2026-10-21 增加 44/61：提炼历史机制还原、定向反编译与版本适配方法。历史原始报告和分析工程未随包分发，不能假定读者已有它们；读者应为自己的输入保存对应证据。此次发布未重新运行游戏或全部历史适配器测试。

后续维护已加入 33 DDS、43 UI、28 §6 RMV2 分类及 DDS 只读工具；当前原版 Lua 的查找/事件核对属于静态证据，UI、模型与贴图游戏行为按实际任务验收。固定外部来源与选择性采纳范围见 91 §7。

静态对拍不代替游戏内验收。移动射击案例 28 采用 2026-10-08 用户反馈，未重新游戏实测。过滤单位集授予主动能力失效不是所有单位集无效；删除表支持以当前 schema/作者说明核实；file 路径覆盖与行主键合并分别分析。
