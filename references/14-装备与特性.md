## 2. `ancillaries_tables`（29 列）

```
key type applies_to transferrable unique_to_world unique_to_faction precedence
start_date end_date avatar_skill avatar_special_ability legendary_item mp_exclusive
is_wife_ancillary category min_starting_age max_starting_age min_expiry_age max_expiry_age
immortal provided_bodyguard_unit provided_banner uniqueness_score turns_before_swap_allowed
subcategory randomly_dropped can_be_stolen can_be_destroyed faction_set
```

| 列 | 含义 / 取值 | 依据 |
|---|---|---|
| `key` | 主键；建议 `{MOD前缀}_anc_{种类}_{名字}` | 实测 |
| `type` | →`ancillary_types_tables.type`，决定图标；普通装备复用 `wh_main_anc_weapon` 等共享 type | 实测（原版共享 type 仅 weapon/armour/talisman/enchanted_item/arcane_item；**无 `wh_main_anc_mount`**） |
| `applies_to` | 适用对象；原版 2619 行为 `.`、52 行为空 | 实测 |
| `transferrable` | 可否在角色间转移 | B（教程 17/素材） |
| `unique_to_world` / `unique_to_faction` | 全图唯一 / 派系内唯一 | 实测列名 |
| `precedence` | 唯一性冲突优先序（常用 1） | 实测列名 |
| `start_date` / `end_date` | 生效时代（`0` / `9999` = 全部时代） | 实测列名 |
| `avatar_skill` / `avatar_special_ability` | 罕见/遗留，一般留空 | B（素材） |
| `legendary_item` | 传奇标记（UI 传奇边框） | B（素材） |
| `mp_exclusive` | 仅多人可用 | B（素材） |
| `is_wife_ancillary` | 配偶装备 | B（素材） |
| `category` | →`ancillaries_categories_tables`（8 个合法值，见 22 §1） | 实测 |
| `min_starting_age`/`max_starting_age`/`min_expiry_age`/`max_expiry_age` | 获取与失效年龄窗 | B（素材） |
| `immortal` | 装备不随角色死亡消失 | B（素材） |
| `provided_bodyguard_unit` | 坐骑提供的单位 →`main_units_tables.unit` | 实测列名 |
| `provided_banner` | 若为方旗 →`banners_tables.banner` | 实测列名 |
| `uniqueness_score` | 稀有度，档位见 `ancillary_uniqueness_groupings_tables`（22 §8.2） | 实测 |
| `turns_before_swap_allowed` | 允许换下的回合数（`0`=随时） | B（素材） |
| `subcategory` | →`ancillaries_subcategories_tables`（11 个合法值） | 实测 |
| `randomly_dropped` | 是否进原版随机掉落池 | 实测列名 |
| `can_be_stolen` / `can_be_destroyed` | 可被偷 / 可被销毁 | B（素材） |
| `faction_set` | 可用派系组 →`faction_sets_tables.key` | 实测 |

> ⚠️ 坑：凭记忆写列名 → WH3 该表 29 列，与 WH2 教程描述有出入；每次以 `data__.tsv` 第 1 行为准。
> ⚠️ 坑：`type` 填不存在的键 → 装备无图标（普通装备用共享 type，general 类用装备自身 key）。

**验收**：`ancillaries_tables` 表头列数 = 29；`type`/`category`/`subcategory`/`faction_set` 四个引用列的值都能在对应表里找到。

## 3. 其余装备域表字段

### 3.1 `ancillary_to_effects_tables`（4 列）
| 列 | 含义 |
|---|---|
| `ancillary` | →`ancillaries_tables.key` |
| `effect` | →`effects_tables.effect` |
| `effect_scope` | 生效范围（取值见 22 §3 与 11 册） |
| `value` | 数值（属性型=修正值、百分比型=百分数、启用型=1） |

### 3.2 `ancillary_set_ancillary_junctions_tables`（2 列）
`ancillary_key` → 装备 key；`set_key` → `ancillary_sets_tables.key`。**只列成员，不含效果**。

### 3.3 `ancillary_sets_tables`（2 列）
`key`（套装主键）+ `icon`（套装图标，`ui/skins/default/` 下）。

### 3.4 `ancillary_set_effect_junctions_tables`（4 列）
`effect_key` + `set_key` + `effect_scope` + `value`：集齐整套后生效的效果。

### 3.5 `ancillaries_included_agent_subtypes_tables`（2 列）
`agent_subtype` + `ancillary`：让指定事务官子类型**只能/可以**用该装备（坐骑必填）。
> ⚠️ 坑：把这表当成"生成时自带装备" → 它的作用是**限制可用范围**（参考实现 `参考mod\Just More Items` 用 `agent_subtype + 坐骑装备` 限制专属坐骑）。

### 3.6 `ancillaries_required_skills_tables`（3 列）
`ancillary` + `required_skill`（→`character_skills_tables.key`）+ `required_skill_level`。

### 3.7 `ancillary_info_tables`（1 列）
`ancillary`：装备注册行。**实测原版 2671 条装备 = 2671 条注册**，一一对应。
> ⚠️ 坑：漏写这一行 → 装备在 UI 不完整/不显示。

### 3.8 `character_ancillary_quest_ui_details_tables`（5 列）
| 列 | 含义 |
|---|---|
| `agent_subtype` | →`agent_subtypes_tables.key` |
| `ancillary` | →`ancillaries_tables.key` |
| `rank` | 解锁等级 |
| `instant` | 是否即时获得（非任务战） |
| `is_quest_battle` | 是否通过任务战获得 |

用途：角色技能面板里"任务解锁装备"的提示 UI。

**验收**：任务神器装备在角色面板显示为可解锁，任务完成后再显示为已获得。

## 4. 特性域

### 4.1 表清单

| 表 | 主键 | 用途 | 引用关系 |
|---|---|---|---|
| `character_traits_tables` | `key` | 特性本体（8 列） | 被 §4.2/§4.4 引用 |
| `character_trait_levels_tables` | `key` | 特性等级（4 列） | `trait`→`character_traits_tables.key` |
| `trait_level_effects_tables` | `trait_level`+`effect` | 等级 → 效果 | `trait_level`→`character_trait_levels_tables.key` |
| `trait_info_tables` | `trait` | 特性注册（1 列，**每特性一行**） | →`character_traits_tables.key` |
| `trait_to_antitraits_tables` | `trait`+`antitrait` | 互斥特性 | 双向引用 |
| `technology_character_traits_junctions_tables` | `character_trait`+`technology_node` | 科技授予特性 | →`character_traits_tables.key` |
| `campaign_payload_character_trait_change_components_tables` | `id`+`character_trait_level`+`payload` | 事件/脚本改特性（`is_removal`=移除） | →`character_trait_levels_tables.key` |
| `character_training_dilemma_choice_traits_tables` | `m_character_trait_level_key`+`choice_key` | 训练两难给特性 | →`character_trait_levels_tables.key` |
| `bretonnia_vows_to_traits_tables` | `trait`+`vow` | 巴托誓言 → 特性 | →`character_traits_tables.key` |
| `trait_categories_tables` | `category`+`icon_path` | 特性分类与图标路径 | **未见被 `character_traits_tables` 引用**；具体消费方【未验证】 |

### 4.2 `character_traits_tables`（8 列）

```
key no_going_back_level hidden precedence icon ui_priority pre_battle_speech_parameter remove_on_skill_reset
```

| 列 | 含义 |
|---|---|
| `key` | 主键 |
| `no_going_back_level` | 达到该级后不可移除 |
| `hidden` | 是否在 UI 隐藏 |
| `precedence` | 优先序 |
| `icon` | 图标**键名**（实测取值如 `personality`/`tomb_kings`/`trait_good`，**不是完整路径**） |
| `ui_priority` | UI 排序 |
| `pre_battle_speech_parameter` | 战前演讲参数（旧素材漏记此列） |
| `remove_on_skill_reset` | 技能重置时是否移除 |

> ⚠️ 坑：把 `icon` 当路径填（如 `ui/...png`）→ 图标不显示；原版填的是图标键，取值规律抄原版同文化同类特性。
> ⚠️ 坑：照抄旧素材的 7 列描述 → 实际 8 列，漏 `pre_battle_speech_parameter` 会错位。

### 4.3 `character_trait_levels_tables`（4 列）

| 列 | 含义 |
|---|---|
| `key` | 主键。**单级特性 = 特性 key；多级特性 = `<trait>_<n>`**（实测 `wh2_dlc09_trait_settra_title_2` / `level=2`） |
| `level` | 等级，从 1 开始（实测分布：1→739、2→96、3→74、4→24、5→24、6→22） |
| `trait` | →`character_traits_tables.key` |
| `threshold_points` | 达到该级所需累计点数 |

### 4.4 `trait_level_effects_tables`（4 列）
`trait_level`（→等级 key）+ `effect`（→`effects_tables.effect`）+ `effect_scope` + `value`。
实测 scope 除 `character_to_character_own` 外还有 `general_to_force_own` 等——**scope 取值以 `campaign_effect_scopes` 与原版同类行为准**。

**特性链**：`character_traits_tables` → `character_trait_levels_tables` → `trait_level_effects_tables` → `effects_tables`；`trait_info_tables` 必须同步注册。

> ⚠️ 坑：只建 `character_traits_tables` 不建 `trait_info_tables` → 特性不完整（原版两表行数相等：744=744）。
> ⚠️ 坑：多级特性把 level key 写成 `<trait>_level_<n>` 却与原版命名不一致 → 与 payload/脚本引用对不上；以原版同类多级特性为基准命名。

**验收**：特性在角色面板显示；达到阈值后等级效果生效；`trait_info_tables` 有对应行。

## 5. Lua 发放装备的坑

正确 API（实测 `<VANILLA>\script\` 中 32 处调用）：

```lua
cm:force_add_ancillary(character, ancillary_key, bool, bool)  -- 直接给角色
cm:add_ancillary_to_faction(faction, ancillary_key, bool)     -- 进派系库存
faction:ancillary_exists(item_key)                            -- 防重复
```

> ⚠️ 坑：使用 `cm:force_add_ancillary_to_character(...)` → **该函数不存在**（旧素材 `warhammer-mod-development\references\ancillaries_and_traits.md` 写法有误）；调用会报错或静默无效，正确名为 `cm:force_add_ancillary`。
> ⚠️ 坑：装备 key 未在 `ancillaries_tables` 注册就调用发放 → **静默失败**（无报错、装备不入包）。
> ⚠️ 坑：复制原版装备做副本却不换 key → 覆盖原版定义；副本必须新建带 MOD 前缀的 key 并完整注册主表 + `ancillary_info_tables`。
> ⚠️ 坑：监听器注册在 `cm:add_first_tick_callback_new` 内 → 读档后失效（用 `cm:add_first_tick_callback`）。
> ⚠️ 坑：不查 `faction:ancillary_exists` 就发 → 同一装备重复入包。

**验收**：触发后装备出现在目标角色/派系库存；读档再触发不重复；日志无 `Invalid reference`。

## 6. 验收清单

- [ ] 用到的每张表都核对过 `data__.tsv` 表头（列名与列数），没有照抄 WH2 教程的列数
- [ ] 新建装备 key 同时出现在 `ancillaries_tables` 与 `ancillary_info_tables`
- [ ] `type`/`category`/`subcategory`/`faction_set`/`effect` 等引用列的目标值都在被引用表中存在
- [ ] 套装三表引用一致（`ancillary_sets_tables` + 成员 junction + 效果 junction）
- [ ] 限定时用了正确的表：大类 → `ancillary_to_included_agents_tables`；子类型 → `ancillaries_included_agent_subtypes_tables`
- [ ] 前置技能走 `ancillaries_required_skills_tables`，`required_skill` 在 `character_skills_tables` 存在
- [ ] 特性：`character_traits_tables` + `character_trait_levels_tables` + `trait_level_effects_tables` + `trait_info_tables` 四表齐；多级 level key 命名与原版一致
- [ ] 特性 `icon` 填图标键（非路径），与 `trait_categories_tables.icon_path` 不混用
- [ ] Lua 用 `cm:force_add_ancillary`（不是 `_to_character`），发放前 `ancillary_exists` 防重复，监听器在 `add_first_tick_callback` 内
- [ ] 数字主键 ≤ 2,147,483,647（`faction_set_items_tables.id` 等）
- [ ] 所有新增 key 都有中英成对本地化（键模板见 22 §9）
