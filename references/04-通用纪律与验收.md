# 通用纪律与验收

> 适用：WH3 ｜ 事实截止：2026-09-08
> 来源：现有 development 技能（TSV 命名/格式、命名规范）、历史命名资料（已归档）、教程 01/05/08/15、工具依赖说明及历史案例
> 可信度：A（跨版本稳定）｜ 指纹：—
> 维护核验：2026-10-08；当前版本、来源与本次验证范围见 `05-版本维护与核验.md`。

本册是全书的**共性约束**：不管做哪类 MOD，这些规则都适用。分册特有的坑在各册写。

## 1. 命名规范

### 1.1 MOD 与文件命名

| 对象 | 规则 | 理由 |
|---|---|---|
| MOD 文件夹 | 英文、无空格、无中文 | RPFM 与引擎对中文路径支持差 |
| pack 文件名 | **不能是中文**（教程作者连写三遍"不能是中文"） | 中文名 pack 无法被游戏加载 |
| 封面图 | 与 pack **同名** + `.png`，≤1 MB，正方形 | 创意工坊上传要求 |
| 自建 key | 带 MOD 专属前缀（如 `my_mod_`），不裸用通用词 | 避免与其他 MOD 撞码 |

> ⚠️ 坑：用中文命名 pack 或目录 → 游戏静默不加载，且无报错。

### 1.2 DB 文件命名与覆盖

使用 MOD 专属文件名，删除不修改的行；相同完整路径覆写文件，不同文件的数据行合并。覆盖原主键仍需核对优先级，不能把 `data__` 视为全库模式开关。机制与验收唯一入口为 `03-工程与打包发布.md` §2。

### 1.3 Lua 文件

- 目录：`script/campaign/<战役>/mod/`（具体战役 key 见 `40-Lua战役脚本.md`）
- 文件**必须无 BOM**（Lua 5.1 会报 `near '�'`）
- 只用 Lua **5.1** 语法（无 `goto`、无 `//`、无整数除法）
- 提交前必查：`luac5.1 -p <文件>`

### 1.4 目录名

- 引擎识别的资源目录必须**精确匹配**（大小写、空格都不能改）：
  `ui\battle ui\ability_icons`、`ui\campaign ui\skills`、`ui\units\icons`、`ui\units\infopics`、`ui\portraits\portholes\<文化>`、`ui\buildings\icons` 等
- 自建目录用英文小写 + 下划线

### 1.5 键名与变量

- 本地化键 = **表前缀 + 完整键名**（详见 `50-本地化与翻译.md`）
- Lua 全局变量加前缀，避免与引擎/其他 MOD 冲突
- 一个 key 只供一个用途（如 `unit_set_unit_ability_junctions_tables` 里一条 key 只能供一个 unit set 或一个 ability）

## 2. 主键与 ID 分配

### 2.1 主键上限（按 schema 类型判断）

- **先看类型，再定上限**（`schema_wh3.ron` 的 `field_type`，不能凭 TSV 表头或当前数值推断）：
  - **I32** 列 → 必须 ≤ **2,147,483,647**（例：`building_units_allowed_tables.key`）
  - **I64** 列 → 无 32 位限制（例：`cdir_events_{incident,dilemma,mission}_payloads_tables.id`）
- 超出 I32 上限 → 该行不加载，通常无明确报错。

> ⚠️ 坑：把 `cdir_events_*_payloads_tables.id` 当成 I32 去"控制数值范围" → 理由错（它是 I64）；反过来把 I32 列填 90 亿 → 整行失效。

### 2.2 专属号段

- 不同 MOD 用不同号段，避免撞号；同一 MOD 内部号段连续便于管理。
- 号段规则写在**该 MOD 自己的 README**，不写进技能书（技能书只给"要划号段"这条纪律）。

### 2.3 占用调查法（不假设，先查）

新建任何 key/ID 前，按顺序查：
1. `<VANILLA>\db\<相关表>_tables\data__.tsv` —— 原版是否已占用
2. `<MODS>\`、`参考mod\` —— 自己的其他 MOD 是否已占用
3. 同名 key 是否在多个表里引用（改一处漏一处 → 引用失效）

> ⚠️ 坑：主键重复 → 后加载的条目覆盖前者；技能主键重复会导致原技能无法释放（表现为需要瞄准的技能不能瞄准、对自身的 buff 不生效）。

## 3. TSV 格式硬约束

```tsv
header
#表名;版本;表路径
列1	列2	列3
```

- 元数据行固定 `#<表名>;<版本>;<表路径>`
- 列数必须等于表头列数（多一列少一列都会被 RPFM 拒绝或错位）
- 分隔符必须是**制表符**，不是空格
- 无多余空行/空列
- 表路径前缀要与文件名前缀匹配
- **编码：UTF-8 无 BOM**（2026-09-08 实测：原版 `localisation__.loc.tsv`、原版 DB、`已完成mod\` 与 `参考mod\` 下全部 TSV 首字节均为 `key\t` / `unit\t` / `attr`，无 `EF BB BF`）

> ⚠️ 坑：旧素材 旧版 TSV 格式素材（已归档） 写"UTF-8 with BOM（RPFM 默认）" → 与历史案例实测不符；按它加 BOM 可能被引擎或 RPFM 误读。以历史案例实测为准。

**数值主键范围校验**：按 schema 的 I32/I64 类型与完整主键列核验；`check-tsv.ps1 -CheckIds` 只按调用者给的上限检查首列，不识别 schema。

## 4. 改动纪律

### 4.1 最小改动

- 只改必须改的行/列；不顺手重构、不批量重排。
- 改动前先备份或确认可回滚。

### 4.2 先查原版基准

任何新建内容，先找一个**原版同类**条目做基准（兵种按攻击动作选、建筑/技能按同类选），复制后改值。凭空写字段是失败率最高的做法。

### 4.3 不手改 pack

- 只改源 TSV；打包交给 RPFM。
- pack 使用现成工具修改；RMV2 局部二进制候选需兼容解析器、往返和字节审计，见 `28` §6。

### 4.4 版本管理（建议）

- Git 命令：`git`；不在 PATH 时用使用者确认的完整路径
- 工作区当前**没有** `.git`；若要启用版本管理，先 `git init` 并加 `.gitignore`（排除 `游戏原文件\`、`*.pack`）
- 提交前 `git diff --check` 查空白错误
- 只提交源 TSV/Lua，不提交打包产物

## 5. 验收

### 5.1 通用验收清单（每个任务都过一遍）

- [ ] 文件命名符合 1.1/1.2，pack 名无中文
- [ ] **跑过 `modcheck` 且退出码 0**（`node "<SKILL>\tools\modcheck\check.js" <MOD目录> [--ref <参考mod解包目录>]`；它检查格式、表头与版本、数据反查引用；类型、复合键和资源仍需专项检查）
- [ ] TSV 元数据行正确、列数与表头一致、制表符分隔
- [ ] I32/I64 主键按各自类型范围检查，完整复合键无撞码且号段明确
- [ ] 所有 key 已在原版或自有 MOD 中查过占用
- [ ] 每个新建 key 都有对应的本地化条目（中英成对）
- [ ] Lua 文件无 BOM，`luac5.1.exe -p` 通过
- [ ] 所有引用的动画/资源/表 key 真实存在（modcheck 抓跨表引用，动画/资源另用 grep 原文件确认）
- [ ] 只改了源文件，未手改 pack
- [ ] 进游戏实测：目标功能生效，且原版同类功能未被破坏
- [ ] 改了技能/装备/角色时，检查战役界面显示是否正常（不只看战斗内）

### 5.2 崩溃红线速查

| 红线 | 后果 |
|---|---|
| pack/目录用中文 | 静默不加载 |
| 主键溢出或重复 | 该行不加载 / 覆盖原版 |
| TSV 列数与表头不符 | 导入失败或列错位 |
| 引用了不存在的 key | `Invalid reference`，RPFM 拒绝导入 |
| 新增 `unit_attributes` / `intensity_source` | 静默失效 |
| 跨骨骼套用动画 | 破图 / 十字摆姿 / 骑手错位 |
| 跨文化动作未填 `culture_to_battle_animation_tables_tables` | 进战场不能动 |
| 槽标签 `</Slot>` 缺失 | 部件不显示 |
| Lua 文件带 BOM | 脚本报错不执行 |
| 监听器注册在 `_new` 回调里 | 读档后失效 |

## 6. 协作约定

- 不确定就问用户，不要硬试（尤其涉及不可逆操作、游戏内无法验证的判断）。
- 工具缺失先读 `工具清单与准备.md`；运行脚本前核实 Node 已安装。缺工具时说明影响并给方案。
- 结论必须给证据：表名 + 字段名 + 原文件路径 或 实测结果。
- 使用者工具路径变化后更新自己的环境记录；包内依赖说明见 `../工具清单与准备.md`。
