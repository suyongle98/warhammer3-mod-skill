> 适用：WH3 ｜ 事实截止：2026-09-08

## 0. 排查铁律

1. **先取日志，再改数据**：没有 `out()` 证据前，不得判定"脚本没生效/回调没触发"。
2. **先定层，再定值**：按边界切分（能力指令收到 → 目标捕获 → 施法命令 → 命中/爆炸），缺哪段只查哪段。
3. **一次只改一处**，改完重跑取新日志，不叠加猜测。
4. **静态校验先过**：TSV 列数、引用存在、`luac5.1.exe -p`、`git diff --check`。

## 1. 日志在哪里、怎么开、怎么读

### 1.1 脚本日志（`out()` 输出）——先探测使用者环境，位置按当前源码核对

| 项 | 结论 | 依据 |
|---|---|---|
| 文件名 | `script_log_<DDMMYY>_<HHMM>.txt` | `all_scripted.lua` L111 |
| 写入目录 | **游戏进程当前工作目录** = `Warhammer3.exe` 所在目录 → `<GAME>\` | L116 `io.open(filename,"w")` 用相对路径；作者环境 `lua_mod_log.txt` 就在该目录 |
| 开关 | 全局 `__write_output_to_logfile`，由 tweaker `ENABLE_SCRIPT_LOGGING` 决定；该值为 `"0"`/`""` 时改看是否存在 `/script/enable_console_logging` | L95-105 |
| 行格式 | 每行前缀 `<N.Ns>`（`os.clock()` 相对本会话起点） | L18-20 |
| 脚本错误 | `script_error()` 同时 `print` 到控制台**并**追加日志：`SCRIPT ERROR, timestamp <Ns>` + 消息 + `debug.traceback` | L52-86 |

作者历史案例未找到 script_log 文件；这不证明使用者环境也未生成。先在自己的游戏目录探测：

```powershell
Get-ChildItem -Path "<GAME>" -Filter "script_log_*.txt" |
  Sort-Object LastWriteTime -Descending | Select-Object -First 5 Name,Length,LastWriteTime
```

有输出 → 读最新那个；无输出 → 脚本日志未启用，走 §1.2/§1.3。

> 实际游戏目录由使用者确认；不要照搬作者盘符。

### 1.2 替代通道（作者环境实测存在）

| 通道 | 路径 | 用途 |
|---|---|---|
| mod 日志 | `...\Warhammer III\lua_mod_log.txt` | `ModLog()` 写（`lib_mod_loader.lua` L39-68）：**每个 mod 文件加载成功/失败**及原因，是"脚本进没进游戏"的第一手证据 |
| mod 自建日志 | 同目录，如 `waaagh_trophy_legendary_debug.txt` | mod 自己 `io.open`；工作目录 = 游戏根目录 |
| 加载顺序 | 同目录 `used_mods.txt`、`wyccc_launch_mods.txt` | `add_working_directory` + `mod "xxx.pack"` 顺序 = 覆盖优先级，查"改动被别的 mod 盖掉"必看 |
| 崩溃转储 | `<USER_CONFIG>\crash_report\` | `*.mdmp`（约 50 MB，含明文字符串）+ `*.stack.txt`（只有模块名，无符号） |
| 引擎日志 | `...\Warhammer3\logs\` | `mp_log.txt`、`gfx.log.txt`、`no_clean_exit`（上次非正常退出标记） |
| 配置 | `...\Warhammer3\scripts\preferences.script.txt` | `vfs_log_level`（0=off/1=mod-user/2=dev）；作者环境 `0` |

**怎么做**：调试输出除 `out("mymod: xxx")` 外**同时**加 `ModLog("mymod: xxx")`——它同时写 `lua_mod_log.txt` 与控制台，**不依赖** `ENABLE_SCRIPT_LOGGING`。**验收**：`lua_mod_log.txt` 出现 `Mod [script\...\your_mod.lua] loaded successfully`，随后 `Executing mod function your_mod()`。

### 1.3 读日志的 4 个陷阱

1. **文件巨大**（几千~几万行）：附件只显示开头初始化段，mod 输出在末尾 → `-Tail` 或按行号读末尾。
2. **编码**：可能是 UTF-16 LE 而非 UTF-8 → grep 搜不到 ≠ 没有。作者环境 `preferences.script.txt`、`lua_mod_log.txt` 为 UTF-8，`crash_report\*.stack.txt` 为 ASCII。
3. **中文路径**：用 `-LiteralPath` 而非 `-Path`。
4. **搜不到 ≠ 不存在**：让用户直接粘贴片段，不要反推"没生效"。

```powershell
Get-Content -LiteralPath "<日志全路径>" -Tail 200 -Encoding UTF8
Select-String -LiteralPath "<日志全路径>" -Pattern "mymod|SCRIPT ERROR|PERFORMANCE WARNING" -Encoding UTF8
```

## 2. 常见报错串：含义与定位方向

### 2.1 加载期（文件/脚本没进游戏）

| 报错串 | 含义 / 定位 |
|---|---|
| `Mod [<路径>] loaded successfully` | 加载成功；**没有此行 = 没进游戏**（`lib_mod_loader.lua`） |
| `Failed to load mod file [<文件>], error is: <err>. Will attempt to require() ...` | `loadfile()` 失败（语法/编码/路径）；紧跟的下一行是 `require()` 给出的**真实语法错误**（`lib_core.lua` L729） |
| `Failed to execute loaded mod file [<文件>], error is: <err>` | 能加载但**顶层执行**抛错；错误文本即行号与原因（L716） |
| `ERROR: <mod>() failed while executing with error: <err>` | 同名入口函数执行失败（L776） |
| `WARNING: ModLog() could not create/open lua_mod_log.txt` | 工作目录不可写（权限/杀软） |
| `check_event_errors_on_startup() is listing N event error(s)` | 读档发现**存档内记录过脚本失败**（`lib_campaign_manager.lua` L2044-2085） |

### 2.2 语法/编码 · 运行时 · 导入期 · 性能

| 报错串 | 含义 | 定位方向 |
|---|---|---|
| `near '�'` / `unexpected symbol near '<乱码>'` | 文件带 BOM 或非 UTF-8 | 存成 **UTF-8 无 BOM**；只用 Lua 5.1 语法 |
| `'=' expected near 'continue'` / `near 'goto'` | 用了 Lua 5.2+ 的 `goto`/`::label::`/`continue` | 改写成 `if/else` 嵌套 |
| `near '//'` / `near '~'` | Lua 5.3+ 运算符 | 用 `/` 与 `math.floor` |
| `attempt to index (a nil value)` | 对 nil 取字段，最常见 `cm:get_faction(k)` 返回 nil | 先 `if faction and not faction:is_dead() and not faction:is_null_interface() then` |
| `attempt to call (a nil value)` | 调用了不存在的函数/方法 | 先在 `游戏原文件\script\` grep 该函数名确认存在与参数 |
| `Invalid reference` | 某列引用了目标表里**不存在**的 key | 沿该列的引用目标表 grep；常见于动画键、效果键、单位 key |
| 列错位 / 数据串行 | 列数或列序与表头不符 | 读 `data__.tsv` 表头逐列比对；分隔符必须是制表符 |
| 导入"没报错"但该行不生效 | 数值主键超出字段类型范围（静默丢弃） | 查 `schema_wh3.ron` 该列 `field_type` |
| `PERFORMANCE WARNING ... took [X]s to execute, exceeding its allowed time of [Y]s` | 事件回调超时 | `lib_core.lua` L2296-2317（`ENABLE_SCRIPT_PERFORMANCE_WARNING_REPORTS`，L32）；改 `cm:callback` 分帧或缩小遍历 |

**验收**：每个改动 `.lua` 都跑 `luac5.1 -p <文件>`（退出码 0）；日志中不再出现该报错且 `out()` 打印了"进入分支"的证据。

## 3. 崩溃分类（按"谁先报错"排）

| # | 类别 | 典型症状 | 定位方法 | 修复方向 |
|---|---|---|---|---|
| 1 | **DB 引用不存在** | 启动阶段闪退，到不了主菜单；多个 dump 签名一致 | 读 `crash_report\*.mdmp` 字符串段，捞出**正在处理的表名与数据** | 补上被引用但未定义的 key |
| 2 | **列数错位** | 导入失败或某行静默失效 | `(行 -split "\t").Count` 对比表头 | 补齐/删多余列；确认制表符 |
| 3 | **主键溢出/重复** | 该行不加载（无报错）或覆盖原版行 | 查 schema 字段类型；grep 主键是否已占用 | 换 ≤ 上限的值与专属号段 |
| 4 | **脚本语法/编码** | 该 mod 整体不加载 | `luac5.1.exe -p`；`lua_mod_log.txt` | 去 BOM、改 5.1 语法 |
| 5 | **资源缺失** | 空图标/无模型/无特效，但不崩 | grep 资源路径；查 pack 内目录 | 补资源或改引用 |
| 6 | **键域混用** | 十字摆姿、骑手错位、进战场不能动 | 见 §5 | 见 §5 |
| 7 | **存档兼容** | 读旧档报错或状态错乱 | 日志中 `check_event_errors_on_startup()` 段落 | 迁移或提示开新档 |

**类别 1 实证案例**（`已完成mod\su_qizhi\制作说明.md` 修复记录 3）：`mortuary_cult_categories_tables` 只有表头 0 条数据，而 `mortuary_cult_categories_to_rituals_tables` 有 48 行引用 `su_qizhi_banners` → 启动读祭祀商店数据时原生崩溃。证据来自 minidump 字符串：`mortuary_cult_categories_to_rituals`、`su_qizhi_bannerssu_qizhi_ritual_buzhunshuohua_pu`。

**类别 1 流程**：① 取最新 `.mdmp`，文本方式捞可打印字符串（表名/key 是明文）→ ② 在 `游戏原文件\db\` 搜该表名，判断"定义表"还是"映射表" → ③ 若是映射表，逐个 key 回查定义表找**悬空引用** → ④ 全工程跑引用完整性检查，目标 0 悬空。

> ⚠️ 坑：只看 `crash_report\*.stack.txt` 判断原因 → 它只有 `ntdll / Warhammer3 / KERNEL32` 这类模块名、**没有符号**；必须去 `.mdmp` 捞字符串或复现。

## 4. API 实证结论：first tick 回调族（**必读，纠正旧技能**）

**结论**：注册**事件监听器**用 `cm:add_first_tick_callback`（全局版）；`_new` 只在新游戏触发，读档不触发。

| API | 触发范围 |
|---|---|
| `cm:add_pre_first_tick_callback(fn)` | 所有模式，**最早** |
| `cm:add_first_tick_callback_new(fn)` | **仅新游戏**（单机或多人）：写入 `_mp_new` + `_sp_new` |
| `cm:add_first_tick_callback_sp_new(fn)` | 仅新游戏·单机 |
| `cm:add_first_tick_callback_mp_new(fn)` | 仅新游戏·多人 |
| `cm:add_first_tick_callback_sp_each(fn)` | 单机·新游戏或读档 |
| `cm:add_first_tick_callback_mp_each(fn)` | 多人·新游戏或读档 |
| `cm:add_first_tick_callback(fn)` | **全局**（含读档），最后调用 |
| `cm:add_post_first_tick_callback(fn)` | 全局，**最晚** |

- 依据：`lib_campaign_manager.lua` **L2219-2330**（函数体逐一实测；`_new` 的 L2327-2328 明确 `table.insert` 进 `_mp_new` 与 `_sp_new`）。官方注释 L2222 给出顺序：`pre` → `_new` → `_sp_each`/`_mp_each` → 全局 `add_first_tick_callback`。
- 附带（L2223）：首 tick 时**读盘界面可能还在**，要上屏显示的脚本应配合 `core:progress_on_loading_screen_dismissed`；非函数入参会 `script_error`。

**怎么做**：任何"注册监听器 / 初始化"统一放全局版；**新开一局 + 读旧档各测一次**，两次日志都要出现 `mymod: first tick` 且监听器都响应。

```lua
cm:add_first_tick_callback(function(context)
    out("mymod: first tick, turn=" .. tostring(cm:turn_number()))
    core:add_listener("mymod_turn_start", "FactionTurnStart", true, function(ctx) end, true)
end)
```
> ⚠️ 坑：在 `add_first_tick_callback_new` 里注册监听器 → 新游戏正常、**读档后监听器全失效**。旧技能 `lua_api.md` 的模板正是这种写法，不要照抄。

## 5. 骑手错位 / 挂点 / 飞行坐骑：可执行排查顺序

**按顺序做，前一步不过不进下一步。**

| 步 | 检查对象 | 怎么做 / 验收 |
|---|---|---|
| 1 | **挂点** `land_units_to_battle_personalities_junctions_tables.attach` + `riders_attachment_point` | 以**相同 mount key 的原版单位**为基准逐字比对；挂点名须与原版同坐骑完全一致（例：高精耀星龙 = `autonomous_rider` + `ap_riderpos_0`；`ap_riderposition_0` 是别的坐骑的挂点，拼写近似也会错位） |
| 2 | **战斗动画键** `land_units_tables.man_animation` 与 `battle_personalities_tables.man_animations_table` | 两处用同一或原版已证明兼容的键；该键必须存在于 `battle_animations_table_tables.key`，且骨骼与骑手一致 |
| 3 | **大地图动画键** `campaign_character_arts_tables.land_animation`、`campaign_mount_animation_set_overrides_tables.character_animation_set` / `rider_animation_set` | 骨骼前缀必须与骑手模型一致（穗香 = `hu1` → 只能 `cam_hu1_*`，不得 `cam_hu1e_*`）；**战斗模型正常不代表大地图动作链有效** |
| 4 | **模型根骨骼** | 仅当 `.variantmeshdefinition` → `.wsmodel` → `.rigid_model_v2` 链明确显示根骨骼名不一致时，才处理 `animroot`/`animRoot` 大小写；备份后等长字节替换，核对替换数量与长度 |
| 5 | **飞行坐骑** | 沿 `land_units_tables.attribute_group` → `unit_attributes_to_groups_junctions_tables` 确认实际获得原版 `flying`（作者环境 `unit_attributes_tables` 共 87 条 key（9.0.2 基线），含 `flying`、`always_flying`） |

**飞行坐骑专用规则**：不要只看 `mounts_tables`、`flying_*` AI 分组或 UI 的 `can_fly` 文案。
- 自定义坐骑复用**不含 `flying` 的原版属性组**时：**不要**给共享原版组补属性（会影响其他单位）；复制原组属性到 MOD 自有属性组 + 追加 `flying`，再让自定义 `land_units` 指向新组。
- 仍不能飞 → 再按同类原版单位核对 `unit_set_to_unit_junctions_tables` 的 `all_units_excluding_flying` 与是否应使用 `always_flying`。
- **键域硬约束**：`cam_*` 只属于大地图动作链，**绝不能**填进 `man_animation` / `man_animations_table`，也不能靠删 `cam_` 前缀推导战斗键。

> ⚠️ 坑：骑手动作会播但坐姿不对就去盲换动画 → 真正原因多在挂点（第 1 步）；换动画只会叠加新问题。

## 6. "技能不生效"排查

| # | 检查点 | 症状 | 怎么做 / 依据 |
|---|---|---|---|
| 1 | `unit_abilities_tables.requires_effect_enabling` | 勾了但没通过 effect/科技/建筑/技能点启用 → 永远点不了 | 单位技能（走 `land_units_to_unit_abilites_junctions_tables` 挂）**不勾**；要靠战役途径解锁才勾（教程 08，B） |
| 2 | `target_friends` / `target_enemies` / `target_ground` / `target_self` / `only_affect_target` | ① 点技能只有"咚"声、选目标界面出不来；② **反过来：能对着别的部队点选、点下去却放不出效果** | 至少勾一个可选目标；②是**目标字段组不自洽**的典型表现（`only_affect_target=true` + 四个 `target_*` 全 `false` + `num_effected_*_units=0`）→ 正确组合表见 `21-技能与法术制作.md` §3.1（A，2026-09-10 实测）；改完用 `scripts/diff-row.ps1` 与原版模板逐字段对拍（教程 08，B） |
| 3 | `affect_self` / `num_effected_friendly_units` / `num_effected_enemy_units` | 能选中目标但效果不生效 | **可被选中 ≠ 会生效**；给友军要 `num_effected_friendly_units>0`（不限 `-1`）；纯自身增益则 `affect_self=true` + `target_*` 全 `false`（组合对照见 `21` §3.1） |
| 4 | `unit_special_abilities_tables.unique_id` | 新技能无法释放（需瞄准的不能瞄准、对自身的 buff 不生效） | 主键/`unique_id` **不得与原版重复**；重复时要么被原技能顶掉，要么权重不够（教程 08 评论，B，多条独立确认） |
| 5 | 装备/坐骑技能缺等级限制 | 进游戏技能显示"已使用"无法点选 | 在 `character_skill_level_details_tables` 加等级行（教程 15，B） |
| 6 | 每级效果未逐级填 | 技能升到 2/3 级无任何加成 | `character_skill_level_to_effects_junctions_tables` **每级一行**（教程 15，B） |
| 7 | `targetting_aoe` / `passive_aoe` / `active_aoe` 留空 | 技能无光圈或表现异常 | 参考原版同类（教程 08 评论，B） |
| 8 | `effect_range` / `target_intercept_range` | 范围技打不到 / 选不了远处目标 | `effect_range`：自体中心 `0`、全图 `-1`；`target_intercept_range` 才是可选施法距离，**两者不同字段**（教程 08，B） |
| 9 | `wind_up_time` + `wind_up_stance` | 前摇时间到了技能还不放 | 法术必须**播完前摇动作**才施放；动作时长 > 数值时以动作为准（教程 08，B） |
| 10 | `effect_scope` 用错 | 效果不作用于目标（尤其随军） | 英雄随军用 `agent_to_parent_army_own` / `character_to_force_own`；`general_to_force_own` 不生效（教程 15，B） |
| 11 | 目标相位条件 | 脚本 `has_attribute` 找不到标记 | 沿 `special_ability_to_special_ability_phase_junctions` → `special_ability_phases` → `special_ability_phase_attribute_effects` 核对 `affects_enemies`、原版标记属性、`attribute_type=positive`（施加）/`negative`（移除） |
| 12 | 涡流数值 | 改了伤害/半径没变化 | 先沿 `unit_special_abilities.vortex` 回溯到同一条 `battle_vortexs` 记录；多个隐藏技能共享 `vortex_key` 时只改共享行 |

> ⚠️ 坑：把"技能没反应"直接归因为数值太小 → 先确认第 1-4 项（启用/目标/主键），数值只在"确认技能已释放"之后才有意义。
> ⚠️ 坑：**技能图标在、能点、甚至能对着别人点选，但放不出效果** → 九成是第 2 条的目标字段组不自洽，根因通常是**克隆了语义不同的原版模板**（拿"对友军施放"的技能行改成"自身增益"）。换模板，别靠试字段；详见 `21` §3.1。

## 7. UI 运行时结构与 XML 静态定义的差异

**结论**：XML 层级不保证等于运行时树；`find_uicomponent` 按字符串路径段搜索后代，可跨层，失败返回 **false**（2026-10-08 核对当前 `lib_common.lua`）。严格孩子用 `Find(index)`；下列招募路径须按当前运行树复核。

```
root > units_panel > main_units_panel > recruitment_docker > recruitment_options
  ├── footer > filter_bar
  └── recruitment_listbox > recruitment_pool_list
        ├── global_min
        └── local1  → 内部子组件包含 template_recuitment_entry 实例
```

**怎么做**：限定面板后查当前树，避免同名误命中。**验收**：返回不是 false，`IsValid()` 且父链属于目标面板，重开后重新查找。布局/CCO/生命周期见 `43-UI布局与运行时.md`。
