# 43 · UI 布局与运行时

> 适用：WH3 9.0.2 的 TWUI、Lua UIComponent 与 CCO 排查 ｜ 事实截止：2026-10-08。
> 来源：scnjwyc 技能包 `b92d85e`；当前原版 `script/_lib/lib_common.lua`、`lib_core.lua`、`events.lua`；CA API 文档的社区镜像。
> 边界：当前 Lua 定义和事件已核对；TWUI 字段来自上游快照，实际修改前须从当前游戏提取目标布局。本次未进游戏验证 UI、CCO 或多人行为，也未安装 TWUI Studio。

## 1. 先定位资源与控制层

找目标面板的 pack 内布局、模板、图片、LOC 与 Lua。没有本地 `游戏原文件/ui/` 时用现成 `inspect.js` 确认在哪个当前 pack，再用 `extract.js` 只提取需要的前缀；不要按旧 pack 名猜位置。工具用法见 `03`，路径配置见 02，依赖见工具清单与准备。

排错顺序：**实际父组件 → 父 LayoutEngine / CCO 列表 → 组件停靠偏移 → 当前状态尺寸 → 图片层位置 → 透明留白**。记录运行时位置、宽高、状态和控制它的回调。改完位置又跳回去时，先找自动布局或回调，不能靠每帧强写坐标掩盖冲突。

## 2. TWUI 的结构与引用

以下为上游提取样本和编辑器研究中的结构，使用时以当前目标文件为准；不是 CA 完整 XML 规范。

| 层 | 编辑判据 |
|---|---|
| `hierarchy` / `components` | 前者保存树连接，后者保存平铺定义，通过 `this` 关联；只移动定义顺序不能改变父子关系 |
| `this` / `uniqueguid` / `id` | GUID、组件名有不同用途；克隆需维护内部引用，改 `id` 后查 Lua/CCO 名字，不做全文件统一替换 |
| `currentstate` / `defaultstate` | 引用状态 GUID；Lua `SetState` 用状态名，两者不能互换 |
| `states` / `state_uniqueguids` | 普通局部状态与模板引用形式不同；模板预览不完整时不擅自补一整套局部状态 |
| 图片链 | `imagepath` → `component_image.this` → `imagemetrics/image.componentimage`；声明图片不等于某状态已引用它 |
| 模板与文本 | 保留 `template_id`、`uniqueguid_in_template` 等引用；按原版 `textlabel` 与 LOC 实际关系生成键，不硬猜全部键前缀 |
| `callback_with_context` | CCO/原生回调绑定，不能当 Lua 代码块执行 |

常见坐标家族：普通定义使用 `docking` / `dock_offset`，模板实例可用 `dock_point` / `offset`，图片层可用 `dockpoint` / `dock_offset`。辨明结构后只改该层实际已有字段；不要因拼写相似统一重命名。保留目标 `layout.version`。

保留原始字节基线和换行/BOM，做局部修改后查看 diff。一些 CCO 属性含裸 `<`、`&&`，严格 XML 解析器拒绝不代表游戏布局已损坏；若工具需转义，应只对验证副本处理，保存时保留有效的源表达式。拒绝批量重写未知字段。

**静态验收**：检查 GUID 重复与断链、同父同名、状态/图片引用、模板/外部布局/LOC/Lua 依赖。与修改前诊断比较，原版已有诊断不能自动算成本次新增错误；预览工具的近似布局、字体、九宫格和圆环算法不能当引擎规则。

## 3. 查找与组件生命周期

当前原版 `lib_common.lua` 的 `find_uicomponent` 每段调用 `find_single_uicomponent` → `parent:Find(name, false)`。字符串名字搜索所有后代；`find_uicomponent(parent, "a", "b")` 找到第一个 `a` 后，再在其后代中找 `b`，可跨层。找不到返回 **`false`**。

先限定目标面板再查按钮，避免同名组件误命中。必须严格查直接子节点时，遍历 `0 .. ChildCount()-1`，用 `Find(index)` 取得地址并经 `UIComponent` 转换；原生 `Find` 未找到返回 nil。不要仅用 `result ~= nil` 判断包装函数成功。

| 情况 | 当前源码支持的做法 |
|---|---|
| UI 尚未创建 | `core:is_ui_created()` 判断；用 `core:add_ui_created_callback` 初始化。该方法只追加回调，晚注册需自行检查并幂等初始化 |
| UI 销毁 | `core` 先清空 root 再调用销毁回调；清理缓存，不能在销毁回调里重新取 root |
| 面板关闭/重开、动态列表刷新 | 重新查找组件，以 `IsValid()` 检查内部指针；接口类型正确、变量非 nil 都不足以证明仍有效 |
| 创建或复用组件 | `core:get_or_create_component` 只扫描直接孩子；同名已存在不代表采用新模板，不会自动覆盖实例 |
| 重复注册监听 | 使用 MOD 唯一前缀，重注册前 `core:remove_listener(自有名字)`；第五参 true 持续监听，false 条件匹配执行后移除 |

依据：本地 `lib_core.lua` 的 UI creation/destruction、get_or_create_component、add_listener/remove_listener；接口有效性及 Find 行为另见 CA UIComponent 文档。延迟工作需重查组件并限制重试次数；固定延迟不是面板一定就绪的保证。

## 4. 事件、CCO 与文字

当前 `events.lua` 定义 `ComponentLClickUp`、`PanelOpenedCampaign`、`PanelClosedCampaign`。点击监听不要虚构 `ComponentLClick`；XML `ContextCommandLeftClick` 是回调名，不能替代 Lua 事件。面板名、按钮名和事件 context 内容必须查原版用例或游戏日志。

CCO 为界面提供运行时数据和命令：列表、文字、状态、可见性可以由上下文回调控制。静态按钮出现不能证明 CCO 执行或业务结果正确。执行 CCO 命令前核对当前对象类型、方法签名与真实调用；文档签名与示例冲突时保留待核验状态，不能补造参数。

`SetText` 与 `SetStateText` 的覆盖范围不同；hover 后恢复旧文字时查状态和回调。图片可有多层/索引，改路径后检查实际状态引用、尺寸和其他状态。关闭界面时恢复本 MOD 改过的输入锁定，不能删除原版容器或其他 MOD 的监听器。

**【未验证：具体 MOD 的多人路径】** UI 操作在各客户端本地发生。点击若改变战役模型，应核对 `CampaignUI.TriggerCampaignScriptEvent` / `UITrigger` 的当前 CA 同步入口和参数，再在模型侧校验目标、资源与条件；不能据此声称某 MOD 已实现多人兼容。

## 5. 验收

- [ ] 只改已定位的控制层；差异范围、资源和引用可核对。
- [ ] 游戏日志证明查到正确面板/组件，事件实际触发；查找失败按 false 处理。
- [ ] 打开、关闭、再次打开，以及动态列表刷新后仍正常；没有旧句柄、重复监听和关闭后残留锁输入。
- [ ] 覆盖默认/悬停/按下/禁用等实际状态、长中文、UI 缩放；列表覆盖空、单项、换行边界。
- [ ] CCO/点击后的业务结果与界面显示分别核验；涉及多人时完成对应游戏测试。
