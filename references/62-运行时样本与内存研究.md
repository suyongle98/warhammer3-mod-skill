# 62 · 运行时样本与内存研究

> 适用：DB/Lua/CCO 与日志不足以解释的原生行为；普通数据修改不需此流程。
> 整理：2026-10-27 ｜ 来源：scnjwyc `45a4c4b` 的运行时研究方法、Microsoft PE 格式与内存读取契约。
> 边界：方法整理；未采集新的游戏内存、未运行上游采集器/Capstone 回归，不附 dump 或采集工具。

前置：[61](61-原生反编译与版本适配.md) 的输入身份与地址；已有 Lua/UI 快照先读 [63](63-MCP证据与日志整理.md)。先定义需要解释的机制和可观测量，再决定是否需要新增采集。

## 1. 识别输入格式

| 输入 | 地址解释 |
|---|---|
| 磁盘 PE | 文件偏移经节映射换成 RVA；不能直接当运行时地址 |
| 按 RVA 排列的完整模块镜像 | 只有采集格式明确保证时，文件偏移才等于 RVA；VA 依本次模块基址计算 |
| 普通内存块 | 需要原始 VA、长度、可读区间与对象生命周期 |
| minidump | 先解析流表及内存映射；裸字节搜索只产生文件偏移线索 |

记录模块 SHA、版本/平台、PID、实际基址和 SizeOfImage、采集起止时间、用户操作、MOD 组合、dump/layout 哈希、空洞与分析工具版本。高熵不单独证明加密，固定 `0x140000000` 不是所有输入的基址。

采集按用户授权与项目规则执行，优先分析已有样本。只读采集也不是原子快照；跨页失败、guard/不可读区及读取期间变化均要记录。零填充区域不是实际零值。主模块不包含全部堆和其他 DLL，找不到对象不能据此断言对象不存在。缺少合法读取条件时保留错误，不自动提升权限或改用注入。

## 2. 从锚点建立调用链

1. 按场景搜字符串/常量的所有位置，分别考虑 ASCII、UTF-8、UTF-16LE；以邻近值、Lua 与 DB 语义筛选。
2. 对 RIP 相对内存引用区分读取、写入和取地址；从可信入口沿控制流确认，不把数据中的偶然字节当指令。
3. x64 `RUNTIME_FUNCTION` 提供展开范围，可缺少叶函数，也可能拆开逻辑函数。对齐、`CC` 与常见 prologue 只能生成候选；间接跳转和跳转表另核验。
4. 调用图记录调用点、caller 范围、target、callee 范围；反向扩展以函数范围为节点，避免只拿某个调用点继续搜索而漏掉上层。间接调用、尾跳转、跨模块目标单列。
5. 绝对指针命中需检查所在节、对齐、相邻项及真实消费者，不能直接命名为虚表。缺直接 call 不证明调用者在模块外。

缓存绑定 dump/layout/工具及反汇编器身份；身份不符则重建。覆盖缺口、空洞、截断和未解析分支进入报告，局部锚点通过不证明整份样本有效。

## 3. 字段含义需要数据流

步长乘数、地址递增与分配大小仅提出结构候选。结合循环、元素数及指针来源追踪对象基址，再核对访问宽度、有无符号、浮点转换、哨兵、clamp 和后续消费者。相邻的乘法与字段写入不自动属于同一对象。

使用反汇编器结构化操作数与读写属性；文本正则难以可靠识别读改写、SIMD、索引和 segment 相对访问。偏移直方图同时记录基址类别、宽度和样本。相同 float 序列只证明字节匹配，字段意义需不同函数和场景 A/B 的交叉支持。

## 4. 验收

- [ ] 输入格式、指纹、地址映射和可读覆盖明确，未将空洞零值当事实。
- [ ] 关键指令、函数范围、分支、调用点和数据流可回查；推断与观测分开。
- [ ] 报告支持/反证、覆盖缺口与下一项补证动作，实际执行与静态可达分开。
- [ ] 优先映射回 DB/Lua/CCO；研究不自动授权 hook、内存写入或持久补丁。
