## 1. 被动技能图标（38×38）

**适用范围**：`ui\battle ui\ability_icons\*.png` 中需要常驻/被动视觉风格的小图标。

### 1.1 尺寸与格式
- 必须 **38×38**，PNG，`Format32bppArgb`（8-bit alpha），约 96 DPI。
- 文件名 = `unit_abilities.icon_name`。

### 1.2 目标风格
- 参考原版同类：四角透明、圆盘完整、边缘**逐渐淡化的 alpha**，不要实心方底。
- 黑边只能是**窄、柔和、渐隐**的暗边；**禁止**粗黑环、硬切圆框、过宽黑框。
- 主体图案占位接近参考图；旧 59×59 图标转 38×38 时先把主体缩到约 **0.86** 占位再压到 38×38，视觉上过小/过大则微调，但**必须先看放大预览**。
- 保留原图核心图案、方向、颜色身份与可识别特征；除非用户明确要求重绘，不要让生成式工具替换原图案。

### 1.3 构图要求
- 单一主体居中，占画布约 60–75%；四周留至少 2 px 呼吸空间，不贴边。
- 被动图标**不加**强动势（旋涡/放射光/粒子），改用静态符号 + 稳定底纹表达"常驻"。
- 圆内背景可以是暗底或材质，但不得盖过主体对比度。

- **怎么做**：先取一张原版 38×38 被动图标（如 `laf_unit_contact_crank_gun_suppressive_fire.png`）并排比对占位与黑边宽度，再画。
- **验收**：见 §8 清单；`magick identify` 为 `38x38` + `srgba`。

> ⚠️ 坑：把 59×59 原图直接 `-resize 38x38` → 主体偏小、黑边变粗、细节糊；正确做法是先把主体缩到 0.86 占位再压尺寸。

## 2. 主动技能图标（59×59）

**适用范围**：`ui\battle ui\ability_icons\*.png` 中主动 ability（`unit_special_abilities` 有战斗实体）的图标。

### 2.1 尺寸与格式
- 必须 **59×59**，PNG，`Format32bppArgb`（有透明边时）；文件名 = `unit_abilities.icon_name`。
- 输出必须是**透明四角上的完整圆形图标**，不是透明背景上的孤立主体。

### 2.2 目标风格与构图
| 要素 | 要求 |
|---|---|
| 外框 | 完整圆形徽章：金属/魔法外环 + 圆盘底 + 圆内场景，均属"图标本体"，必须保留 |
| 主体 | 居中，占圆盘约 60–75%；主题是物品则物品轮廓占中心；主题是光环/庇佑则核心符号 + 环形保护感清楚 |
| 动势 | 可有旋涡、光环、护盾、火焰、风流、符文光、粒子、方向性动势，但**不得遮住主体** |
| 高光 | 轻微玻璃高光、玻璃按钮材质感（比被动图标更"施放感"） |
| 边缘 | 仅圆外方形区域与外溢特效渐隐到透明；不得啃掉外环、不得把圆盘切成主体轮廓 |
| 禁止 | 文字、字母、水印、人物大脸、UI 说明文字、过多小物件 |

### 2.3 与 ability 的对应关系
- `unit_abilities.icon_name` → `ui\battle ui\ability_icons\<icon_name>.png`（**无扩展名**写在字段里）。
- `icon_name` 与 ability key **可以不同**：实测 `wh2_dlc09_army_abilities_tomb_swarm` 的 `icon_name` 是 `wh2_dlc09_army_ability_tomb_swarm`（单复数差异）；多条 ability 也可共用同一 `icon_name`（如 `wh2_dlc09_army_passive_realm_of_souls_ushabti_trigger` 复用 `wh2_dlc09_army_abilities_realm_of_souls_ushabti`）。
- 升级版 ability 与基础版共用同一图标时，角色技能使用**基础版**图标。
- 超载版是**另一条** ability key，可共用或另配图标；名称/说明必须单独两行。

- **怎么做**：先在 `unit_abilities` 表里取 `icon_name` 列的值，按该值命名 PNG，再目视核对 tooltip 里出现的图。
- **验收**：进游戏 hover ability，图标显示为自绘图而非白块/原版图；`Get-ChildItem 'ui\battle ui\ability_icons' -Filter "<icon_name>.png"` 命中。

> ⚠️ 坑：按 ability key 命名文件而字段里写的是另一个 `icon_name` → 图标不显示（引擎只找字段值）。
> ⚠️ 坑：`icon_name` 带 `.png` 后缀 → 引擎拼成 `xxx.png.png`，白块。

## 3. 边缘抠图与透明画布（技能图标具体做法）

**通用规则（模式 A/B 的定义、三种底检查）见 `30-美术总规范.md` §2**；此处只给技能图标的落地参数与命令。

| 项 | 参数 |
|---|---|
| 画布 | 与目标尺寸**同尺寸**（38×38 / 59×59），不要先放大再缩 |
| alpha | 8-bit（`Format32bppArgb`）；四角 `A=0` |
| 抗锯齿 | 绘制时开 `SmoothingMode.AntiAlias`；缩放用 `InterpolationMode.HighQualityBicubic` |
| 圆外过渡 | 1–2 px 渐隐 alpha，不做硬切 |
| 安全边距 | 中央主体抠图时保留 4–10% 透明边距 |

**ImageMagick 做法（作者环境实测可用）**

```powershell
$magick = 'magick'
# ① 确定性缩放 + 保持 alpha
& $magick src.png -resize 59x59 -define png:color-type=6 out.png
# ② 圆形 alpha 遮罩：先建同尺寸透明画布画白色圆，再 DstIn 合成
& $magick -size 59x59 xc:none -fill white -draw "circle 29.5,29.5 29.5,0.5" mask.png
& $magick src59.png mask.png -alpha off -compose CopyOpacity -composite out.png
# ③ 色键抠图（仅中央主体抠图时用）
& $magick in.png -fuzz 15% -transparent '#00ff00' out.png
# ④ 自检四角与圆心 alpha
& $magick out.png -format "A00=%[fx:p{0,0}.a] A58=%[fx:p{58,58}.a] Ac=%[fx:p{29,29}.a]`n" info:
```

- **怎么做**：优先 ①+②（确定性像素处理）；只有明确要中央主体抠图才用 ③，并检查绿边。
- **验收**：④ 输出 `A00=0 A58=0 Ac=1`；三种底色目视无黑晕/白边。

> ⚠️ 坑：用色键对整张图去底 → 圆环与圆内场景一起消失（正确做法见 `30-美术总规范.md` §2 A 模式清单）。

## 4. 图标与 ability / 角色技能的复用规则

| 场景 | 做法 | 路径 |
|---|---|---|
| 新画战斗 ability 图标 | 主动 → 59×59；被动 → 38×38 | `ui\battle ui\ability_icons\<icon_name>.png` |
| 角色 skill 直接启用某 ability | 复用该 ability 的图案；按角色槽位制作 59×59 副本 | `ui\campaign ui\skills\<image_path>.png` |
| 角色 skill 与任何 ability 无关 | **不另画**；从原版 `ui\campaign ui\skills\` 选语义最匹配的图标，把文件名写进 `image_path` | `ui\campaign ui\skills\` |
| 一个节点解锁多个 ability | 用该节点的**主要** ability 图标 | 同上 |
| 升级版与基础版共用图标 | 角色技能用**基础版**图标 | 同上 |
| 已重绘 MOD ability | **不得**再用原版同名 ability 图标代替 | 同上 |

**硬性区分**
- 角色技能图标槽位是 `character_skills.image_path` → `ui\campaign ui\skills\`；战斗能力图标槽位是 `unit_abilities.icon_name` → `ui\battle ui\ability_icons\`。**两个目录不同、不可互相顶替**。
- 两处复用同一图案时，分别按目标槽位准备文件，并验证尺寸与透明角；直接引用原版图标也须量尺寸。不能因图片来自原版就省略检查（总规范见 `30` §0/§1）。
- 阶段提示副图标走 `ui\skins\default\`（16×16 / 22×22 / 24×24 / 38×38，按原版同名文件），与 ability 图标是**第三套槽位**。

**阶段副图标的档名一致性（重要）**
- `special_ability_phases.phase_display` 引用 `special_ability_phase_displays_tables.key`，配置 VFX，不是本地化键或图标路径。
- 名称由 `special_ability_phases_onscreen_name_<phase_id>` 提供，该 loc 文本可用 `[[img:...]]` 引用图标：
  - 全路径写法（实测可解析）：`[[img:ui/skins/default/modifier_icon_poison.png]]`、`[[img:UI/Battle UI/ability_icons/wh3_dlc25_unit_contact_suffocating.png]]`
  - 短名写法：`[[img:stage_one]]`、`[[img:icon_hp]]` —— 作者环境**未找到**对应的松散 PNG 文件，解析路径 **【未验证】**
- 自建阶段副图标**只用全路径写法**，且文件放进 `ui\skins\default\`，档名与 loc 引用**逐字符一致**。

- **怎么做**：改图标后核对 `unit_abilities.icon_name`、`character_skills.image_path`、phase 名称中的 `[[img:]]` 路径；分别量目标槽位尺寸。接触效果另查 §4.1。
- **验收**：三处都在游戏内显示正确（战役技能树 + 战斗 tooltip + 被命中提示）。

> ⚠️ 坑：把 59×59 的 `ability_icons` 图直接改名塞进 `ui\campaign ui\skills\` 并**删掉原图** → 战斗 tooltip 变白块。
> ⚠️ 坑：把图片路径写入 `phase_display` → 字段引用域错误；图标应按上述 loc 路径或 §4.1 的 phase 同名文件配置。

### 4.1 接触效果：兵种面板与效果名称分别配图

| 显示位置 | 取图配置 |
|---|---|
| 兵种面板的接触效果图标 | `ui/battle ui/ability_icons/<phase id>.png`；以原版同类文件为尺寸基准 |
| 效果名称中的内嵌图标 | `special_ability_phases_onscreen_name_<phase id>` 的 `[[img:...]]`；另查该槽位尺寸 |

- **依据（2026-10-08）**：原版中毒、丧胆、灵魂枯萎的面板 PNG 均与 phase id 同名，实测为 38×38；从当前 `游戏原文件/ui.pack` 用 `extract.js` 导出后 `magick identify` 可复核。

## 6. 程序化绘制方案（PowerShell + System.Drawing）

**参考实现**：`<MODS>\su_qizhi\_xls_work\make_group_icons.ps1`（391 行，实测产出 8 张 59×59、四角 alpha=0 的徽章）。通用骨架见 `30-美术总规范.md` §5.3；下面是技能图标专用的三个图元与一次完整出图。

```powershell
$ErrorActionPreference = 'Stop'
Add-Type -AssemblyName System.Drawing

# —— 图元 1：径向渐变圆盘（Graphics 无原生径向渐变，逐圈 FillEllipse 近似）——
function Draw-Disc($g, [float]$cx, [float]$cy, [float]$r, $outer, $inner) {
  for ($i = 22; $i -ge 1; $i--) {
    $f = $i / 22; $rr = $r * $f; $t = 1 - $f
    $col = [System.Drawing.Color]::FromArgb(255,
      [int]($outer.R + ($inner.R - $outer.R) * $t),
      [int]($outer.G + ($inner.G - $outer.G) * $t),
      [int]($outer.B + ($inner.B - $outer.B) * $t))
    $b = New-Object System.Drawing.SolidBrush($col)
    $g.FillEllipse($b, $cx - $rr, $cy - $rr, $rr * 2, $rr * 2); $b.Dispose()
  }
}

# —— 图元 2：金属外环（三圈：暗外 / 亮中 / 内描边）——
function Draw-Ring($g, [float]$cx, [float]$cy, [float]$r, $dark, $bright, $inner) {
  $p1 = New-Object System.Drawing.Pen($dark, 2.2)
  $g.DrawEllipse($p1, $cx - $r - 2, $cy - $r - 2, ($r + 2) * 2, ($r + 2) * 2); $p1.Dispose()
  $p2 = New-Object System.Drawing.Pen($bright, 3.0)
  $g.DrawEllipse($p2, $cx - $r, $cy - $r, $r * 2, $r * 2); $p2.Dispose()
  $p3 = New-Object System.Drawing.Pen($inner, 1.2)
  $g.DrawEllipse($p3, $cx - $r + 1.5, $cy - $r + 1.5, ($r - 1.5) * 2, ($r - 1.5) * 2); $p3.Dispose()
}

# —— 图元 3：符号（多边形 / 扇形 / 贝塞尔曲线，任选）——
function Draw-Symbol($g, [float]$cx, [float]$cy, [float]$s, $color) {
  $b = New-Object System.Drawing.SolidBrush($color)
  $g.FillPolygon($b, @(                        # 三角：换成 FillPie / DrawBezier 即另一种主题
    [System.Drawing.PointF]::new($cx, $cy - $s),
    [System.Drawing.PointF]::new($cx + $s * 0.87, $cy + $s * 0.5),
    [System.Drawing.PointF]::new($cx - $s * 0.87, $cy + $s * 0.5)))
  $b.Dispose()
}

# —— 出图：59×59 主动图标 ——
$size = 59; $c = $size / 2 - 0.5
$bmp = New-Object System.Drawing.Bitmap($size, $size, [System.Drawing.Imaging.PixelFormat]::Format32bppArgb)
$g = [System.Drawing.Graphics]::FromImage($bmp)
$g.SmoothingMode     = [System.Drawing.Drawing2D.SmoothingMode]::AntiAlias
$g.InterpolationMode = [System.Drawing.Drawing2D.InterpolationMode]::HighQualityBicubic
Draw-Disc $g $c $c ($c - 0.5) ([System.Drawing.Color]::FromArgb(255,18,6,6)) ([System.Drawing.Color]::FromArgb(255,198,22,14))
Draw-Ring $g $c $c ($c - 4) ([System.Drawing.Color]::FromArgb(255,74,52,16)) ([System.Drawing.Color]::FromArgb(255,148,116,48)) ([System.Drawing.Color]::FromArgb(255,150,16,12))
Draw-Symbol $g $c $c 13 ([System.Drawing.Color]::FromArgb(255,232,222,196))
$g.Dispose()
$out = '<WORKSPACE>\<MOD>\ui\battle ui\ability_icons\my_ability.png'
$bmp.Save($out, [System.Drawing.Imaging.ImageFormat]::Png); $bmp.Dispose()

# —— 出图后自检 ——
$img = [System.Drawing.Image]::FromFile($out)
"{0}x{1} cornerA=({2},{3},{4},{5})" -f $img.Width, $img.Height,
  $img.GetPixel(0,0).A, $img.GetPixel($size-1,0).A, $img.GetPixel(0,$size-1).A, $img.GetPixel($size-1,$size-1).A
$img.Dispose()
```

- **怎么做**：改 `$size` 得 38×38 被动版；换 `Draw-Symbol` 表达主题；`Draw-Ring` 的 `$r` 控制外环粗细（留出圆外渐隐空间）。
- **验收**：脚本自检输出 `<size>x<size> cornerA=(0,0,0,0)`；再用 §7 命令复核。

> ⚠️ 坑：`$g`/`$bmp` 未 `Dispose()` → 批量出图时句柄泄漏、目标文件被占用无法覆盖。

## 7. 批量校验（`magick identify`）

```powershell
$magick = 'magick'
$dir = '<MODS>\su_qizhi\打包版\ui\campaign ui\ancillaries'

# ① 全目录尺寸/通道一览
& $magick identify -format "%f|%wx%h|%[channels]`n" "$dir\*.png"

# ② 只列尺寸不是 59x59 的（主动图标目录）
& $magick identify -format "%f|%wx%h`n" "$dir\*.png" | Where-Object { $_ -notmatch '\|59x59$' }

# ③ 递归（magick 不展开 **，先取列表）
$files = Get-ChildItem '<WORKSPACE>\<MOD>\ui' -Recurse -File -Filter *.png | Select-Object -ExpandProperty FullName
& $magick identify -format "%f|%wx%h|%[channels]`n" $files

# ④ 检查四角 alpha 是否为 0（逐个）
& $magick identify -format "%f|%[fx:p{0,0}.a]|%[fx:p{w-1,0}.a]|%[fx:p{0,h-1}.a]`n" "$dir\*.png"

# ⑤ DB 字段 ↔ 文件 对照（示例：列出 icon_name 与文件是否齐）
$db = '<VANILLA>\db\unit_abilities_tables\data__.tsv'
$icons = Get-Content $db | Select-Object -Skip 2 | ForEach-Object { ($_ -split "`t")[2] } | Where-Object { $_ } | Sort-Object -Unique
$have  = Get-ChildItem '<REFERENCE>\Just More Items\ui\battle ui\ability_icons' -Filter *.png | ForEach-Object BaseName
Compare-Object $icons $have -PassThru | Select-Object -First 20
```

- **验收**：② 无输出（主动图标全为 59×59）；④ 四列均为 0；⑤ 交集为空则说明本 MOD 未覆盖原版图标（属正常）。
