# 45 · Lua 离线回归

> 适用：WH3 Lua 的状态机、队列、延迟、存档与 UI 生命周期；普通 DB/文案改动不要求建立模拟框架。
> 整理：2026-10-27 ｜ 来源：scnjwyc 固定提交 `45a4c4b` 的离线回归方法、Lua 5.1 手册及当前原版库。
> 边界：本册是方法整理；没有重新执行上游业务用例或游戏测试。

## 1. 运行真实源码

优先用项目已有的 Lua 5.1 测试环境，按真实加载器、初始化、事件和回调路径加载 MOD 源码。`luac -p` 只能检查语法；另写一份业务算法并让它通过，不能证明 MOD 源码正确。

边界替身集中模拟 `cm`、`core`、UI、CCO 等引擎接口；数据 fixture 与替身分开。接口签名查当前原版；字符串查找先读 [46](46-CA字符串接口.md)。未知调用和非法参数独立记入失败列表，即使源码用 `pcall` 捕获，也不能让用例通过。明确可选 API 的存在/缺失及降级预期，避免通用空操作掩盖未实现接口。

## 2. 按风险选场景

| 改动 | 需要区分的行为 |
|---|---|
| 状态或队列 | 按玩家触发顺序复现旧错，再验证结果、扣点、结算和队列内容 |
| 延迟与取消 | 等待期间关闭面板、切换对象；永久未就绪时在明确边界停止 |
| 重复初始化 | 第二场、重开面板、重复事件不重复扣款/奖励，不残留旧任务 |
| 保存恢复 | 保存值为 1，运行中改成 2；新 Lua 环境载入仍为 1 |
| UI/CCO 提交 | 记录表达式、对象身份、真实状态变化；调用已发生不等于提交成功 |

独立场景使用隔离环境；连续操作在同一环境完成整个周期。断言状态、参数、保存快照和资源注册表，日志只辅助定位。长期监听器按契约保留，不能为了“零残留”删除正常功能。

## 3. 先校准替身

- 监听器按名称存储；同一事件可有多个监听器。条件可为函数或固定 true，回调必须为函数；非 persistent 监听器在实际执行后移除。删除 A 不影响同事件的 B，具体重注册行为查当前 `lib_core.lua`。
- 延迟保留 API 的时间单位、顺序与取消语义。涉及超时/取消时用可推进的虚拟时钟，立即清空回调队列只能做不依赖时间的冒烟。
- 存档必须序列化或深复制，跨新环境恢复；不能共享原来的 Lua 表、闭包和 userdata。
- 对每类边界主动注入未知调用/坏参数，确认 `pcall` 后仍能汇总失败。核对预期执行数量，错误和异常返回非零退出码。

Python/Lupa 仅在需要时使用，显式选择 `from lupa import lua51` 并核对运行版本。Lua 表/数组、冒号隐含 self、多返回值和二进制字符串须用当前版本小例校准；Python 读取 Lua 的 `items` 等字段用字符串下标，避免命中包装对象方法。不要因安装了默认 `LuaRuntime` 就断言它是 Lua 5.1。
