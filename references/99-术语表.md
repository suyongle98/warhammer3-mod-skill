## 3. 易混淆对照

### 3.1 culture vs subculture
- `culture`（文化）→ `cultures_tables.key`，如 `wh3_main_cth`；一个文化含多个子文化。
- `subculture`（子文化）→ `cultures_subcultures_tables.subculture`（junction 表，列 `subculture` / `culture`）；派系通过 `factions_tables.subculture` 落到子文化。
- **判断口径**：需要「同一文化下的不同派系风格」用 subculture；需要「跨派系共享」用 culture。

### 3.2 agent vs agent subtype
- `agent`（事务官类型）→ `agents_tables.key`，管移动点 / 视野 / 是否可玩 / 肖像覆盖。
- `agent_subtype`（事务官子类型）→ `agent_subtypes_tables.key`，管图标 / 是否法师 / `magic_lore` / 招募类别 / 是否可装备随从。
- **口径**：做「一个具体领主/英雄」通常填 `agent_subtype`；`agent` 只在定义「这一类事务官」时改。

### 3.3 effect vs effect bundle
- `effect`（效果）→ `effects_tables.effect`，**单条**可复用效果（含图标与正负语义）。
- `effect_bundle`（效果集）→ `effect_bundles_tables.key`，**一束** effect，通过 `effect_bundles_to_effects_junctions_tables` 绑定具体 effect + `effect_scope` + 数值。
- **口径**：能给玩家看到的一条 buff/ debuff 通常是 bundle；effect 是被复用的零件。

### 3.4 ability vs special ability vs phase
- `ability`（能力）→ `unit_abilities_tables.key`：**UI 层**（图标、类型、来源、稀有度）。
- `special ability`（特殊能力）→ `unit_special_abilities_tables.key`：**战斗层**（时长、冷却、目标、AOE、投射物/涡流/召唤）。
- `phase`（阶段）→ `special_ability_phases_tables.id`：**效果本体**（属性、数值、接触、治疗）。
- 链：`unit_abilities` ↔ `unit_special_abilities`（同名 key）→ `special_ability_to_special_ability_phase_junctions` → `phase`。

### 3.5 unit_set vs unit_list
- `unit_set`（部队集合）→ `unit_sets_tables.key`（3,331 条），成员由 `unit_set_to_unit_junctions_tables` 按 `unit_caste`/`unit_category`/`unit_class`/`unit_record` + `exclude` 定义；**用于给一类部队批量挂效果/能力/属性、限定旗帜可用范围**。
- `unit_list`（单位列表）→ `unit_lists_tables.key`（27 条），成员由 `unit_to_unit_list_junctions_tables` 逐个指定；**原版用于仪式/召唤等一次性清单**。
- **口径**：批量限定用 `unit_set`；枚举固定几个单位用 `unit_list`。

### 3.6 variant vs variant mesh
- `variant`（变体）→ `variants_tables.variant_name`，是「一套外观组合」的键；`unit_variants_tables` 把 `faction` + `unit` + `variant` + `unit_card` 绑起来。
- `variant mesh`（兵模网格）→ `variants_tables.variant_filename` 指向的 `.variantmeshdefinition` 文件，内部是部件挂点树。
- **口径**：换皮肤 = 换 variant；改部件/材质 = 改 variantmeshdefinition 文件。

### 3.7 trait 的表名
- 特性主表是 **`character_traits_tables`**，不是 `traits_tables`（该表不存在）；等级效果在 `character_trait_levels_tables`。

### 3.8 引擎拼写坑
- 单位直接挂能力的 junction 表实际名是 **`land_units_to_unit_abilites_junctions_tables`**（引擎拼写为 `abilites`，少一个 `i`），搜 `abilities` 搜不到；列为 `ability` / `land_unit`。

## 4. 命名前缀约定

### 4.1 MOD 专属前缀
- 既有约定：`wyccc_`（见 `naming_conventions.md`）；作者案例实例用 `su_qizhi_`。
- 规则：前缀**只用于自定义 key / 文件**；引用原版 key 一律保持原样，不加前缀。
- 文件前缀：`!!!wyccc_` / `!!wyccc_` / `!wyccc_` 控制 TSV 加载优先级；**禁止**用 `data__` 作 MOD 文件名。

### 4.2 前作前缀识别（引用前必查）

| 前缀 | 归属 | 处置 |
|---|---|---|
| `wh_main_` | WH1 本体 | 在 WH3 中**合法但属前作内容** |
| `wh_dlc01_`…`wh_dlc08_` | WH1 DLC | 同上 |
| `wh2_main_` / `wh2_dlc*` / `wh2_pro*` / `wh2_twa*` | WH2 | 同上 |
| `wh3_main_` / `wh3_dlc*` / `wh3_cp*` / `wh3_pro*` / `wh3_twa*` | WH3 | 新建内容优先用这一类做基准 |

### 4.3 标注与选型
- 引用前作 key 时**必须标注来源作品**（例：`wh_main_unit_contact_poison`（WH1 键，WH3 仍可用））。
- 新建内容优先抄当前 **WH3 原版同类行**；版本维护见 `05-版本维护与核验.md`。

### 4.4 数字主键
- 先查 schema 的 I32/I64 类型与完整复合键；按对应范围检查并使用 MOD 专属号段（见 `04-通用纪律与验收.md`）。

### 4.5 本地化键
- 格式 `{表前缀}_{完整键名}`，且中英两行成对；换行用字面 `\n`（见 `50-本地化与翻译.md`）。

## 5. 验收：新内容加入时如何保持术语一致

- [ ] 写新词前先在本表 §1 查；已有译法直接复用，**不得另创**。
- [ ] 本表未收录的新术语，按三步补录：① 在 `db\` 找承载它的表 / 字段（表头实测）→ ② 用 loc 取官方中文名（`localisation__.loc.tsv`）→ ③ 追加到本表对应分组，并更新头部「指纹」条数。
- [ ] 同一概念全书写法唯一，以 §2「固定中文」为准（尤其 phase=阶段、scope=作用域、junction=绑定表）。
- [ ] 表名 / 字段名 / key 反引号包裹且大小写与原文件完全一致（含 §3.8 的引擎拼写）。
- [ ] 前作 key 已标注来源作品；新建内容已用 WH3 原版同类 key 做基准。
- [ ] 新增分册引用了本表，且没有在分册里重复定义同一术语的中文名。
