# 最小可运行 MOD 骨架（模板）

> 用途：① 新 MOD 的起点；② 验证"建 MOD → 打包 → 进游戏生效"的闭环是否通畅。
> 维护基线：WH3 9.0.2 / 2026-10-08 ｜ 来源：教程 01/16 + `已完成mod\su_qizhi` 实证结构

## 1. 目录结构

```
<你的MOD名>\
├── db\
│   └── <表名>_tables\          # 目录名必须与 游戏原文件\db\ 下同名
│       └── <你的前缀>.tsv       # 独立文件名；避免与原版完整路径撞名
├── text\
│   └── db\
│       └── <你的前缀>.loc.tsv   # 列头 key/text/tooltip
└── settings.rpfm_reserved.json  # RPFM 保存时自动生成
```

## 2. 建一个最小 MOD 的步骤

| # | 操作 | 验收 |
|---|---|---|
| 1 | 复制本骨架目录，改名（英文、无空格、无中文） | 目录名无中文 |
| 2 | 从 `<VANILLA>/db/` 复制目标表目录名到 `db\` | 目录名逐字符一致 |
| 3 | 在 RPFM 里打开原版表，导入到自己的 pack，重命名子表为你自己的名字 | pack 内路径与原版不重名，覆盖意图明确 |
| 4 | **删掉不修改的行**，只留要新增/覆盖的行 | 行数 = 你的改动数 |
| 5 | 源文件自检：`node "<SKILL>/tools/modcheck/check.js" <你的MOD目录>`；他人补丁加 `--ref`，类型与复合键另查 schema | 退出码 0，警告均已审阅 |
| 6 | 加本地化（中英成对），键名 = 表前缀 + 完整键名 | 键名符合 `50-本地化与翻译.md` §2 |
| 7 | 已获打包授权时：`node "<SKILL>/tools/rpfm-pack/pack.js" <你的MOD目录>`；部署/发布按用户授权 | 文件名无中文 |
| 8 | 启动器里勾选该 MOD，进游戏验证 | 目标改动生效，且原版同类功能未被破坏 |

## 3. 常见失败与定位

| 现象 | 先查 |
|---|---|
| MOD 完全没进游戏 | `...\Warhammer III\lua_mod_log.txt`、`used_mods.txt` 顺序（见 `60-日志与崩溃排查.md`） |
| 整表改动无效（静默） | TSV 版本号是否与 `游戏原文件\db\<表>_tables\data__.tsv` 一致（版本与列序不符需迁移） |
| 单个条目无效 | 主键是否重复/溢出；引用的 key 是否存在 |
| 文本显示为键名原文 | 检查实际 loc key、文件路径、加载顺序和当前游戏语言 |
| 图标不显示 | 路径大小写/空格是否与原版一致（`ui\battle ui\ability_icons`） |
